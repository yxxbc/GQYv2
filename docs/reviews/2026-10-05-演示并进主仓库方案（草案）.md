## 一、这是要并什么、为什么现在写

记录里两个前置都指着这一步（`docs/construction/README.md` 第二节「拆界面那一段的两条」，2026-10-01 项目主人定）：

- 终端界面以 `proto/tui-demo` 演示为蓝本**并进主仓库**：演示的样子和它的蓝图 `tui.md` 就是版式图纸，代码能搬的搬进工作区；「显示什么」改由核心的视图投影给，演示里自己算的那部分换掉——**那一段是拆 M9 的步，不在并进这一步**；并进来以后做演示的会话接着在上面开发。
- 8-24（`gqy config` 拉起终端界面停在配置页）写着「等终端演示合进 main」；拆 M9 写着「等终端界面、网页演示改好合进 main」。

要并两块：**终端界面先**，网页演示随后照同一套办法。这份方案写给终端界面这一份。

## 三、怎么并（推荐做法）

1. **来源**：收口以后的 `proto/tui-demo`。顺序是：三平台 CI 绿 → 项目主人验收 → 合进 `proto/tui-demo`；收口的那一个提交 SHA 填到本文末尾，并进照它。
2. **搬运**：照搬迁那次的老办法——整树照搬、名字改回 `gqy`：
   - 目录、包、程序：`tui-demo` → `crates/gqy-tui`；包名和程序名 `gqy-tui`（施工方案第二节「拆 M9 时另带四样」第 2 条已经写：打包怎么拆 `gqy`、`gqy-tui` 随 M9 定）。
   - `miyu` → `gqy`：三个环境变量（`MIYU_HOME`、`MIYU_RESOURCES`、`MIYU_CORE_BIN`）、代码和注释里的字样、文档里的字样。
   - 改完逐字节比对，确认只差名字；依赖路径 `../crates/miyu-*` 改成搬迁后的同级 `../gqy-*`。
3. **放哪、登记**：`crates/gqy-tui`，工作区成员（`members = ["crates/*", "xtask"]` 自动收）；登记进 `01-架构.md` 第九节第 5 层「头」（那张表「放什么」本来就写着「终端界面」，crate 列里加 `gqy-tui`），照 `gqy-web` 的先例。
4. **对着 main 适配**：旧内核副本不搬；整树对着本仓库 main 的 `gqy-ipc`/`gqy-store`/`gqy-kernel`（和测试的 `gqy-core`/`gqy-endpoint`/`gqy-session`/`gqy-tool`）编，编不过的地方照 main 的接口改。落点集中在连接和拉起（W-8 以后握手的说法）、给人看的字、资源目录三处；动到语义的地方停下来问演示会话。
5. **测试、门禁、CI**：进工作区照本仓库规矩查——`cargo xtask check` 八项 ＋ 行数 ＋ 分层；演示的测试（含伪终端那组）随 `cargo test` 跑。演示那台独立 CI 收掉，并进主 `ci.yml` 的矩阵（照「进工作区、门禁查它」）。
6. **文档归位**（他们分支上的施工方案和施工图**不搬**——那两份各自演进过，照搬会把旧状态带回来）：
   - `docs/blueprint/tui.md`（744 行）→ 本仓库蓝图；`docs/blueprint/README.md` 索引加一行（照他们改法）。蓝图是「现在的样子」，搬进来时里面的路径、程序名、`GQY_*` 要照新样子改；`TUI-*.md` 七张施工单（配置页、网站卡片跟进、herdr 会话恢复、herdr 重复通知、预编辑同步刷新、鼠标选区复制、三平台测试补齐）→ `docs/construction/`，它们是当时的记录，路径照旧不改。
   - `docs/reviews/2026-10-01-终端界面演示现状.md` → `docs/reviews/`。
   - `docs/designs/21-网页.md` 的两处（收起那一行打头、插进正文的信息，2026-10-02 项目主人定，两处都引 `tui.md`）→ 照改。
   - `docs/construction/README.md` 第五节、`施工图.html`：主会话照当时的样子手改（本仓库的总表只有一个作者）。
7. **体量说明**：这一步是**搬迁**——330 个文件、约 3.8 万行，全部已经存在、已经过三平台测试；照「一步的大小」那条规矩做来源说明，按搬迁看。
8. **做法**：照施工规矩——一个工作树（`.worktrees/演示并进/`，分支 `step/演示并进`）、一张施工单（`docs/construction/演示并进.md`）；三平台 CI 全绿、项目主人真机验收，再合 main。

## 四、顺序（建议）

1. **演示侧收口（终端）**：三平台 CI → 项目主人验收 → 合进 `proto/tui-demo`。← 现在走到这里
2. **并进**：上面第三节，一个工作树做下来。
3. **并进之后**：8-24 按顺序开工（`gqy config` 拉起界面带 `--page config`；先写施工单、改 `config.md`、`models.md`）。
4. **网页演示**照同一套办法收口并进。
5. **拆 M9**：两个演示都并进来以后，和两个演示的会话商量、项目主人批准，再拆步；并进来的代码就是拆的起点。
