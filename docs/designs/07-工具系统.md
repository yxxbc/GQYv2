# 07 · 工具系统

> 状态：【规划】。前置阅读：[00 设计理念](00-设计理念.md)、[01 总体架构](01-总体架构.md)、[02 运行时与并发模型](02-运行时与并发模型.md)；相关：03 回合引擎、04 前缀缓存账本、08 权限审批与沙盒、12 人格配置与场所、18 扩展体系。
>
> 本文回答：工具是什么类型、怎样注册、怎样变成模型可见的 tools 数组、一次调用从模型输出到工具结果经过哪些步骤，以及内核自带哪些工具。权限判定与沙盒细节见 08；子回合与作业的执行见 03。

## 1 目标

1. **加一个内置工具 = 一个文件 + 注册表一行**（v1 要改 23 个文件，其中 9 处纯接线，见 00 §1.3）。
2. **工具面会话内字节恒定**：tools 数组在会话创建时编译、冻结，之后逐字节回放（铁律 1，04）。
3. **工具不回调引擎**：子代理、后台作业、向用户提问这类“需要引擎做事”的能力，由工具返回 `ToolEffect`，引擎执行（01 §3.1）。
4. **参数收口在唯一入口**：模型写错类型时按 schema 还原，落库保留原始参数（v1《理念》§九）。
5. **报错说它真正知道的**：期望什么、收到什么，不写猜测的原因。
6. **输出有上界**：每个工具声明模型可见上限；超出按头尾截断，全文可取回。

非目标：参数语法层的严格校验（stub 模式下 enum/pattern 降级为描述文字，见 §6）；工具间编排语言。

## 3 核心类型

### 3.1 ToolSpec 与元数据

`ToolSpec` 属于领域数据，定义在 `gqy-core`（01 §3）；其余类型在 `gqy-tools`。

```rust
// 草案，以实现为准
pub struct ToolSpec {
    // 内置工具为 Cow::Borrowed 字面量；扩展工具（脚本头部、MCP 列举）为 Cow::Owned
    pub name: Cow<'static, str>,        // ^[a-z][a-z0-9_]{0,63}$；扩展工具见 §4.3
    pub summary: Cow<'static, str>,     // ≤ 60 字符，英文短句；stub 与 load_tools 目录用
    pub description: Cow<'static, str>, // 完整契约，英文；不得插值任何运行时值（§12.2）
    pub schema: Cow<'static, str>,      // JSON Schema 原文；注册时规范化并校验
}

pub enum EffectClass { ReadOnly, Presentation, Writes, Exec, Network }

pub enum Residency {
    Core,   // 任何加载模式下都以完整形态常驻
    Lazy,   // 受 LoadingMode 支配（§6）
}

pub struct ToolMeta {
    pub effect: EffectClass,          // 默认效果类别；assess 可按参数升级，不可降级
    pub residency: Residency,
    pub min_trust: Trust,             // 低于此信任级的场所不编译该工具（08 §7）
    pub host: bool,                   // 是否触达宿主文件/进程；External 永不获得 host 工具
    pub requires: &'static [HostCap], // 依赖的 Host 能力（09），缺失则不编译
    pub output: OutputPolicy,         // 写入期截断策略（§8、05 §10）：HeadTail{limit, head, tail} | SelfBounded
    pub parallel_safe: bool,          // 默认 true；false 时即使是 ReadOnly/Presentation 也单独成组（03 §6.2）
    pub timeout: TimeoutClass,        // Foreground(默认 120 s) | Short(30 s) | Custom
    pub interactive_only: bool,       // 如 ask_user：非交互场所不编译
}
```

`EffectClass` 的含义：

| 类别 | 含义 | 例子 |
| --- | --- | --- |
| `ReadOnly` | 只读宿主或会话状态，无外部副作用 | read、glob、grep、read_output、job_status |
| `Presentation` | 只改变会话内展示或会话自有状态 | todo_write、load_tools、ask_user |
| `Writes` | 写文件或存储域 | write、edit、apply_patch、trash |
| `Exec` | 启动或驱动子进程 | run_command、pty_*、脚本工具 |
| `Network` | 由 daemon 发起对外网络请求 | web_fetch |

一次调用的实际类别由 `assess` 决定，只能比 `meta.effect` 更高（例如 `web_fetch` 的目标为私有地址段时不可降级；`job_cancel` 由 meta 直接声明为 `Exec`）。排序：`ReadOnly < Presentation < Writes < Network < Exec`，仅用于“只升不降”的比较；权限判定按类别逐项配置，不按序号（08）。

### 3.2 Tool trait

```rust
// 草案，以实现为准
pub trait Tool: Send + Sync + 'static {
    fn spec(&self) -> &ToolSpec;
    fn meta(&self) -> &ToolMeta;

    /// 纯函数：根据已收口的参数给出本次调用的效果、目标与审批键。
    /// 不得做 IO（路径规范化除外，由 ctx.paths 提供）。默认实现返回 meta.effect、无目标。
    fn assess(&self, ctx: &ToolContext, args: &Args) -> Result<Assessment, ToolError> {
        Ok(Assessment::from_meta(self.meta()))
    }

    /// 执行。必须响应 ctx.cancel；不得调用引擎，不得读 task_local。
    fn invoke<'a>(&'a self, ctx: ToolContext, args: Args) -> BoxFuture<'a, ToolOutcome>;

    /// 阻塞型效果完成后由引擎回调，把效果结果渲染成最终工具结果。
    /// 默认实现按 §3.3 的标准格式渲染。
    fn resume(&self, ctx: &ToolContext, result: EffectResult) -> ToolOutcome {
        ToolOutcome::render_effect_result(result)
    }
}

pub struct Assessment {
    pub effect: EffectClass,
    pub targets: Vec<Target>,          // Path{domain, path, access} | Command{argv, cwd} | Url(..) | Job(JobId) ...
    pub approval_key: Option<ApprovalKey>, // “本会话内同意”的匹配键（08 §5.3）
    pub risk: Risk,                    // Normal | Dangerous{reason}；Dangerous 永不被会话授权覆盖
    pub summary: String,               // 给审批界面的一行英文摘要，如 `run_command: cargo test -p gqy-core`
}
```

`Args` 是收口后的 `serde_json::Map` 包装，提供 `get_str/get_u64/get_bool/...`，读不到时返回带字段路径的 `ToolError::InvalidArgs`；工具内部不再自己解析字符串数字。

### 3.3 ToolContext、ToolOutcome、ToolEffect

`ToolContext` 是 `TurnContext` 的只读投影（02 §4），外加本次调用的信息。它**不包含**引擎句柄、store 写句柄或审批通道：审批在 `invoke` 之前由引擎完成（§7.1），工具看到的一定是已放行的调用。

```rust
// 草案，以实现为准
pub struct ToolContext {
    pub call: CallId,
    pub session: SessionId,
    pub run: RunId,
    pub venue: Arc<Venue>,
    pub principal: Principal,
    pub workspace: Arc<WorkspaceScope>,  // 读写根、路径守卫、SandboxPolicy（08）
    pub host: Arc<HostFacts>,            // 本回合冻结的 Host 能力（09）
    pub domains: Arc<DomainTable>,       // 存储域解析（§9）
    pub blobs: BlobWriter,               // 大输出落 blob（10）
    pub progress: ProgressSink,          // tool.progress / tool.output 事件（有界、可丢弃）
    pub cancel: CancellationToken,       // run 的子令牌
    pub deadline: Instant,               // 由 TimeoutClass 与配置算出
    pub clock: Arc<dyn Clock>,
}

pub struct ToolOutcome {
    pub status: ToolStatus,              // Ok | Error(ToolError) | Cancelled
    pub content: Vec<ToolContent>,       // Text(String) | Image(BlobRef, mime) —— 模型可见
    pub effects: Vec<ToolEffect>,        // 请引擎执行的动作
    pub footprint: Footprint,            // reads / writes: Vec<PathRef>，memories: Vec<MemoryRef>；工具自报，随结果条目持久化，供 05 §7.2
    pub facts: AuditFacts,               // exit_code、touched、bytes_out、truncated… 只进审计与 UI
}

pub enum ToolEffect {
    /// 子代理：引擎以 parent_run 构造普通 TurnRequest 走准入（02 §3.3、03）。
    SpawnSubturn(SubturnSpec),           // task, tier, background, resume: Option<SessionId>
    /// 后台作业：引擎登记 Job，结果以 job.* 事件和 job_* 工具可见（03 §10.1）。
    StartJob(JobSpec),                   // 命令、PTY 或脚本；携带已判定的 SandboxPolicy
    /// 向用户提问（不是审批）：引擎发 question.asked(kind=ask)，等待回答。
    AskQuestion(QuestionSpec),           // prompt, options(≤6), multi, allow_free_text
    /// 会话自有状态更新（todo 列表等），由引擎落库并广播。
    SessionState(StatePatch),
}
```

- **阻塞与否**：`SpawnSubturn{background:false}` 与 `AskQuestion` 是阻塞效果——引擎执行完后调用 `Tool::resume` 得到最终结果；工具结果在此之前不写入账本。其余效果非阻塞，`content` 立即作为结果。
- **一次调用至多一个阻塞效果**，多于一个时 `Dispatcher` 判为实现错误（`ToolErrorKind::Internal`），测试钉住。
- **标准渲染**：`SpawnSubturn` 结果 `<subagent-result run="…" status="completed">…</subagent-result>`；`AskQuestion` 结果 `User answered: …` 或 `User dismissed the question.`。模板字节固定，形状夹具覆盖（§12.1）。

### 3.4 错误分类

```rust
// 草案，以实现为准
pub enum ToolErrorKind {
    UnknownTool,        // 不在本会话工具面中
    InvalidArgs,        // 带字段路径、期望、实际
    NotFound,
    Denied,             // 权限层拒绝（08），带 layer 与规则 id
    SandboxUnavailable, // 失败关闭（08）
    Conflict,           // 编辑时文件已变、补丁上下文不匹配
    Timeout,
    Cancelled,
    TooLarge,           // 输入超过工具上限（如 write 内容 > 1 MiB）
    Unsupported,        // Host 能力缺失（09），说明缺什么
    Io,                 // 带 errno 名与路径
    Upstream,           // MCP / 脚本 / 网络对端返回的错误，原文截断保留
    Internal,
}
```

模型可见错误文本统一由一个函数渲染：`error[<kind>]: <what>: expected <x>, got <y>`，英文，单行优先，最长 1,000 字符。例：

```text
error[invalid_args]: start_line: expected integer >= 1, got string "abc"
error[not_found]: read: no such file: src/mian.rs (did you mean src/main.rs? 1 candidate in same dir)
error[denied]: run_command: capability mode is ReadOnly (layer=capability, rule=mode.readonly)
error[conflict]: edit: old_string matched 3 times in src/lib.rs; add context or set replace_all=true
```

`did you mean` 只在工具真正做过同目录候选查找时出现，不猜测原因。

## 4 注册表

### 4.1 静态内置表

```rust
// crates/gqy-tools/src/builtin/mod.rs —— 草案，以实现为准
pub static BUILTINS: &[&dyn ToolFactory] = &[
    &read::FACTORY,

    &trash::FACTORY,

    &pty::FACTORY_OPEN, &pty::FACTORY_SEND, &pty::FACTORY_READ, &pty::FACTORY_CLOSE,
    &read_output::FACTORY,
    &job::FACTORY_STATUS, &job::FACTORY_WAIT, &job::FACTORY_OUTPUT, &job::FACTORY_CANCEL,
    &todo_write::FACTORY,
    &load_tools::FACTORY,

    fn build(&self, cfg: &ToolBuildConfig) -> Arc<dyn Tool>;  // cfg 来自 ConfigSnapshot 的只读片段

```

加一个内置工具：新建 `builtin/<name>.rs`（spec、meta、assess、invoke、单元测试），在 `BUILTINS` 加一行，运行 `cargo xtask fixtures refresh --reason "<说明>"` 刷新形状夹具（04 §13）。没有 build.rs 扫描，没有第二份描述文件，没有 UNITS 表。

### 4.2 扩展来源

`gqy-memory`、`gqy-ext` 在更高层（L3），它们通过 `ToolSource` 把自己的工具交给注册表；注册发生在组装处（`gqy-daemon`，01 §3），`gqy-tools` 不依赖它们。

```rust
// 草案，以实现为准
pub trait ToolSource: Send + Sync {
    fn id(&self) -> &'static str;                        // "memory" | "skills" | "scripts" | "mcp:<server>"
    fn snapshot(&self) -> SourceSnapshot;                // 当前可用工具与目录指纹；不做阻塞 IO
}

pub struct Registry {
    builtins: Vec<Arc<dyn Tool>>,
    sources: Vec<Arc<dyn ToolSource>>,
}

impl Registry {
    /// 合成一个不可变的注册表代际。编译工具面只读代际，不直接读来源。
    pub fn generation(&self) -> Arc<RegistryGeneration>;  // 含 generation 号与 catalog_hash
}
```

- 注册表代际在**会话创建或 persona 代际切换**时读取一次（12），v1 “每个 logical turn 开始时 rescan 并冻结” 的语义保留为：扩展目录变化只影响之后创建或切换代际的会话。
- 来源的快照必须是内存中的值；需要 IO 的扫描（技能目录、脚本头部、MCP 列举）由来源自己在后台刷新（18）。

### 4.3 命名与冲突

- 内置工具名 `^[a-z][a-z0-9_]{0,63}$`。扩展工具名由来源加前缀：脚本 `script_<id>`，MCP `mcp_<server>_<tool>`（非法字符替换为 `_`，截到 64 字符，截断冲突时追加 blake3 前 6 hex）。
- 内置名保留；扩展重名时后注册者被丢弃并记 `tool.conflict` 日志与 `gqy doctor` 警告，不静默覆盖。
- 权限按**真名**判定（stub 与完整形态同名）。

## 5 工具面编译与冻结

### 5.1 输入与筛选

```rust
// 草案，以实现为准
pub fn compile_surface(
    reg: &RegistryGeneration,
    persona: &PersonaSnapshot,   // 启用集：显式工具名、工具组、来源 id（12）
    venue: &Venue,               // trust、caps、interactive
    host: &HostFacts,            // 平台能力（09）
    mode: LoadingMode,
) -> Result<ToolSurface, SurfaceError>;
```

筛选顺序（每一步都有日志记录被排除的工具与原因，供 `gqy doctor` 与 `/tools` 显示）：

1. persona 启用集：未启用的工具**不构造**（“决定构造什么，而不是装上再关”）。
2. 场所信任：`meta.min_trust` 高于 `venue.trust` 的排除；`venue.trust == External` 时排除所有 `host: true` 与 `Writes/Exec` 工具（08 §7）。
3. 场所能力：`interactive_only` 工具在 `venue.interactive == false` 时排除（ask_user）。
4. Host 能力：`meta.requires` 不满足的排除（例如无 PTY 能力时排除 pty_*），在 `gqy doctor` 显示“因 Host 缺失 X 未编译”。
5. **能力档位不参与编译**：`CapabilityMode`（ReadOnly/Workspace/Full）会在会话中被用户切换，若参与编译会改变 tools 字节。档位只在分发时判定（08 §4）。

### 5.2 序列化

- 选中的工具按名字排序；每个条目按 `mode` 与 `residency` 取完整形态或 stub 形态（§6）；整个数组经 `gqy-core` 规范化 JSON 序列化（键序固定、无多余空白、数字规范化）。
- 结果是 `ToolSurface { entries, bytes: Arc<[u8]>, surface_hash, registry_generation, mode }`，`surface_hash = blake3(bytes)`。
- `bytes` 进入账本作为会话的固定前缀段（04），供应商适配器只做协议层包装（06），不得重排或改写条目。

### 5.3 冻结与漂移

- 工具面在会话创建时编译，`bytes` 以 blob 形式落库，会话记录保存 `surface_hash`。daemon 重启后**从落库的字节恢复**，不重新编译——否则一次二进制升级就会静默改变前缀。
- 恢复时仍会用当前注册表重编一次做比对：哈希不同记为 `surface_drift`（日志 + 会话视图标记），但会话继续使用冻结字节。
- 冻结字节里有、当前注册表没有的工具，被调用时返回 `error[unknown_tool]: <name> is not available in this build`。
- 冻结 schema 与新实现不兼容时，以新实现的 `Args` 读取结果为准，报错照常说期望与实际。
- 漂移何时应用到会话：见 Q-07-3（推荐在下一次压缩时换面，因为压缩本来就是计划内冷启动）。
- persona 代际切换（12）产生新工具面，这是计划内冷启动，由 04 计入。

## 6 加载模式与 load_tools

| 模式 | Lazy 工具在 tools 数组中的形态 | 前缀稳定性 | 适用 |
| --- | --- | --- | --- |
| `Stub`（默认） | 真名 + `summary (stub)` + 参数壳 `{"type":"object"}` | 会话内恒定 | 所有带前缀缓存的供应商 |
| `Hybrid` | 首次 `load_tools` 前不出现；加载后以完整形态加入 | 每回合至多一次变化，每次是一次冷启动 | 仅用于无缓存、按次计费供应商（06 `PerRequest`） |
| `Full` | 完整形态常驻 | 恒定，但体量大 | 工具少的 persona、调试 |

- `Core` 驻留的工具（read、edit、run_command 等高频工具）在三种模式下都是完整形态。哪些工具是 `Core` 由工具文件自己声明，persona 可以在启用集中把个别 Lazy 工具提升为 Core（12），提升发生在编译期，不在会话中变化。
- stub 描述格式：有 `summary` 时为 `<summary> (stub)`；工具声明了 `stub_example` 时为 `<summary> (stub, e.g. {"query":"x"})`。“先 load_tools 取契约再调用”的说明只在 `load_tools` 自己的描述里写一次（v1 每条 stub 省约 55 字节的教训）。
- stub 的真实参数直接写在调用的顶层（与正常调用一致），执行时无需拆壳。

**`load_tools` 契约**：

- 参数：`{"names": [string]}`，每项是工具名或 `group:<name>`；上限 16 项。
- 结果（tool result，落在对话尾部，不碰前缀）：每个工具一段 `<tool name="…"><description>…</description><schema>…</schema></tool>`，字节来自同一个规范化序列化函数，与 Full 模式的条目内容一致。
- Stub 模式下 `load_tools` 的描述是**常量字节**，不嵌入目录；可加载目标列表以 `<available_load_targets>` 放在 system 段（04 的 S 层），会话内冻结。Hybrid 模式沿用 v1 的动态描述（目录随加载变化），这也是它破坏前缀的原因之一。
- 模型不先加载就直接调用 stub 工具是允许的：分发按真实 schema 收口与校验；参数错误时错误文本附带一句 `hint: call load_tools {"names":["<name>"]} for the full contract`。
- 同一回合重复加载同一工具：返回 `already loaded in this session` 与完整契约的哈希，不重复输出全文。

## 7 分发管线

### 7.1 步骤

```text
ToolCall{call_id, name, arguments_raw}（来自 06 的归一化事件）
  │ 0. 若本次响应 finish_reason=length：全部 tool call 不执行，写 03 §7 的固定合成结果（06、03）
  ├─ 1. 查面：name 不在冻结工具面 → error[unknown_tool]（附最接近的 3 个真名）
  ├─ 2. 解析：arguments_raw → JSON；失败 → error[invalid_args]: arguments is not valid JSON (line l, col c)
  ├─ 3. 收口：按该工具真实 schema 还原类型（§7.2），记录 coercions
  ├─ 4. 校验：必填、类型、additionalProperties；报期望/实际
  ├─ 5. assess：得到 effect / targets / approval_key / risk
  ├─ 6. 权限判定（08 §4，纯函数）→ Allow | Ask(QuestionSpec) | Deny(reason)
  │      Ask：引擎发 question.asked，运行进入 AwaitingApproval（02 §6），等待 Answer
  ├─ 7. invoke（前台：受 deadline 与 cancel 约束；Exec 在沙盒内，08）
  ├─ 8. 执行 effects（引擎）；阻塞效果完成后 resume
  └─ 9. 输出上限与截断（§8）→ 写账本 tool_result → tool.finished 事件 → 审计记录（08 §9）
```

- 步骤 1–6 在 `gqy-tools::Dispatcher::prepare` 中完成，是**唯一**的参数收口点；主回合、子代理、作业唤醒、斜杠命令触发的工具调用都走它。守护见 §12.3。
- 步骤 6 的判定函数在 `gqy-tools::permission`（纯函数、无 IO），“提问与等待”由引擎执行，因为只有会话 actor 能接收 `SessionCmd::Answer`（02 §3.2）。
- 同一响应中的多个工具调用：按 03 §6.2 分组执行——连续的 `ReadOnly`/`Presentation` 且 `meta.parallel_safe = true` 的调用组内并发（上限 `engine.tool_parallelism`，默认 8），`Writes`/`Exec`/`Network` 各自单独成组形成屏障；结果一律按请求顺序落账。组内需要审批的调用按顺序逐个提问，全部回答后整组执行。
- 取消：回合取消时，未完成的调用写入 `error[cancelled]` 结果，保持 tool_call / tool_result 配对（02 §5）。

### 7.2 参数收口规则

规则只在 schema 明确声明目标类型时生效，递归深度上限 8，每次还原都记录 `Coercion{path, from, to}`。

| schema 类型 | 模型给的值 | 还原为 | 不还原（报错）的情况 |
| --- | --- | --- | --- |
| `integer` | `"12"`、`" 12 "`、`12.0` | `12` | `"12.5"`、`"1e3"`、超出 i64 |
| `number` | `"3.5"` | `3.5` | 非有限值、`"NaN"` |
| `boolean` | `"true"`/`"True"`/`"TRUE"`/`"false"`/`"False"` | `true`/`false` | `"yes"`、`"1"`、`1` |
| `array` | JSON 数组的字符串形式 `"[\"a\",\"b\"]"` | 数组 | 字符串不以 `[` 开头且 `items` 不是 `string` |
| `array`（`items: string`） | 单个字符串 `"a"`（不以 `[` 开头） | `["a"]` | — |
| `object` | JSON 对象的字符串形式 | 对象 | 解析失败 |
| 可选字段 | `null` | 删除该键 | 必填字段为 `null` → 报错 |
| `string` | 数字或布尔 | **不还原**，报错 | 避免把 `true` 静默变成路径 `"true"` |

- 未知字段：schema 为 `additionalProperties: false` 时报错，列出未知键与全部允许键；否则忽略并记录。
- enum 值大小写不符（如 `"Replace"` 对 `["replace"]`）：只在唯一大小写不敏感匹配时还原并记录。
- 还原后的参数进入 `Args`；**原始参数字节**（包括非法 JSON 的半截字符串）原样保存在账本的 `Raw` 通道和审计记录中，作为取证链，永不净化。

### 7.3 调用去重与幂等

- `CallId` 由供应商给出；缺失或重复时由 `gqy-ledger` 按 `(run, index)` 生成稳定 ID（04）。
- 恢复（02 §9）不重放工具调用：非终态调用按 03 §13 的合成结果文案补写（按效果类别区分），由模型决定是否重试。

## 8 输出上限与截断

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 截断时机 | 工具结果**写入账本时**一次性截断（05 §10），之后永不再改 | 截断只有这一处，不存在事后 prune |
| 截断策略 `ToolMeta.output: OutputPolicy` | 默认 `HeadTail { limit: 8192, head: 4096, tail: 1024 }`（字符，05 §10） | 按 Unicode 标量计数，切片走 `gqy-core` 安全切片；工具可声明自己的策略 |
| 工具声明示例 | `run_command`、`job_output`：`HeadTail { limit: 20000, head: 12000, tail: 6000 }`（v1 run_command 值）；`read`：`SelfBounded`（自带 50 KiB / 2,000 行上限）；`subagent`：`HeadTail { limit: 16384, … }` | `SelfBounded` 的工具不再二次截断 |
| 原始捕获硬上限 | 8 MiB（v1 值） | 超过后继续读取并丢弃，只计数，防止子进程因管道满而阻塞 |
| 原始捕获去向 | blob（blake3 内容寻址，10），`Raw` 通道记录引用 | 模型用 `read_output`（或 `read out:<call_id>`）分段取回 |

截断标记（固定模板，英文）：

```text
[… 48213 chars truncated; full output: out:call_7f3a — use read_output to view a range …]
```

- 头尾比例选择理由：命令输出的错误信息多在尾部，结构信息多在头部。截断标记模板只有这一份，05 §10 引用它。
- 图片内容不计入字符上限；单次结果至多 4 张，单张经 blob 引用，是否送给模型由 `ProviderProfile` 的视觉能力决定（06）。
- `tool.output` 进度事件对 UI 流式展示，前端展示也受每调用 1 MiB 上限，超出只显示计数；UI 与模型看到的截断点不同是允许的，但**模型可见文本只有一条渲染路径**。

## 9 存储域与统一补丁

### 9.1 存储域

文件类工具（read、write、edit、apply_patch、glob、grep、trash）的路径参数可以带域前缀：

| 前缀 | 域 | 提供者 | 读写边界 |
| --- | --- | --- | --- |
| 无前缀 | 工作区文件系统 | `gqy-tools` | `WorkspaceScope` + 路径守卫（08 §6） |
| `artifact:` | 会话/用户的产出物库 | `gqy-tools`（数据落 blob + 索引表，10） | 按 principal 隔离 |
| `kb:` | 知识库 | `gqy-memory`（11） | 按 persona / principal 可见性 |
| `out:` | 本会话工具输出全文（只读） | `gqy-tools` | 只能读本会话的 `CallId` |
| `history:` | 本会话压缩折叠原文转录（只读，`history:fold/<epoch>`，05 §7.4） | `gqy-tools`（数据在 `compactions.transcript_blob`，10） | 只能读本会话 |
| `skill:` | 已启用技能的资源文件（只读，`skill:<name>/<path>`，18 §4.3） | `gqy-ext` | 只能读本会话 persona 启用的技能 |

这是存储域的唯一清单；10、11、18 引用本表，新增域必须先登记在这里。所有带前缀的域都不走文件系统路径守卫，由域自身按 principal / 会话隔离（08 §6.1）。

```rust
// 草案，以实现为准
pub trait StorageDomain: Send + Sync {
    fn prefix(&self) -> &'static str;                            // "artifact:" 等
    fn resolve(&self, ctx: &ToolContext, rel: &str) -> Result<DomainPath, ToolError>;
    fn read(&self, p: &DomainPath, range: ReadRange) -> BoxFuture<'_, Result<ReadChunk, ToolError>>;
    fn list(&self, p: &DomainPath, pattern: &GlobPattern) -> BoxFuture<'_, Result<Vec<Entry>, ToolError>>;
    fn apply(&self, ctx: &ToolContext, ops: &[PatchOp]) -> BoxFuture<'_, Result<ApplyReport, ToolError>>;
    fn writable(&self) -> bool;
}
```

`DomainTable` 在组装处（`gqy-daemon`）构建，`kb:` 由 `gqy-memory`、`skill:` 由 `gqy-ext` 注册——与 `ToolSource` 一样，依赖只向下。

### 9.2 统一补丁格式

所有写入最终都表示为 `PatchOp` 序列：`Add{path, content}`、`Update{path, hunks, move_to}`、`Delete{path}`。`apply_patch` 的文本格式沿用 v1：

```text
*** Begin Patch
*** Update File: src/lib.rs
@@ fn main
-    println!("old");
+    println!("new");
*** Add File: docs/notes.md
+hello
*** Delete File: tmp/old.txt
*** End Patch
```

- **一个补丁只能指向一个域**（v1 规则：`one patch must target a single namespace`）。
- **原子性**：先对全部操作做预检（路径守卫、上下文匹配、目标存在性），全部通过后才写；文件系统域逐文件“写临时文件 + fsync + rename”，中途失败时回滚已替换的文件（保留 `.gqy-bak` 直到补丁完成）。
- `Delete` 一律走回收站（08 §5.4），不直接 unlink。
- `edit` 与 `write` 在内部也构造 `PatchOp`，共用同一套预检与写入代码——写入路径只有一条。
- 补丁预览（diff）与写入使用同一解析结果，UI 展示的 diff 就是将要应用的内容。

## 10 内核内置工具

所有模型可见文本为英文；下表“契约”是描述的要点，不是描述原文。限额为默认值，集中在 `gqy-config`（02 §6）。

| 工具 | 类别 | 驻留 | 契约与上限 |
| --- | --- | --- | --- |
| `read` | ReadOnly | Core | 读文件或域路径；`offset`（行，1 起）/`limit`；单次 ≤ 50 KiB、≤ 2,000 行、单行 > 2,000 字符截断并标注；二进制（前 8 KiB 含 NUL）拒绝并报 mime 与大小；图片按视觉能力返回图像；目录返回错误并提示用 glob |
| `glob` | ReadOnly | Core | glob 模式匹配文件，遵守 `.gitignore`；按修改时间倒序；≤ 1,000 条，超出报总数 |
| `grep` | ReadOnly | Core | 正则搜索（ripgrep 同类 crate，进程内，不依赖 PATH 上的 rg）；`output_mode` = files / content / count；≤ 200 个匹配或 100 个文件；30 s 超时（v1 值） |
| `write` | Writes | Core | 创建或整体覆盖文件；内容 ≤ 1 MiB；覆盖已存在文件时结果中报告原大小；父目录不存在时创建 |
| `edit` | Writes | Core | `old_string` → `new_string` 精确替换；非唯一匹配且未设 `replace_all` 时报匹配次数；预检后到写入前文件哈希变化 → `error[conflict]` |
| `apply_patch` | Writes | Core | §9.2 格式；≤ 256 KiB 补丁文本、≤ 64 个文件 |
| `trash` | Writes | Lazy | 把路径移入系统回收站；拒绝目标见 08 §5.4；单次 ≤ 64 个路径 |
| `run_command` | Exec | Core | `sh -c`（非 login shell，环境见 08 §6.3）在工作区内执行；`timeout_seconds` 1–600（默认 120）；`background: true` 直接转作业；软超时到期转作业并返回 `JobId`（02 §6）；输出 §8 |
| `pty_open` | Exec | Lazy | 在 PTY 中启动程序；`cols`/`rows`（默认 120×40）；每会话 ≤ 4 个；空闲 30 min 自动关闭 |
| `pty_send` | Exec | Lazy | 写入文本或命名按键（`Enter`、`C-c`、`Up`…）；单次 ≤ 4 KiB |
| `pty_read` | ReadOnly | Lazy | 等待输出静默（`wait_ms` ≤ 10,000）后返回**屏幕快照**（终端仿真器渲染后的文本），不返回原始转义序列 |
| `pty_close` | Exec | Lazy | 关闭 PTY：SIGHUP → 2 s → SIGKILL（02 §6） |
| `read_output` | ReadOnly | Core | 按范围读取本会话某次调用的输出全文（`out:` 域）：`call_id`、`offset`/`limit`（字符）；05 §10 截断标记指向它 |
| `job_status` | ReadOnly | Core | `id?`：省略时列出本会话作业；返回状态、耗时、退出码（03 §10.1） |
| `job_wait` | ReadOnly | Core | 等待作业结束或超时；单次 ≤ 120 s（03 §10.1），可被回合取消打断 |
| `job_output` | ReadOnly | Core | 作业输出分段读取；截断策略见 §8 |
| `job_cancel` | Exec | Core | 按 02 §6 终止作业进程组 |
| `todo_write` | Presentation | Core | 整表替换；≤ 50 项；状态 pending / in_progress / completed，至多一个 in_progress；效果 `SessionState` |
| `load_tools` | Presentation | Core | §6 |
| `subagent` | Presentation（效果决定实际权限） | Lazy | 参数 `task`、`tier`、`background`、`resume_id`（v1 同名）；描述为常量字节；效果 `SpawnSubturn`；并发 ≤ 4、深度上限见 03 |
| `ask_user` | Presentation | Lazy，`interactive_only` | 向用户提问：`question`、`options`（≤ 6）、`multi`；效果 `AskQuestion`；与审批共用 Question 通道但 kind 不同（08 §5） |
| `web_fetch` | Network | Lazy | 取一个 URL 转 Markdown；≤ 5 MiB 下载、20 s 超时、只允许 http/https、拒绝私有地址段（除非配置放行）；是否进内核见 Q-07-1 |

说明：

- **能力依赖**（`meta.requires`，09 §4.1）：`run_command`、`job_cancel`、脚本工具需要 `ProcessGroup`；`pty_*` 需要 `Pty`；`trash` 需要 `Trash`。能力缺失（例如 Windows，00 §5 平台范围）时这些工具不编译进工具面，沙盒缺失则由 08 在分发时失败关闭。工具实现中不写 `cfg(target_os)`。
- **没有独立的 delete/rm 工具**：删除只能走 `trash` 或补丁的 `Delete`，二者都进回收站。
- **子代理的工具面**：子回合使用父会话工具面的冻结快照减去 `ask_user`（非交互），并按 `tier` 限制（03）。`subagent` 本身不出现在深度已达上限的子回合面中——这属于子回合会话自己的工具面，与父会话字节无关。
- **v1 的 `check_os_info`** 不再是工具：Host 信息由感知矩阵提供（09），需要细节时用 `run_command`。
- 伴侣功能（记账、玄学、游戏查询、生图、快递、汇率等）不在此表，按 00 §4 以扩展形式回归（18）。

## 11 边界与失败模式

| 情形 | 行为 |
| --- | --- |
| 工具 panic | `invoke` 在独立任务中运行，`JoinError` 转为 `error[internal]`，回合继续；clippy 已禁止非测试代码 panic，这是兜底 |
| 工具忽略取消 | 取消后 2 s 未返回：放弃等待、写 `error[cancelled]`、记 `tool.cancel_overrun` 告警；子进程由进程组清理 |
| 同步阻塞 IO | 工具内一律经 `gqy_core::blocking::run`（02 §2）；xtask 扫描 `std::fs::` 在 async fn 中的直接调用 |
| 输出含已知密钥 | 结果进入账本前做精确值替换（08 §9.3） |
| 工具面超出供应商限制 | 例如工具数 > `ProviderProfile.max_tools`：编译失败，会话创建报错并列出超出数量，不静默丢弃 |
| 模型调用不存在的工具 | `error[unknown_tool]` + 最接近的 3 个真名（编辑距离） |
| 冻结面与实现不一致 | §5.3 |
| 存储域不可用（如 kb 未启用） | `error[unsupported]: kb: domain is not enabled for this persona` |

## 12 测试与守护

### 12.1 形状夹具

- 位置：`crates/gqy-tools/tests/fixtures/shapes/<surface>.json`。每个文件记录一个**代表性工具面**中每个工具条目的 sha256（v1 同口径，便于 `sha256sum` 手工核对）以及整个面的 `surface_hash`。
- 代表性工具面（至少）：`coding.owner.tui.stub`、`coding.owner.tui.full`、`coding.owner.tui.hybrid-initial`、`chat.external.connector.stub`、`subagent.depth1.stub`、`noninteractive.timer.stub`。
- `cargo xtask fixtures check` 在 CI 中运行；失败信息列出哪个工具、哪个面的哈希变了，以及新旧规范化 JSON 的 diff。刷新用 `cargo xtask fixtures refresh --reason "<说明>"`（04 §13），PR 描述必须写明变化原因（它意味着前缀变化）。
- 区分能力：修改任一工具描述中的一个字符，对应夹具必须变红（测试中自动做这次变异）。

### 12.2 确定性

- 同一输入编译两次，字节相等；在不同工作目录、不同 `HOME`、不同时区、不同 locale 下编译，字节相等（测试中逐项改环境）。
- 描述插值禁令：`xtask` 规则检查内置工具的 `ToolSpec` 字段只能是字符串字面量（不得出现 `format!`）；扩展工具的描述来自文件或列举结果，按来源快照冻结（18）；动态目录只允许出现在 system 段（04）或 load_tools 结果中。

### 12.3 收口唯一性

- 参数收口的表驱动测试覆盖 §7.2 每一行（还原与不还原各一例），并断言原始字节被保存。
- 集成测试：同一个 `"start_line": "1"` 分别经主回合、子回合、作业唤醒、斜杠命令四条入口发起，四处结果一致；把收口从 `Dispatcher::prepare` 移走后测试变红。
- `cargo xtask arch` 增加规则：`gqy-tools` 之外禁止调用 `Tool::invoke`（只能经 `Dispatcher`）。

### 12.4 其他

- 输出截断：构造 100,000 字符输出，断言头尾长度、标记模板、`read_output` 能取回全文。
- 并行分组：见 03 §16 的“并行落账顺序”与“屏障”测试；`parallel_safe = false` 的只读工具单独成组。
- `yes` 压力测试：run_command 执行 `yes` 5 秒，daemon RSS 增长 < 32 MiB，捕获停在 8 MiB。
- 取消：pty 与 run_command 在取消后 1 s 内进程组退出（02 §10）。
- 接线成本守护：新增一个测试用内置工具的 PR 模板在 CI 中统计改动文件数（`builtin/<name>.rs`、`builtin/mod.rs`、夹具），超出即提示。
