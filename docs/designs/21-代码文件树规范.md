## 3 crates/：crate 内部约定

### 3.1 模块与 lib.rs

- `src/lib.rs` 只放：crate 文档（`//!`：一句话职责 + 设计出处）、`mod` 声明、`pub use` 再导出；不放实现。
- 模块文件扁平优先：`src/<module>.rs`；成组时用目录 `src/<group>/mod.rs`，`mod.rs` 只做声明与再导出；**不用** `src/foo.rs` + `src/foo/` 混排（沿用仓库里已有的写法）。
- 文件与模块名 snake_case、一一对应；跨 crate 可见的类型经 crate 根再导出，模块内部实现默认私有。
- 一个文件一个概念；零散小类型并入它服务的模块，不为单个类型建目录（AGENTS.md「文件要小」「模块职责单一」）。

### 3.3 测试与夹具

| 层 | 位置 | 备注 |
| --- | --- | --- |
| 单元 | 实现文件内 `#[cfg(test)] mod tests`；模块变大后移到该模块目录下的 `tests.rs` | 19 §5.2 的例子：`crates/gqy-ledger/src/plan/tests.rs` |
| crate 集成 | `crates/<crate>/tests/<主题>.rs`，一主题一文件 | `store_basic.rs`、`migration_guards.rs` |
| crate 夹具 | `crates/<crate>/tests/fixtures/<主题>/`，主题目录 kebab-case | crate 专属夹具，例如供应商流；跨 crate 的 `request-shapes/` 不放在这里 |
| 跨 crate 字节夹具 | 根 `tests/fixtures/<主题>/` | 共享 `request-shapes/` 与其他跨 crate 字节契约，见 §6 第 1 项 |
| 端到端 / 浏览器 | 根 `tests/e2e/*.sh`（M1 验收脚本起）、`tests/web/` | 19 §4 |
| 基准 | `crates/<crate>/benches/<name>.rs` | criterion；不作 CI 失败条件 |
| 门禁自测 | `xtask/tests/*.rs` | xtask 那几步 |

- 集成测试文件头按测试的样板放开 `unwrap / expect / panic / indexing_slicing`（只对测试代码）。
- 需要真实环境的用例标 `#[ignore = "needs:<tag>"]`（19 §4.1），由 `cargo xtask test --include-ignored=<tag>` 选择性运行。
- 测试的数据目录一律来自 `TestHome`（19 §4.1）；不依赖真实数据目录。

### 3.4 资源与数据文件

- 迁移 SQL：`crates/gqy-store/migrations/NNNN_<name>.sql`，`include_str!` 编入二进制；`CHECKSUMS` 同目录。
- 提示词与工具描述：`crates/<crate>/resources/<文件>`，用 `include_str!` / `include_dir!` 内嵌，不散落在逻辑代码中（AGENTS.md「不硬编码」）。落地时同步 07/12 与本文（§6）。
- 二进制样本（`.db`、`.png` 等）在 `.gitattributes` 标 `binary`；文本夹具一律 LF（`*.sse -text` 随后补上）。

## 4 apps/、xtask/ 与根 tests/

- `apps/gqy/`：入口二进制——`src/main.rs` 子命令分发、`src/cmd/<子命令>.rs` 一文件一子命令、`src/logging.rs` 日志初始化；daemon 角色调用 `gqy-daemon` 组装，不自己拼装（01 §3）；契约测试与夹具在 `apps/gqy/tests/`。
- `apps/tui/`（crate `gqy-tui`，创建最小版）：先 `src/{lib.rs,app.rs,ui.rs,input.rs}`；后来照 14 §3 展开为 `state/ update/ layout/ view/ transcript/ editor/ commands/ image/ effects/`，`view/` 下每个区域一个文件。
- `apps/web-console/`：照 15 §4 —— `src/{core,state,widgets,features,app}/`、`styles/`、`index.html`；`dist/` 不入库；生成类型固定落 `src/core/generated/`，文件头标「生成文件，勿手改」，由 `cargo xtask gen-ts --check` 守护。
- `apps/desktop/src-tauri/`、`apps/connectors/`：随各自施工单创建。
- `xtask/`：`src/main.rs` + 每类检查一个模块（`arch/{mod,layers,scan}.rs`、`size.rs`、`check.rs`、`test/{mod,parse,report,count_gate}.rs`，后续 `gen_ts.rs`、`compat_scan.rs`、`migrations.rs`、`fixtures.rs`、`web/*`、`plan.rs`）+ `baselines/`（测试计数基线，Q-19-5）+ `tests/`（门禁自测）。
- 根 `tests/`：跨 crate e2e（`e2e/*.sh`）与浏览器测试（`web/`）；夹具归属见 §3.3 表。

## 5 守护方式

| 约定 | 守护 |
| --- | --- |
| 层序、依赖方向、附加约束、重依赖白名单 | `cargo xtask arch`（01 §3） |
| `task_local!`、可变全局 `static`、`#[instrument]` 缺 `skip_all` | `cargo xtask arch` 扫描器 |
| 文件体积 800 / 1500 / 2000 行（`.rs` / `.ts` / `.css`） | `cargo xtask size`（00 §3） |
| `missing_docs`、`missing_errors_doc`、rustdoc 断链（含私有项） | clippy 与 `cargo doc` |
| 吞错误（`let _ =`、`.ok()`）、`unwrap / expect / panic`、无界通道、`block_on` | clippy lints 与 `clippy.toml` |
| 测试计数不下降、按 `needs:<tag>` 运行 | `cargo xtask test` + `xtask/baselines/` |
| 迁移只增、编号与校验和 | `cargo xtask migrations` + `CHECKSUMS` |
| Web 分层（`core → state/widgets → features → app`）与生成类型不被手改 | `xtask/src/web/layers.rs`（15 §4） |
| 本文的目录与文件布局、命名 | 评审（`cargo xtask fixtures refresh` 只管夹具内容刷新，不管位置） |
