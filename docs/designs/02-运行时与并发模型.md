# 02 · 运行时与并发模型

> 状态：【规划】。前置阅读：00、01。本文针对 v1 最致命的缺陷：单线程 runtime 加隐式上下文（00 §1.1、§1.2）。

## 1 目标

1. 一个会话卡住（慢模型、挂死的 MCP、长命令、压缩）时，其他会话照常推进。
2. 取消、超时与停机是协议的一部分，能从入口一直传播到 HTTP 请求和子进程。
3. 所有状态都有唯一所有者；跨任务共享的只有不可变快照和消息。
4. 并发正确性不依赖“碰巧是单线程”。

## 2 运行时布局

| 执行体 | 数量 | 用途 | 约束 |
| --- | --- | --- | --- |
| tokio 多线程 runtime | 1 个，worker 数 = 可用核数（上限可配置） | 网关、Supervisor、会话 actor、回合任务、供应商流、事件总线 | 不得做同步阻塞 IO；不得跨 `.await` 持有 std 锁 |
| tokio blocking 池 | 默认上限 64 | 大文件读写、压缩解压、哈希大 blob、同步第三方库 | 调用方经 `gqy_core::blocking::run(label, f)` 包装：统一计时、限流、tracing |
| store 写者线程 | 1 条 OS 线程 | SQLite 唯一写连接，批量提交（10） | 写请求经有界队列进入，每个请求自带超时 |
| store 读连接池 | 默认 4 | 只读查询 | 在 blocking 池执行，不占 async worker |
| 子进程 | 按需 | 命令、PTY、MCP、脚本工具 | 独立进程组；超时与取消时整组终止（§6） |

库 crate（包括组装层 `gqy-daemon`）禁止创建 runtime，也禁止调用 `block_on`。这两条由 clippy 的 `disallowed_methods` 钉住（`Runtime::new`、`Handle::block_on`、`futures::executor::block_on`）。只有入口二进制（`apps/gqy` 与桌面宿主，01 §3 的 L7）可以创建 runtime。

## 3 所有权模型

```text
Daemon
 ├─ Gateway（axum）──submit/cancel/query──▶ Supervisor
 └─ Supervisor（单任务，持有 SessionId → SessionHandle 表）
      └─ SessionActor（每个已加载会话一个任务，持有 SessionState）
           ├─ RunTask（当前回合，至多一个；由 actor 通过 JoinHandle + 取消令牌持有）
           └─ ExclusiveOp（压缩 / 回退 / 分叉等独占操作，与 RunTask 互斥）
```

### 3.1 Supervisor

- 负责会话的加载、卸载与路由，自身不执行任何业务逻辑，所以永远不会阻塞在业务上。
- 表项为 `SessionHandle { tx: mpsc::Sender<SessionCmd>（有界）, state: watch::Receiver<SessionSummary> }`。
- 会话空闲超过 `session_idle_unload`（默认 30 分钟）且没有活动回合时，卸载其 actor。再次访问时从 store 重建。
- 并发上限：全局活动回合数用 `Semaphore` 限制（默认 16）；每个场所配额类别另有配额（连接器默认 8、定时器默认 4，类别表见 12 §6.2），防止群聊洪峰挤占终端。

### 3.2 SessionActor

- 独占持有 `SessionState`：会话快照（persona 代际、场所、工具面、模型绑定）、账本游标、排队中的请求、当前运行、独占操作状态。
- 消息循环只做**状态转移**，不做耗时工作。耗时工作（回合、压缩）作为子任务 spawn 出去，完成后以消息形式回报 actor。v1 压缩把所有会话拖死四分半的根因（在主循环里直接 await）因此在结构上不可能出现。
- 命令：

```rust
// 草案，以实现为准
enum SessionCmd {
    Submit { req: TurnRequest, reply: oneshot::Sender<Admission> },
    Cancel { run: Option<RunId>, reason: CancelReason },
    Exclusive { op: ExclusiveOp, reply: oneshot::Sender<Result<OpTicket, BusyError>> },
    Answer { question: QuestionId, answer: Answer },   // 审批与提问的回复
    RunFinished { run: RunId, outcome: RunOutcome },   // 子任务回报
    OpFinished { op: OpId, outcome: OpOutcome },
    Snapshot { reply: oneshot::Sender<SessionView> },
    Shutdown { deadline: Instant },
}
```

- 独占性是**会话级**的：独占操作与当前运行互斥，只影响本会话。v1 的全局 `admin_busy` 布尔被整体取消。
- **压缩的两种形态**：回合内压缩（预检触发、强制档、溢出恢复）在持有执行权的运行内执行（运行状态 `Compacting`，03 §3），不申请 `ExclusiveOp`；只有手动压缩（以及撤销压缩）作为 `ExclusiveOp::Compact` 提交（05 §8）。两者都以子任务运行，actor 只收发消息。

### 3.3 准入的唯一入口

所有回合发起方都构造 `TurnRequest`，并经 `Supervisor::submit` 进入：TUI、Web、`gqy ask`、连接器、定时器、作业唤醒、子代理、聊后复盘都一样。`TurnRequest` 必须带 `Venue`（12）。子代理也不能绕过这条路，它的回合是一个带父运行 ID 的普通回合（03）。`SessionActor` 的构造函数不公开，引擎之外拿不到绕过准入的句柄。

## 4 TurnContext：显式的回合上下文

回合开始时，actor 用不可变快照构造 `TurnContext`，按值（`Arc`）传给回合任务。回合中的每一层都从参数拿上下文。禁止用 `task_local!` 或全局可变状态传递业务上下文，由 `cargo xtask arch` 用 grep 规则检查 `task_local!` 的出现。

```rust
// 草案，以实现为准
pub struct TurnContext {
    pub session: SessionId,
    pub run: RunId,
    pub parent_run: Option<RunId>,        // 子代理
    pub depth: u8,                        // 子代理嵌套深度，上限见 03
    pub venue: Arc<Venue>,                // 来源场所：信任级、能力、交互性
    pub principal: Principal,             // 随会话冻结
    pub persona: Arc<PersonaSnapshot>,    // 会话代际内冻结
    pub surface: Arc<ToolSurface>,        // 会话内字节恒定的工具面
    pub model: ModelBinding,              // 供应商 + 模型 + 能力画像
    pub workspace: Arc<WorkspaceScope>,   // 工作区根、读写边界、沙盒策略
    pub perception: Arc<PerceptionFrame>, // 本回合冻结的感知值（09）
    pub config: Arc<ConfigSnapshot>,      // 回合开始时的配置快照
    pub budget: TurnBudget,               // 请求数、工具调用数、时长、token 预算
    pub cancel: CancellationToken,        // 运行级取消令牌
    pub events: EventSink,                // 有界事件出口
    pub clock: Arc<dyn Clock>,
}
```

- **快照语义**：配置、persona、感知值在回合开始时冻结，回合内不变。配置热更新只影响下一回合；persona 变化按代际切换（12）。
- **工具上下文**：`ToolContext` 是 `TurnContext` 的只读投影，另加本次调用的 `CallId`、子取消令牌和审批通道（07、08）。

## 5 取消

取消令牌是一棵树（`tokio_util::sync::CancellationToken` 的 child token）：

```text
daemon ─▶ session ─▶ run ─▶ request（供应商流）
                        └─▶ tool call ─▶ 子进程组 / MCP 请求
```

- 取消原因用枚举表示：`User`、`Superseded`（新代际覆盖）、`Timeout`、`Shutdown`、`Budget`、`Admin`，写入运行终态。
- 被取消的回合，状态机进入 `Cancelled` 终态。已落库的账本条目保留，不做回滚；尚未完成的工具调用写入“已取消”的工具结果，以保持 tool_call / tool_result 配对完整（03、04）。
- 取消到停止的时限：模型流在 1 秒内停读并关闭连接；子进程按 §6 的宽限流程处理。

## 6 超时与上界

每一种等待都要有上界（铁律 5）。默认值集中在 `gqy-config` 的一处定义，可以配置，但不能关闭，只能放宽到上限。

| 等待 | 默认 | 上限 | 超时后 |
| --- | --- | --- | --- |
| 供应商建连 | 10 s | 60 s | 按重试策略处理（06） |
| 供应商首字节 | 120 s | 600 s | 同上 |
| 供应商流空闲（两个 SSE 事件之间） | 90 s | 600 s | 中止本次请求，错误分类为 `StreamStalled` |
| 单次请求总时长 | 20 min | 60 min | 中止 |
| 工具调用（前台） | 120 s | 600 s | 见下方“长命令” |
| MCP 请求 / 列举 | 60 s / 15 s | 300 s / 60 s | 该调用返回超时错误；服务器标记为不健康 |
| store 写入排队 | 5 s | 30 s | 返回 `StoreBusy`；回合失败，不静默丢写 |
| 审批等待 | 无超时，但可取消 | — | 等待期间运行处于 `AwaitingApproval`，不占全局回合配额 |
| 停机宽限 | 10 s | 60 s | 强制终止剩余子进程 |

- **长命令不丢回合**（v1 backlog：300 秒超时直接杀进程、整轮丢失）：前台命令超过软超时后，不杀进程，而是转为后台作业（03），工具结果立即返回作业句柄。模型可以轮询或等待作业。硬上限到期才终止。
- **子进程终止流程**：先向进程组发 SIGTERM，等待 2 秒，再发 SIGKILL，然后回收（reap）。PTY 会话另外先发 SIGHUP。
- **重试**：只在最外层重试一次决策，禁止嵌套重试。退避采用带抖动的指数退避，封顶 30 秒，总次数有上限（06）。

## 7 背压与通道

- **禁止无界通道。** `mpsc::unbounded_channel` 列入 `disallowed_methods`。
- 默认容量：会话命令 64，事件出口每订阅者 1024，store 写队列 4096。
- 通道满时的策略必须在代码中显式选择，三选一：
  - **等待**：带超时（例如 store 写入）；
  - **拒绝**：返回 Busy（例如准入）；
  - **降级**：丢弃可重建的数据。只有事件流可以这样做，见下文。
- **事件总线**：每个事件有会话内单调递增的 `seq`，并先落库再广播（完整事件或可重建的摘要）。订阅者落后导致缓冲溢出时，总线发出 `resync_required { from_seq }`，客户端按 seq 从网关补拉（13）。补拉有上限，超限就整页刷新会话视图，所以不会像 v1 前端那样陷入 resync 死循环。

## 8 共享状态规则

- 允许的全局状态：`OnceLock` 形式的不可变值（编译好的正则、内嵌资源）。可变的全局 `static` 一律禁止，由 xtask 规则扫描 `static .*Mutex|RwLock|RefCell`。
- 配置：`ArcSwap<Config>`。写入时原子替换，读取方取快照。保存配置经单一写入路径完成：先读当前值，校验，写临时文件，`rename`，最后替换内存。同一时刻只有一个写者，因此不会出现 v1 那样的并发保存互相回滚 secret。
- 授权与访问索引属于数据库事实，按请求查询（可以带有明确失效机制的缓存）。不再使用 v1 那种“进程内一次性缓存导致撤销要重启才生效”的做法。
- std `Mutex` 只用于极短的临界区，并用 clippy `await_holding_lock` 守护；需要跨 await 的场合，改成由 actor 持有状态。

## 9 停机与恢复

1. 收到 SIGINT 或 SIGTERM（两者都处理），或 `gqy daemon stop`：网关停止接受新请求，已有 SSE 连接收到 `daemon.stopping`。
2. Supervisor 向全部会话广播 `Shutdown { deadline }`，运行以 `CancelReason::Shutdown` 取消。
3. 在宽限期内等待运行进入终态；工具子进程按 §6 终止。
4. store 写队列排空，执行 WAL checkpoint，然后关闭写者线程。
5. 删除 `run/daemon.json`，释放锁，退出码 0。超过宽限期强制退出时，退出码非零。

**恢复**只在 daemon 启动时做一次（v1 是每次 StartTurn 前都做两次）：凡是处于非终态的运行，一律标为 `Interrupted`，并补写配对完整的工具结果；持久化定时器按到期时间补跑或标记为错过（03）。

## 10 测试与守护

- 可确定性测试：`#[tokio::test(start_paused = true)]` 配合注入的 `Clock`，覆盖所有超时路径。
- **隔离回归测试**（针对 v1 事故）：会话 A 的工具阻塞 30 秒，同时会话 B 完成 10 个回合，B 的 p99 延迟不受 A 影响。去掉 blocking 池包装后此测试必须变红。
- **压缩隔离测试**：会话 A 压缩时，会话 B 的回合正常推进。
- **取消传播测试**：取消运行后 1 秒内，mock 流连接被关闭，子进程组全部退出（用 pid 探测验证）。
- **停机测试**：SIGTERM 后，非终态运行在重启时恢复为 `Interrupted`，工具调用配对完整。
- **静态规则**：禁用方法列表、`task_local!` 扫描、可变全局扫描，都纳入 `cargo xtask arch`。
