# 18 · 扩展体系

> 状态：【规划】。前置阅读：[00 设计理念](00-设计理念.md)（§4 范围：内核先行，伴侣后置）、[01 总体架构](01-总体架构.md)（`gqy-ext`、`gqy-memory` 位于 L3）、[02 运行时与并发模型](02-运行时与并发模型.md)、[07 工具系统](07-工具系统.md)、[08 权限审批与沙盒](08-权限审批与沙盒.md)；相关：04 前缀缓存账本、09 感知矩阵、11 记忆与知识库、12 人格配置与场所。
>
> 本文回答：内核之外的能力如何接入——进程内子系统钩子、技能、脚本工具、MCP 服务器、扩展包——以及它们各自的字节契约、信任、隔离与失败方式。

## 1 目标

1. **一个抽象、多个来源**：技能、脚本、MCP 最终都成为 `Tool`（经 `ToolSource`，07 §4.2）或 system 段提示片段；引擎不认识“脚本”“MCP”这些词。
2. **子系统用钩子挂接**，不在回合循环里写死调用（v1 挂接点 A/B/C 写死在 `turn_loop/stream.rs`）。
3. **扩展不能破坏字节契约**：钩子产出只能追加到尾部 `Context` 通道并化石化；目录变化只在会话代际边界生效（04、12）。
4. **扩展不能扩大权限**：扩展声明能力，内核按声明收紧沙盒；声明不能超出安装时用户确认过的范围（08）。
5. **伴侣功能以扩展回归**（00 §4 已定决策）：语音、记账、玄学、游戏查询、日用查询都不进内核。

## 2 v1 教训

| v1 事实 | 数字 / 证据 | v2 的回答 |
| --- | --- | --- |
| 无子系统 trait | 全库 5 个 trait；记忆挂接点写死在回合循环 | `SubsystemHooks`（§3） |
| MCP 读 stdout 无超时 | `read_line` 永久占住唯一执行线程，冻住全部会话 | 专用读任务 + 每请求超时 + 健康状态（§6） |
| MCP 列举拖垮启动 | 每次注册表重建对每个 server 串行 spawn 做 tools/list；一个不可达 server 让重建等 `timeout + 5 s`，daemon 启动被 CLI 的 8 s 就绪窗口杀掉 | 列举缓存 + 并行 + 列举预算 15 s + 5 s + 启动最多等 3 s 后回填（保留 v1 修复） |
| 失败列举 | 60 s 内不重试 | 保留，并加指数退避与健康状态 |
| 脚本头部被一行编码声明截断 | `# -*- coding: utf-8 -*-` 终止解析，内置 5 个 Python 脚本头部失效，全靠 index.json 兜底 | 头部解析跳过未知注释行（v1 已修，保留）并有夹具 |
| 脚本工具不隔离 | 成员脚本需要 `personas/` 执行权限才能跑；属主脚本无沙盒 | 脚本在 `SandboxPolicy` 内运行，按声明收紧（§5） |
| 包管理不签名、不沙盒 | `gqy pm`：`gqy-package.toml`、`lock.json`、上限 2,000 个文件 / 64 MiB；“只防君子” | 锁文件带内容哈希；能力声明与升级时的权限差异确认；签名为待定（§7、Q-18-1） |
| 技能 YAML 可被构造成内存炸弹 | frontmatter 限 4,096 个 YAML token；单文件 ≤ 256 KiB | 保留上限 |
| 伴侣功能散在内核 | 记账自有库、玄学、游戏查询、汇率、快递、地图、生图、表情包、语音独立二进制 | §8 映射到扩展形式 |

## 3 子系统钩子

### 3.1 契约

```rust
// 草案，以实现为准 —— trait 与下列类型定义在 gqy-core（00 §5 已定，01 §3）；引擎（L4）调用，gqy-memory / gqy-ext（L3）实现
pub trait SubsystemHooks: Send + Sync + 'static {
    fn id(&self) -> &'static str;                         // "memory"、"kb"…；排序与日志用

    /// 每个模型请求规划前调用（工具循环中的每个请求都会调用）。
    /// 只能返回“追加到尾部”的块；不能修改历史、system 段、工具面。
    fn before_request<'a>(&'a self, cx: &'a HookCx, req: &'a RequestView)
        -> BoxFuture<'a, Result<Vec<TailBlock>, HookError>> { Box::pin(async { Ok(vec![]) }) }

    /// 回合进入终态后调用（完成 / 失败 / 取消都会调用）。在后台执行，不阻塞下一回合准入。
    fn after_turn<'a>(&'a self, cx: &'a HookCx, turn: &'a TurnDigest)
        -> BoxFuture<'a, Result<(), HookError>> { Box::pin(async { Ok(()) }) }

    /// 压缩提交后调用，交给钩子被折叠条目的副本（05）。
    fn on_evict<'a>(&'a self, cx: &'a HookCx, span: &'a EvictedSpan)
        -> BoxFuture<'a, Result<(), HookError>> { Box::pin(async { Ok(()) }) }
}

pub struct TailBlock {
    pub trust: BlockTrust,        // Trusted → trusted tail（system 角色）；Untrusted → untrusted tail（user 角色）
    pub tag: &'static str,        // XML 外壳名，如 "associated-memories"；白名单登记
    pub body: String,             // 英文或原文引用；经 sanitize 与 redact_known_secrets
    pub once_per_turn: bool,      // true：同一回合只在第一个请求注入
}

pub struct HookCx {
    pub session: SessionId, pub run: RunId, pub turn_seq: u64,
    pub principal: Principal, pub venue: Arc<Venue>, pub persona: Arc<PersonaSnapshot>,
    pub cancel: CancellationToken, pub deadline: Instant,
    pub clock: Arc<dyn Clock>,
}
```

`HookCx` 不携带 store 句柄（`gqy-core` 不依赖 `gqy-store`）：子系统需要的存储句柄在组装处（`gqy-daemon`）注入到子系统自身，只访问自己的表 / 命名空间（10）。`RequestView` 是只读视图（含 `request_index`）：当前 user 原文（`Raw` 通道）、本回合已发生的工具调用摘要、上下文占用。它不包含 system 段与工具面字节，钩子无从修改。

### 3.2 字节契约

- 钩子输出**只能**成为尾部块。块由 `gqy-ledger` 以 `Channel::Context` 条目写入并化石化（04），之后逐字节回放；钩子不能要求删除或替换已注入的块。
- 注入顺序由 `(hook.id 字典序, 块返回顺序)` 决定，与钩子完成的先后无关——并发执行的钩子不引入非确定性。
- `tag` 必须在白名单登记（如 `associated-memories`、`kb-hits`）；未登记的 tag 视为实现错误，块被丢弃并记 `hook.invalid_block`。
- `once_per_turn = true` 的块（例如联想记忆，v1 行为）在工具循环后续请求中不再调用对应逻辑；钩子可以通过 `RequestView.request_index` 自己判断。
- 钩子失败、超时或返回空：**什么都不注入**。不注入同样是确定的——它只影响本回合的新增尾部，不影响已有前缀。
- 大小：单块 ≤ 2 KiB，单钩子单请求 ≤ 4 KiB，全部钩子单请求 ≤ 8 KiB；超出按块截断并记日志。

### 3.3 时限与失败

| 钩子 | 默认时限 | 上限 | 超时/失败 |
| --- | --- | --- | --- |
| `before_request` | 1.5 s（所有钩子并发，共享该时限） | 5 s | 跳过该钩子本次注入；事件 `hook.skipped{id, reason}`；不重试 |
| `after_turn` | 30 s | 300 s | 记日志；由钩子自己决定是否登记作业重试（03 作业） |
| `on_evict` | 10 s | 60 s | 记日志；压缩已提交，不回滚；钩子可在下次启动时按 05 的折叠记录补做 |

- `before_request` 的等待计入请求准备时间，出现在 19 的回合时间线中。
- 钩子内部的阻塞 IO 走 `gqy_core::blocking::run`（02 §2）；钩子不得创建 runtime。
- 钩子的产出若需要影响**之后**的回合（例如整理后的记忆），只能写入自己的存储，由之后的 `before_request` 读出——没有“后台写回上下文”的路径。reset 之后后台作业把旧结果写回自己存储的问题仍然存在，由 11 §9.2 的记忆代数守护处理。

### 3.4 注册

- 钩子在组装处（`gqy-daemon`，01 §3）按 persona 启用集构造并注册：persona 未启用记忆，就不构造记忆子系统（12）。
- 钩子集合随 persona 代际冻结；中途启用某子系统 = persona 代际切换。
- 第一版只有进程内 Rust 实现的钩子（记忆、知识库）；扩展包不能注册钩子（Q-18-3）。

## 4 技能（Skills）

### 4.1 目录格式

```text
<scope>/skills/<name>/
  SKILL.md          # 必需：YAML frontmatter + Markdown 正文
  <任意资源文件>     # 可选：模板、参考资料、脚本（脚本不会自动成为工具）
```

`SKILL.md` frontmatter 字段（与 v1 相同）：

| 字段 | 必需 | 约束 |
| --- | --- | --- |
| `name` | 是 | `^[a-z0-9][a-z0-9-]{0,63}$`，与目录名一致（它是路径边界） |
| `description` | 是 | ≤ 300 字符，进入索引 |
| `license`、`compatibility` | 否 | 原样保存 |
| `allowed-tools` | 否 | 只作提示；**不授予**任何权限 |
| `metadata` | 否 | 字符串映射 |

上限：`SKILL.md` ≤ 256 KiB，frontmatter ≤ 4,096 个 YAML token，单技能目录 ≤ 200 个文件 / 8 MiB。

### 4.2 作用域与覆盖

| 作用域 | 位置 | 信任 |
| --- | --- | --- |
| built-in | 编译进二进制 | 可信 |
| global | `<data>/extensions/skills/` | 用户安装，可信 |
| persona | `<data>/personas/<p>/skills/` | 可信 |
| workspace | `<workspace>/.gqy/skills/` | **不可信**（仓库内容，可能来自他人）；默认关闭（Q-18-4） |

同名覆盖优先级：persona > global > built-in。覆盖与冲突在 `gqy doctor` 列出。

### 4.3 索引与加载

- **索引在 system 段**：`<skills>` 块按 name 排序，每条 `<skill name="…">description</skill>`，总长 ≤ 6 KiB（超出时按 name 排序截断并在块尾写 `+N more; use load_skill with list=true`）。
- 索引在会话创建（或 persona 代际切换）时渲染一次并冻结；技能目录在会话中发生变化**不改**当前会话的 system 段。新增技能对当前会话的可见方式：`load_skill {list: true}` 的结果（尾部，不碰前缀）。
- `load_skill {name}`：Lazy 工具（07 §6），返回 `SKILL.md` 正文（剥离 frontmatter）以 tool result 进入尾部；资源文件用 `read skill:<name>/<path>` 读取（`skill:` 是只读存储域，登记在 07 §9.1 的存储域清单中）。
- 技能正文是提示文本，不是指令权限：它对模型可见，但不能改变工具面、档位或审批。

## 5 脚本工具

### 5.1 头部契约

脚本是单文件，放在 `<scope>/scripts/`。头部紧随 shebang 的注释块（`#` 或 `//` 开头），`键: 值` 形式；未知注释行跳过，第一个非空非注释行结束头部；只读前 32 KiB。

| 键（别名） | 必需 | 含义 |
| --- | --- | --- |
| `id` | 否（默认取文件名去扩展名） | 工具名为 `script_<id>` |
| `description` | 是 | 英文完整描述（中文 `描述` 用于 UI） |
| `summary` | 否 | ≤ 60 字符，stub 与目录用；缺省取 description 第一句截断 |
| `parameters` | 否 | 单行 JSON Schema；缺省为 `{"type":"object"}` |
| `argv` | 否 | `none`（默认，参数只经 stdin JSON）/ `flags`（额外展开为 `--key=value`） |
| `timeout` | 否 | 秒，默认 60，上限 600 |
| `trust` | 否 | 最低信任级 `owner` / `member` / `external`；**只能收紧**安装作用域的默认值 |
| `permission` | 否 | 能力声明：`read-only` / `workspace` / `network` / `full`（§9） |
| `platform` | 否 | `linux`、`macos` 等能力条件；不满足时不编译该工具（07 §5.1） |
| `group` | 否 | load_tools 分组 |
| `example` | 否 | stub 示例（07 §6） |
| `requires` | 否 | 需要先调用的工具（提示用） |

- 头部是脚本自带的真相源；v1 的 `index.json` 覆盖层不再保留（覆盖需求改为 persona 启用集中的禁用名单，12）。
- 头部解析结果进入 `ToolSource` 快照；目录扫描在后台进行（inotify / FSEvents 去抖 2 s，另每 5 分钟全量校验），不在回合路径上。

### 5.2 调用

- 参数经 07 §7 收口后以 JSON 写入 stdin（写入与读取并发，防止脚本不读 stdin 时死锁）；`argv=flags` 时同时展开为命令行参数。
- 在 08 的子进程环境中执行（环境白名单、私有临时目录、进程组），沙盒策略由 `permission` 声明决定（§9）。
- stdout 为结果文本；以 `GQY-IMAGE: <path> | <caption>` 开头的整行被摘出，转为图片内容（路径必须位于脚本的可写根或私有临时目录内，≤ 10 MiB，PNG/JPEG/WebP/GIF；否则该行替换为 `[image rejected: <reason>]`）。
- 退出码非 0：`error[upstream]: script_<id> exited with 2: <stderr 尾部 2,000 字符>`。
- 输出上限与截断同 07 §8。
- 效果类别：`permission: read-only` → `ReadOnly`（且沙盒以只读策略强制执行）；`network` → `Network`；其余 → `Exec`。

### 5.3 可信与平台

- 脚本的来源决定默认信任：built-in / global / persona 为 Owner 安装；Member 私有 persona 下的脚本只对该 Member 的会话编译。
- External 场所永远不编译 `Exec` 类脚本工具（08 §7）；`read-only` 且 `trust: external` 的脚本可以编译进外部场所，但仍在沙盒内运行、无宿主写权限。
- 平台不满足时不编译，`gqy doctor` 显示原因；脚本解释器缺失（例如 `#!/usr/bin/env python3` 而无 python3）同样显示为“缺失增强能力”，不静默失败（00 §1.6）。

## 6 MCP 客户端

### 6.1 范围

- 第一版只支持 **stdio 传输**（v1 同）。HTTP 传输见 Q-18-5。
- 支持 `initialize`、`tools/list`、`tools/call`、`notifications/tools/list_changed`；resources / prompts 暂不支持。

### 6.2 进程与 IO

- 每个 server 一个子进程（独立进程组），一个专用读任务按行读 stdout（单消息 ≤ 16 MiB，超出即判协议错误并重启），stderr 进 256 KiB 环形缓冲供 doctor 与日志。
- 请求表 `id → oneshot`，每个请求自带超时；读任务结束（EOF/崩溃）时所有待决请求以 `error[upstream]: mcp server <id> exited` 完成——v1 “read_line 无超时永久占住 worker”的故障在结构上不存在。
- 取消：回合取消时发送 `notifications/cancelled`，1 s 后不再等待该请求的响应。

### 6.3 时限

| 操作 | 默认 | 上限（02 §6） |
| --- | --- | --- |
| 进程启动到 `initialize` 响应 | 10 s | 60 s |
| `tools/list` | 15 s + 5 s 余量 | 60 s |
| `tools/call` | 60 s | 300 s |
| daemon 启动等待 MCP 就绪 | 3 s，之后后台回填 | — |

### 6.4 健康状态

```text
Starting ──initialize ok──▶ Ready ──调用超时/协议错误──▶ Degraded ──连续 3 次失败──▶ Restarting
    │                         ▲                            │                            │
    └──启动失败──▶ Failed ◀────┴──── 10 min 内重启 5 次 ◀────┴────── 退避 1 s→60 s ◀──────┘
```

- `Failed` 后不再自动重启，直到配置变化或用户执行 `gqy ext mcp restart <id>`；失败列举 60 s 内不重试（v1 值），之后按退避。
- 状态经 `ext.mcp_status` 事件与 `gqy doctor` 展示。

### 6.5 列举缓存与工具面稳定

MCP 与冻结工具面天然冲突：server 可能晚于会话就绪，也可能中途 `list_changed`。规则：

- 列举结果持久化在 `mcp_catalog` 表（10 §7.6），键为 `blake3(server 配置规范化 JSON)`（命令、参数、环境变量名，不含 secret 值），值为规范化后的工具清单与 `catalog_hash`。
- **工具面编译只读持久化目录**（07 §4.2 的来源快照），不等待 server 在线。因此：server 当前离线，会话工具面照样包含它的工具（stub）；调用时返回 `error[upstream]: mcp server github is unavailable (state=Restarting)`。
- 首次安装、从未成功列举的 server：会话创建时没有它的工具；列举成功后只影响之后的会话或代际切换。“先就绪后回填”回填的是目录，不是正在运行会话的工具面。
- `list_changed` 或重新列举得到不同 `catalog_hash`：更新目录，对现有会话记 `surface_drift`（07 §5.3），不改字节。
- 工具描述来自第三方，是**不可信文本**：进入工具面前去除控制字符、截断到 1,024 字符、schema 深度 ≤ 16 且 ≤ 16 KiB；超出的工具被排除并在 doctor 报告。

### 6.6 每服务器的信任与权限

```toml
# 草案
[[mcp.servers]]
id = "github"
command = "github-mcp-server"
args = ["stdio"]
env = { GITHUB_TOKEN = { secret = "github_token" } }   # 值来自密钥存储，不进日志与模型
min_trust = "owner"          # 低于此信任级的场所不编译
effect = "network"           # 默认效果类别：read_only | network | exec（默认 exec）
tool_effects = { get_issue = "read_only" }             # 逐工具覆盖，只影响审批，不影响沙盒
sandbox = "none"             # none | workspace；none 仅 Owner 可配置，doctor 警告
timeout_call_s = 60
```

- 默认效果 `exec`：第三方 server 能做什么无法验证，所以默认按最高后果审批。
- `approval_key` 为工具真名（08 §5.3）。
- `sandbox = "workspace"` 时 server 进程在 08 的 Landlock 策略下启动（写根 = 当前 daemon 默认工作区），许多 server 需要读家目录配置，因此默认 `none`，这个选择在 doctor 中显式展示（Q-18-6）。

## 7 扩展包

### 7.1 清单

扩展包是一个目录或 git 仓库，根上 `gqy-extension.toml`：

```toml
# 草案
[package]
name = "gqy-ext-divination"
version = "0.3.1"                 # semver
kind = "extension"                # extension | persona
description = "Tarot and I Ching helpers"
requires-gqy = ">=0.4, <0.6"
license = "MIT"

[provides]
skills = ["skills/tarot", "skills/iching"]
scripts = ["scripts/draw_card.py"]
mcp = []                          # 可包含 [[mcp.servers]] 片段，安装时需用户确认
personas = []

[capabilities]                    # 包内所有脚本 / MCP 的能力上限（§9）
fs = "none"                       # none | workspace | read-home
network = false
exec = ["python3"]                # 需要的解释器；用于 doctor 检查，不授予权限
platforms = ["linux", "macos"]
```

上限（沿用 v1）：≤ 2,000 个文件、≤ 64 MiB。

### 7.2 安装、锁文件、升级

- 命令：`gqy ext install <path|git-url[@rev]|tarball-url#sha256=…>`、`gqy ext list`、`gqy ext update [name]`、`gqy ext remove <name>`。v1 的 tap 索引（GitHub 仓库 `index.json`）作为后续功能，不在第一版。
- 安装流程：下载到 `<data>/extensions/.staging/` → 校验清单与上限 → 计算内容哈希（规范化文件树的 blake3：路径排序、仅内容与可执行位）→ **展示能力声明并请用户确认** → 原子移动到 `<data>/extensions/<name>/` → 写锁文件 → 来源在后台刷新目录。
- 锁文件 `<data>/extensions/gqy-extensions.lock`（TOML）：

```toml
[[package]]
name = "gqy-ext-divination"
version = "0.3.1"
source = "git+https://example.com/divination.git"
rev = "3f9c2a1…"                   # 解析后的完整提交号
content_hash = "blake3:9ad0…"
capabilities_hash = "blake3:17be…"
installed_at = "2026-09-28T14:05:00Z"
approved_capabilities = { fs = "none", network = false }
```

- 启动时校验：已安装目录的内容哈希与锁文件不符（被手工修改或篡改）→ 该包被禁用，doctor 报 `content_hash mismatch`，需要 `gqy ext verify --accept` 或重装。
- **升级**：拉取新版本 → 与锁文件比较能力声明；能力**扩大**（例如 `network: false → true`、新增 MCP server）必须再次确认，缩小或不变只显示 diff。升级 = 安装新版本到 staging，成功后原子替换，旧版本保留一个副本直到下次升级（可 `gqy ext rollback`）。
- 签名：见 Q-18-1。

### 7.3 扩展的数据

- 扩展**不能**直接写 `gqy.db`。需要持久数据的扩展（如记账）使用自己的目录 `<data>/extensions-data/<name>/`（10 §3；脚本以可写根的形式获得，§9）或由其 MCP server 自行管理。
- 这些数据不在 v2 的迁移纪律范围内，但备份（10）会一并打包该目录。

## 8 伴侣功能如何回归

依 00 §4 与已定决策“内核先行，伴侣后置”，下表是各 v1 功能在 v2 的扩展形态规划（施工在 P13/P14 之后，逐项由用户决定优先级）：

| v1 功能 | v2 形态 | 需要的能力 | 备注 |
| --- | --- | --- | --- |
| 语音（`gqy-voice`，sherpa-onnx ~30 MB） | 独立二进制，作为网关客户端（`gqy-client`）；落地前须先在 12 §6.2 登记 `VenueKind::Voice` | 麦克风、音频输出、本地模型 | 不是工具；是一个入口。依赖外置模型的问题同 D-05 |
| 播报 / TTS（MiniMax、小米 MiMo） | MCP server 或脚本工具 | network | 返回音频文件经 `artifact:` 呈现 |
| 记账（v1 自有库） | 扩展包：技能 + 脚本工具（或 MCP），数据在 `extensions-data/ledger/` | fs=workspace（其数据目录） | v1 数据由导入器迁入该目录（20） |
| 玄学（塔罗、易经等） | 技能 + read-only 脚本 | 无 | 最适合作为扩展包的示范 |
| 游戏查询、Arch 新闻 / AUR / ArchWiki、汇率、快递、地图、网页图片搜索 | 脚本工具或 MCP | network | `web_search` 同类，见 07 Q-07-1 |
| 生图 / 图像处理 | MCP 或脚本，`GQY-IMAGE` 回传 | network | 生图额度（v1 的 `IMAGE_GEN_LIMIT` task_local）改为扩展自身的计数 |
| 表情包 | 技能 + 知识库条目（`kb:`，11） | 无 | 投递幂等闸在连接器层（16） |
| 信件、闹钟、提醒 | 内核的持久化定时器与作业（03）+ 技能 | 无 | 定时器本身是内核能力，不是扩展 |
| GitHub bot 账号 | MCP server（如官方 github server） | network | 凭据走 MCP env secret |
| 聊天室、主动发起（private_initiative） | 内核场所能力（12、16）+ persona 配置 | — | 不属于扩展 |

扩展化后，内核不包含任何上述功能的代码；v1 数据的对应部分由导入器（20）写入扩展数据目录，扩展未安装时导入器只保存原始数据并提示。

## 9 扩展隔离与能力声明

所有扩展代码（脚本、MCP server）都作为子进程运行，**不在 daemon 进程内执行第三方代码**（没有动态库插件、没有嵌入式脚本引擎）。

能力声明 → `SandboxPolicy` 的映射：

| 声明 | 文件系统（Landlock / D-02） | 网络 | 效果类别 |
| --- | --- | --- | --- |
| `read-only` / `fs = "none"` | 只读系统目录 + 扩展自身目录（只读）+ 私有临时目录 | 不限制（诚实声明：无法强制） | ReadOnly |
| `workspace` | 上面 + 当前工作区读写 + 扩展数据目录读写 | 不限制 | Exec |
| `read-home` | 上面 + 家目录只读（保护路径除外，08 §4.1） | 不限制 | Exec |
| `network` | 同所配合的 fs 声明 | 不限制；声明仅用于审批与展示 | Network |
| `full` | 不加沙盒；仅 Owner 可批准，doctor 警告 | 不限制 | Exec |

- **网络声明当前无法强制**：Linux 沙盒不管网络（08 §6.2）。`network = false` 的含义是“扩展作者声称不需要网络”，内核据此把它的效果类别定为非 Network，但不阻止它联网。doctor 与安装确认界面都写明这一点。若 Seatbelt 后端落地（D-02），macOS 上可以真正强制，届时两平台行为差异也必须写明。
- 沙盒不可用时，要求沙盒的扩展工具按 08 §4 第 3 步处理（非 Owner 失败关闭；Owner 走无沙盒 + 审批路径，08 §4.1）；`full` 声明的扩展不套沙盒，按 Exec 审批（08 §4.1、§5.2）。
- 扩展的实际权限 = 声明 ∩ 场所上限 ∩ 会话档位 ∩ 审批，任何一层都不能被扩展自己放宽。

## 10 边界与失败模式

| 情形 | 行为 |
| --- | --- |
| 钩子 panic | 钩子在独立任务中运行，panic 转为 `HookError::Panicked`，按超时处理；连续 3 回合失败则本会话禁用该钩子并通知 UI |
| 钩子返回超长块 | 截断并记日志（§3.2） |
| 技能 frontmatter 非法 | 该技能不进索引，doctor 报行号与原因；不影响其他技能 |
| 脚本头部 `parameters` 非法 JSON | 该脚本不编译，doctor 报错；不回退为空 schema（避免模型随意传参） |
| MCP server 输出非 JSON 行 | 计数并丢弃（许多 server 在 stdout 打日志）；超过 100 行/分钟判 Degraded |
| MCP 工具名与内置重名 | 加前缀后不会重名；前缀后仍冲突按 07 §4.3 |
| 扩展包内容哈希不符 | 禁用该包（§7.2） |
| 扩展声明的解释器缺失 | 相关工具不编译，doctor 显示“缺失增强能力” |

## 11 测试与守护

- **钩子字节契约**：mock 供应商 + 一个每次返回不同内容的测试钩子，断言第 N 轮请求仍是第 N−1 轮的字节前缀延伸（04 门禁）；让钩子尝试（通过测试后门）修改 system 段时，类型上无法表达——编译期保证，另加一条 compile-fail 测试。
- **钩子确定性**：两个钩子以随机延迟完成，注入顺序恒为 id 字典序（100 次循环）。
- **钩子超时**：一个永不返回的 `before_request`，请求在 1.5 s 后照常发出且无该钩子块；去掉超时包装后测试挂住（由测试外层 10 s 超时判红）。
- **MCP 隔离**：一个读 stdin 后永不回复的假 server，会话 A 调用它时会话 B 完成 10 个回合（02 §10 隔离测试的 MCP 版本）；调用在 60 s（测试中配置为 1 s）后返回超时。
- **MCP 目录稳定**：server 离线时创建会话，工具面包含持久化目录中的 stub；server 返回不同目录后，现有会话 `surface_hash` 不变。
- **脚本头部**：夹具覆盖编码声明行、`//` 注释、中文键名、缺失 description、非法 parameters、超出 32 KiB。
- **GQY-IMAGE**：合法路径、工作区外路径、超大文件、非图片各一例。
- **扩展包**：篡改已安装文件后启动，包被禁用；升级扩大能力时未确认则安装中止且旧版本仍在。
- **不可信描述**：MCP 描述含控制字符、超长、深层 schema，分别被清洗、截断、排除。
