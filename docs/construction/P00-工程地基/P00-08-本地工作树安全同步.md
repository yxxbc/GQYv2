# P00-08 · 本地工作树安全同步

| 项 | 值 |

| 状态 | 待验收 |

| 规模 | S（≤1 天） |
| 涉及 crate / 目录 | `scripts/`、`scripts/tests/`、`CONTRIBUTING.md`、`docs/construction/` |

## 目标

提供一条在云端 main 合并后可运行的本地同步命令：先列出所有 worktree 相对 `origin/main` 的状态；用户显式传入 `--apply` 后，只更新干净且未发布的工作树。脏改动、已发布分支和真实冲突都不会被静默改写。

## 范围

- 做：默认 fetch + 状态报告；`--apply` 快进干净的 main、rebase 干净的本地分支；遇到冲突 abort 当前 rebase 并停止；用临时 bare remote 覆盖保护行为。
- 不做：后台定时同步、自动 push/force-push、自动解决冲突、删除 worktree 或分支、保证不同任务的重叠修改零冲突。

## 改动清单

| 文件 | 内容 |
| --- | --- |
| `scripts/sync-worktrees.sh` | 枚举 worktree、报告 ahead/behind 与脏状态；显式同步时仅快进/rebase 安全候选 |
| `scripts/tests/sync-worktrees.sh` | 临时 bare remote 集成测试，覆盖只读、干净、脏、已发布、同名远端、upstream 丢失和冲突路径 |
| `CONTRIBUTING.md` | 说明合并 main 后的运行命令与同步边界 |
| `CHANGELOG.md` | 记录新增本地维护工具 |
| `docs/construction/` | 登记本单及施工图 `plan-data` / `BASE` |

## 接口草案

```text
bash scripts/sync-worktrees.sh [--repo <仓库路径>]
bash scripts/sync-worktrees.sh --apply [--repo <仓库路径>]
```

不传 `--apply` 时只 fetch 和报告，不改本地分支或工作树文件；`--repo` 仅用于测试和排查，默认仓库从脚本路径定位。脚本只依赖 Bash、Git 和可访问的 `origin`，不需要 secrets，也不推送任何分支。

## 实施步骤

1. 实现 status-only 默认模式，并在真实本地 worktree 清单上人工核对分类。
2. 加入显式同步模式：只快进干净 main，rebase 干净且没有非 main upstream 的本地分支。
3. 遇到冲突时 abort 当前 rebase、报告并停止；在临时 bare remote 中验证不会丢改动或改写已发布分支。
4. 更新贡献说明、变更日志和施工图登记。

## 测试与守护

- `bash scripts/tests/sync-worktrees.sh`：默认模式不改 main 和 branch HEAD；`--apply` 快进 main 并 rebase 干净本地分支；脏、detached、有其他 upstream、存在同名远端分支或 upstream 已删除的工作树均跳过。
- 同一测试故意让分支与 main 修改同一行，断言命令非零退出、冲突分支 abort 后恢复原 HEAD 和干净状态。
- `bash -n scripts/sync-worktrees.sh` 与 `bash -n scripts/tests/sync-worktrees.sh`。

## 验收流程

1. 在仓库任一工作树运行 `bash scripts/tests/sync-worktrees.sh`，期望打印“全部样例通过”。
2. 先运行 `bash scripts/sync-worktrees.sh` 检查本地所有工作树；默认模式不得改动 branch HEAD。
3. 确认报告后运行 `bash scripts/sync-worktrees.sh --apply`；干净 main 应仅 fast-forward，干净本地分支应 rebase 到最新 `origin/main`。
4. 确认脏工作树、已发布/失去 upstream 的分支保持不变；若真实冲突，确认失败分支已 abort，其他先前成功同步的 worktree 不回滚。

## 完成判据

- [x] 默认报告与显式 `--apply` 分离，fetch 失败时不改工作树。
- [x] 脏、detached、非 main upstream、失去 upstream 的工作树不会被 rebase。
- [x] 冲突会中止并返回非零；不自动推送、force-push 或删除任何内容。
- [x] 临时 Git 测试覆盖可区分的安全与失败路径。
- [ ] 本地实仓报告由维护者核对，并在 PR 合入后按流程运行。

## 风险与回退

- rebase 仍可能遇到语义冲突；脚本只恢复冲突中的当前 worktree，不回滚此前已成功同步的 worktree。
- 已发布分支不会自动更新；维护者须在 PR 分支上单独决定是否 rebase 和使用 `--force-with-lease`。
- 回退本单时删除脚本、测试和贡献说明，不影响已有 Git 历史及任何 worktree 内容。
