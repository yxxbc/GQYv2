## 目标

把“错误”与“日志”这两条地基打出来：

1. **错误分类**：`gqy-core` 提供 `ErrorKind` 与分类接口，各 crate 的错误类型按它分类（01 §6：“每个库 crate 定义自己的 `Error`（thiserror），并实现 `gqy_core::ErrorKind` 分类”），供重试、HTTP 状态映射与日志字段使用。
2. **密钥容器**：`gqy-core` 提供 `Secret<T>`，`Debug`/`Display` 输出 `***`、不实现 `Serialize`（19 §3.5）。
3. **阻塞包装**：`gqy-core::blocking::run(label, f)`，统一计时、限流与 `blocking{label}` span（02 §2、19 §3.1）。
4. **日志初始化骨架**：`gqy-daemon` 提供 `logging::init` —— stderr 人读格式 + 文件 JSON 行（`daemon.YYYY-MM-DD.jsonl`、`requests.YYYY-MM-DD.jsonl` 两个目标文件）、非阻塞有界队列（容量 8192）与丢弃计数、单文件 256 MiB 滚动；`logging::purge_old_logs` 做 14 天保留清理。文件名里的本地日期用 `jiff` 计算（唯一时间库，tech-stack；00 §5）。

做完之后：后续任何 crate 都能用统一的错误分类与密钥容器；daemon 组装后日志同时可读（stderr）与可检索（JSONL），且写日志不会阻塞回合。

## 接口草案

草案，以实现为准。

```rust
// gqy-core/src/error.rs

/// 跨层的错误分类。重试决策、HTTP 状态映射与日志字段都从这里取值，
/// 不靠字符串穿透（00 §3）。
///
/// 分类值来自各设计文档引用的失败语义；后续施工单需要新类别时，
/// 先改设计文档再扩这个枚举。
#[non_exhaustive]
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum ErrorKind {
    /// 内部不变量被破坏（不应发生）。报错必须带期望与实际。
    Internal,
    /// 输入不合法（参数、配置、协议字段）。
    InvalidInput,
    /// 未找到（会话、文件、记录）。
    NotFound,
    /// 冲突（并发写、状态不允许）。
    Conflict,
    /// 暂时忙碌，可以稍后重试（队列满、锁被占）。
    Busy,
    /// 超时（连接、流空闲、总时长）。
    Timeout,
    /// 被取消。
    Cancelled,
    /// 权限不足（审批拒绝、沙盒拒绝）。
    PermissionDenied,
    /// 能力不可用（平台不支持、沙盒缺失）。
    Unavailable,
    /// 存储错误（SQLite、写队列）。
    Store,
    /// 供应商错误（HTTP 状态、流中断、协议异常），细分见 06。
    Provider,
}

/// 每个 crate 的错误类型实现它，向上层暴露分类。
///
/// 约定：`kind()` 必须是无副作用的纯查询；错误信息用
/// “期望 X，实际 Y”的写法（00 §3），不写猜测的原因。
pub trait Classified {
    fn kind(&self) -> ErrorKind;
}
```

```rust
// gqy-core/src/secret.rs

/// 不会泄漏到日志/调试输出里的密钥容器。
///
/// - `Debug` / `Display` 一律输出 `***`（19 §3.5）；
/// - 不实现 `Serialize`（写配置文件走专门路径）；
/// - 取值必须显式调用 `expose()`，便于搜索全部使用点。
pub struct Secret<T>(T);

impl<T> Secret<T> {
    pub fn new(value: T) -> Self;
    /// 显式取出明文。调用点越少越好。
    pub fn expose(&self) -> &T;
}

impl<T> std::fmt::Debug for Secret<T> { /* 输出 *** */ }
impl<T> std::fmt::Display for Secret<T> { /* 输出 *** */ }
```

```rust
// gqy-core/src/blocking.rs

/// 阻塞任务的统一入口：走 tokio blocking 池（默认上限 64，02 §2），
/// 统一打 `blocking{label}` span 并记录耗时。
///
/// 调用方约定：`label` 是稳定短标识（例如 "store.read"、"blob.hash"），
/// 不得含正文或密钥。
///
/// # Errors
/// 任务 panic 或 runtime 正在关闭时返回错误（不吞掉，不静默）。
pub async fn run<F, R>(label: &'static str, f: F) -> Result<R, BlockingError>
where
    F: FnOnce() -> R + Send + 'static,
    R: Send + 'static;

/// 包装层失败：任务 panic（含 panic 载荷摘要）或 runtime 关闭。
#[derive(Debug, thiserror::Error)]
pub enum BlockingError {
    #[error("blocking task `{label}` panicked: {payload}")]
    Panicked { label: &'static str, payload: String },
    #[error("blocking task `{label}` cancelled: runtime is shutting down")]
    Cancelled { label: &'static str },
}
```

```rust
// gqy-daemon/src/logging.rs

/// 日志初始化参数。调用方给出目录与级别；缺省值集中在本类型的 `Default`。
pub struct LoggingOptions {
    /// 日志目录（通常为 `<数据目录>/logs`）。`None` = 只输出 stderr。
    pub dir: Option<PathBuf>,
    /// 过滤级别，默认 `info`；语法同 `RUST_LOG`（19 §10 的 `GQY2_LOG` 接线在 P11-01）。
    pub filter: String,
    /// 单文件上限，默认 256 MiB（19 §3.2）。
    pub max_file_bytes: u64,
    /// 非阻塞队列容量，默认 8192（19 §3.2）。
    pub queue_capacity: usize,
}

/// 初始化全局日志。进程内只允许调用一次；返回的 guard 在退出前 Drop。
///
/// 输出：
/// - stderr：人读紧凑格式，级别 ≥ `info`；
/// - `<dir>/daemon.YYYY-MM-DD.jsonl`：JSON 行（全部 target）；
/// - `<dir>/requests.YYYY-MM-DD.jsonl`：只含 target `gqy::usage` 与 `gqy::context_rewrite`。
///
/// 写侧不阻塞：队列满时 `debug`/`trace` 直接丢弃并计数；
/// `info` 以上等待至多 50 ms 后丢弃并计数；丢弃计数每分钟输出一行 `warn`。
///
/// # Errors
/// 目录不可创建、同名 logger 已初始化时返回错误。
pub fn init(opts: &LoggingOptions) -> Result<LoggingGuard, LoggingInitError>;

/// 删除 `retention_days` 之前的日志文件（按文件名日期）。
/// 返回删除的文件数；daemon 启动时调用（P05-05 接线），每日零点由作业执行（P13-02）。
///
/// # Errors
/// 目录读取失败时返回错误；个别文件删除失败记入返回值的失败列表，不中断。
pub fn purge_old_logs(
    dir: &Path,
    retention_days: u32,
    now: SystemTime,
) -> Result<PurgeReport, std::io::Error>;
```

## 风险与回退

- **`gqy-core` 依赖 `tokio`/`tracing`**：01 §3 的“允许的外部重依赖”列没有列这两个（它列的是重依赖；tokio/tracing 是全项目标配），而 02 §2 明确 `gqy_core::blocking::run` 的存在、19 §3.1 的 span 层级也引用它——本单按 02/19 执行。若项目主人认为 01 §3 需要更新（把 tokio/tracing 写进 L0 的允许列表），先改设计文档再合入。
- **`tracing-subscriber` 的 JSON 字段名**：19 只规定了 daemon/requests 两类文件与“JSON 行”，字段名（`ts`/`level`/`target`/span 字段）以本单实现为准并写入模块文档；P02-07 的用量行字段以 19 §3.3 的样例为准（那是事件内容，不是 layer 格式）。
- **丢弃策略的测试**：非阻塞意味着“不断言耗时”，只用超时与计数断言，避免抖动（19 §4.1 确定性要求）。
- **回退**：revert 即可；日志与错误骨架不影响数据。

## 实施记录（2026-09-28 23:18:01，AI 助手 Cline 会话）

- **新增文件比「改动清单」多两个**：`crates/gqy-daemon/src/logging/purge.rs`（保留期清理独立成文件：职责单一，也让单提交体量合规）与 `crates/gqy-daemon/tests/logging_io.rs`（写侧行为用 pub API 做集成测试，避免单文件超过体量上限）。清单漏列属写单时的遗漏。
- **`SyncSender::send_timeout` 在 stable 不可用**（属 unstable 的 `std_internals`）：`info` 以上的「等待至多 50 ms」改为 `try_send` + 1 ms 轮询（`send_waiting`），语义等价（19 §3.2）。
- **`purge_old_logs` 的 `now` 参数用 `jiff::Timestamp`**（草案是 `SystemTime`）：与文件名日期的本地时区换算同源，避免两套时间表示。边界规则：文件日期与 `now` 的本地日期「相差超过 `retention_days` 天」才删；正好 14 天保留（有测试）。
- **丢弃计数的测试方式**：单测直接构造 `FileSink`（容量 1、无人消费）→ 「必然丢弃」可复现；靠真写线程把队列打满要看调度，会抖（集成式的那个尝试已删除）。
- **`clippy.toml` 加 `allow-invalid = true`**：路径可达性随各 crate 依赖面不同（部分 crate 不依赖 tokio/futures），clippy 会报「does not refer to a reachable function」的配置警告；按 clippy 提示静音，检查本身在可达的 crate 里照常生效。
- **依赖补充**：`gqy-daemon` 除清单列的四个外还需要 `serde_json`（JSON 行组装）与 `thiserror`（`LoggingInitError`）。`jiff` / `serde_json` 未进 `[workspace.dependencies]`（清单只列了 tokio / tracing / tracing-subscriber / thiserror 四个），版本集中化留待后续需要时统一。
- **stderr 的丢弃计数直接 `eprintln!`**：写线程再进日志层会递归，这是刻意的旁路（模块文档已写明）。每分钟的报告间隔未做专门测试（要等 60 秒），留待 P00-06 的 CI 观察。
