## 目标

把 P00-02/03/04 的检查接进 GitHub Actions：三平台矩阵（Linux、macOS 全量测试；Windows 编译 + 单元测试）、本地与 CI 用同一套 `scripts/ci-*.sh` 薄封装、报告构件上传与作业摘要；同时补齐 `cargo deny`（供应链）与 PR 模板的“修复前失败的证据”必填项。做完之后，任何 PR 都由 CI 自动验证，`AGENTS.md` 的“CI 全绿是验收的一部分”成立。

## 接口草案

草案，以实现为准。

```yaml
# .github/workflows/ci.yml（骨架）
name: CI
on:
  pull_request:
  push:
    branches: [main]
  workflow_dispatch:

permissions: {}

jobs:
  checks:            # ubuntu-latest   bash scripts/ci-checks.sh
  test-linux:        # ubuntu-latest   bash scripts/ci-test.sh
  test-macos:        # macos-latest    bash scripts/ci-test.sh
  test-windows:      # windows-latest  shell: bash; bash scripts/ci-test.sh --unit
  docs:              # ubuntu-latest   bash scripts/ci-docs.sh
  supply-chain:      # ubuntu-latest   cargo deny check
# 每个测试作业：
#   - 上传 target/gqy-test-report/ 为构件（保留 14 天）
#   - 把 report.md 追加到 $GITHUB_STEP_SUMMARY
#   - Swatinem/rust-cache 按 Cargo.lock 与工具链缓存（固定 SHA）
# 所有 uses: 固定到完整 commit SHA；checkout 设 persist-credentials: false
```

```sh
# scripts/ci-test.sh（骨架，与 19 §8.2 一致）
#!/usr/bin/env bash
set -euo pipefail
# 定位仓库根（脚本可被任意 cwd 调用）
# --unit：Windows 作业；先 cargo build --workspace，再 cargo xtask test --unit（--lib --bins）
```

```toml
# deny.toml（骨架；以 cargo deny 当前稳定版的 schema 为准）
[licenses]
# 允许清单按 LICENSE 与依赖实际协议确定；首版先只允许 MIT/Apache-2.0/BSD 系，
# 其余许可证出现即红，由维护者逐案决定
[bans]
multiple-versions = "warn"
[advisories]
# 默认阻断已知漏洞
```

## 测试与守护

- **脚本本地等价**：`bash -n scripts/ci-*.sh`；三个脚本本地运行结果与直接命令一致。
- **CI 自证**：在 PR 上 6 个作业全绿；故意引入一处失败（例如临时开一个 Windows 编译错误或不更新 changelog）验证对应作业变红，然后恢复。PR 描述贴两组链接。
- **zizmor 门禁**：新工作流必须通过既有 `workflow-security`（固定 SHA、最小权限、无 `pull_request_target`）。
- **计数基线**：windows 基线首次由 CI 实测回填；linux/macos 基线值与本地实测互为对照。
- **区分能力**：把 `ci-test.sh` 的退出码吞掉（`|| true`）→ PR 上 `test-*` 作业必须变红（验证脚本真的在把关）。

## 风险与回退

- **macOS runner 架构**：`macos-latest` 需按 19 §8.2 为 arm64；若 runner 标签变化，固定为具体镜像标签并记录在单里。
- **Linux runner 标签**：照 19 §8.2 先用 `ubuntu-latest`；若 P16-04 定义发布产物的 glibc 基线需要钉系统版本，改钉 `ubuntu-24.04`（参考 gqy 0-3 为 glibc 2.39 基线钉版本的选择），改动记录在本单。
- **平台专属编译错误**：只在某个平台上出现的写法（例如只在 Unix 分支需要的 `mut`）要等第一次推送 CI 才暴露；本地推之前可先用交叉 clippy 提前拦：`rustup target add x86_64-pc-windows-msvc aarch64-apple-darwin` 后 `cargo clippy --workspace --all-targets --target x86_64-pc-windows-msvc -- -D warnings`（只做类型检查、不链接；参考 gqy 3-3 第一次推 Windows 就红了的实测）。交叉 clippy 是本地便利，不是必需检查；CI 才是门槛。
- **Windows 上的 bash**：使用 GitHub runner 自带的 Git Bash（`shell: bash`）；不在 Windows 上跑非单元测试（沙盒、PTY 相关测试由 `cfg` 排除，后续阶段的单负责标注）。
- **CI 分钟数**：macOS 作业较贵；缓存生效后应保持分钟级增量；若明显变慢，先查缓存命中再考虑裁剪（不裁剪必需检查）。
- **`cargo deny` 版本与 schema**：以施工时固定版本的 schema 为准；配置错误会让 supply-chain 作业红，按错误修配置，不放宽检查。
- **回退**：revert `ci.yml` 与脚本即可回到“只有 pr-standards/security-review”的现状；不影响数据。
