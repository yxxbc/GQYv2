## 目标

设备身份从零成立：`gqy mesh init` 生成 Ed25519 身份（私钥 `<data>/mesh/device.key`，0600，不参与任何同步、不进导出），`DeviceId` = 身份公钥 SPKI 的 blake3 前 16 字节（32 hex）；TLS 证书由身份密钥自签发（10 年，重签不改信任）；第一台设备创建网格并写入成员账本创世条目（随机 128 bit mesh id、网格密码 ≥ 12 字符且不落盘）；mesh 默认关（`mesh.enabled = false`，D-03），开启后才监听；监听只接受成员账本中未撤销的公钥——自定义 rustls 校验器取对端证书 SPKI → `DeviceId` 查账本，不看证书链与主机名；握手交换六个版本维度（应用版本 / `gqy-mesh/1` 大版本 / API 小版本 / 账本格式 / `layout_version` / `encoding_version`），不兼容时报错写清期望与实际。

## 接口草案

草案，以实现为准。

```rust
pub struct DeviceIdentity { /* 私钥 + 证书缓存 */ }
impl DeviceIdentity {
    pub fn load_or_create(paths: &GqyPaths) -> Result<Self, MeshError>;
    pub fn device_id(&self) -> DeviceId;
    /// 自签证书；信任对象是公钥，重签（同密钥）不改 DeviceId（17 §5.1）。
    pub fn certified_key(&self, now: Timestamp) -> Result<CertifiedKey, MeshError>;
}
/// blake3(SPKI DER)[..16] → 32 hex；唯一派生实现（铁律 6）。
pub fn device_id_from_spki(spki_der: &[u8]) -> DeviceId;
/// 全链校验：哈希链接与作者签名；完整 Join/Revoke 规则在 P15-03 补齐。
pub fn verify_membership_chain(entries: &[MembershipEntry]) -> Result<(), ChainError>;
```

## 测试与守护

- **身份**：私钥文件 0600；同一密钥两次加载 `DeviceId` 相同、不同密钥不同；`DeviceId` 为 32 hex；导出物不含 `mesh/device.key`（去掉导出排除项，红）。
- **账本**：创世条目可校验；篡改任一字节或去掉签名 → 断链 / 拒收（红）。
- **TLS**：成员设备握手通过；非成员拒绝（去掉校验器查账本，红）；撤销条目存在后新握手失败（1 秒窗口的即时性在 P15-03 验收）。
- **默认关**：`mesh.enabled = false` 时无监听端口；改为默认开，红。
- **握手**：六维度不一致时报错含期望与实际（断言错误字段，不只断言失败）。
- 先红后绿对照（PR 贴输出）：去掉 SPKI 核对、把 `mesh.enabled` 默认改成 `true` 各一次。

## 风险与回退

- **重依赖未登记**（复核第 1 条）：`gqy-mesh` 的 rustls / rcgen / x509-parser 须先在 01 §3 登记，否则 `cargo xtask arch` 红。
- **换密钥等于换设备**：`DeviceId` 变化需要重新配对；重签证书不影响信任（17 §5.1）；恢复路径写进用户文档（17 §10）。
- **回退**：`mesh.enabled = false` 回到单机形态；`mesh_membership` 与 `mesh/` 文件保留（数据不丢）。
