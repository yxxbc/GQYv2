## 目标

设备 B 的「文件与命令」类能力可在设备 A 的会话里使用：远程工具以 `device_<name>.<tool>` 命名（stub 形态），会话创建时按当时委派表快照冻结进工具面；调用经 `POST /api/v1/mesh/invoke`（`origin` = A 的 device / session / principal / venue）到 B，B 以 `Venue{kind: Mesh{device: A}, trust: 来自 mesh_grants}` 构造 `ToolContext`、由 B 的权限引擎判定；A 只能收紧不能放宽；需要审批时 B 生成 `Question` 推送到 A 的会话流并在 B 本机同时展示，任一端回答、由 B 校验回答者身份；执行在 B 的沙盒内，结果返回 A；A 取消经 `/api/v1/mesh/invoke/{id}/cancel` 传播到 B，断网时 B 在 `invoke_timeout` 后自行终止；B 下线后工具面字节不变、调用返回 `device_offline`（英文短句）；B 的审计记录发起设备 / 会话 / principal / 参数哈希，A 的账本化石化记录调用与结果。

## 范围

- 做：
  - 远程工具 stub、命名与工具面快照（12 §7、07 §6 复用）。
  - invoke / cancel 路由；`origin` 结构；执行在 B、`ToolOutcome` 回 A。
  - `mesh.grants.<device>.<category>`（默认 `read_only`）接 B 的权限引擎（08 档位）；A 侧只能收紧。
  - 双端审批：B 的 `Question` → A 会话流（§5.3.2 形状）+ B 本机；回答者校验。
  - `invoke_timeout`、取消传播、断网终止；`device_offline` 语义。
  - 审计与 A 账本化石化；`gqy mesh grants`（最小 CLI）。
- 不做：
  - 模型接入委派（`ModelBinding::Mesh{device}`，Q-17-4 落地形态）、记忆 / 知识库 / 硬件类别的委派（17 §6.1 其余行；另单）。
  - 浏览器直连（17 §5.6，代理在 P15-07）；界面。

## 接口草案

草案，以实现为准。

```rust
pub struct InvokeRequest { pub capability: CapabilityCategory, pub tool: String, pub args: serde_json::Value, pub origin: InvokeOrigin }
pub struct InvokeOrigin { pub device: DeviceId, pub session: SessionId, pub principal: PrincipalId, pub venue: Venue }
pub enum InvokeOutcome { Ok(ToolOutcome), Denied { reason: String }, NeedsApproval(QuestionId), DeviceOffline, Timeout, Cancelled }
/// 工具面命名：`device_<name>.<tool>`；name 取成员账本设备名并规范化（唯一实现）。
pub fn mint_remote_tool_name(device_name: &str, tool: &str) -> Result<String, MeshError>;
/// B 侧裁决入口：以 Mesh{device: A} 场所与 mesh_grants 档位构造 ToolContext（08）。
pub async fn handle_invoke(mesh: &Mesh, req: InvokeRequest) -> InvokeOutcome;
```

## 实施步骤

1. 远程工具 stub 与命名；会话创建时快照（先写「B 下线后工具面字节不变」红用例）。
2. invoke 路由与 B 侧裁决接线；`mesh.grants` 默认 `read_only`（先写「A 请求 Exec、B 为 ReadOnly → 拒」红用例）。
3. 双端审批：B 生成 `Question` → A 会话流 + B 本机；回答者校验。
4. 取消传播、断网 `invoke_timeout`、`device_offline`。
5. 审计与 A 账本化石化；`cargo xtask check`；提交：`feat(mesh): 能力委派`。

## 测试与守护

- **裁决在 B**：A 请求 `Exec`、B 授权 `ReadOnly` → 拒绝；A 侧配置放宽无效（去掉 B 侧裁决，红）。
- **冻结**：会话创建后 B 下线 / 改名 → 工具面字节不变（比对 `surface_hash`）；调用返回 `device_offline`。
- **审批**：`Question` 同时出现在 A 会话流与 B 本机；回答者校验（第三方回答被拒，红）。
- **取消 / 超时**：取消传播到 B 的子进程终止（02 §6）；断网后 B 在 `invoke_timeout` 内自行终止（暂停时钟）。
- **审计**：B 的 `audit_log` 含 `origin.device` / session / principal / 参数哈希；A 账本有调用与结果（化石化）。
- 先红后绿对照（PR 贴输出）：去掉 B 侧裁决、去掉工具面快照各一次。

## 风险与回退

- **类别边界**：本单只做「文件与命令」；模型接入 / 记忆 / 知识库 / 硬件按 17 §6.1 另单，不顺手扩大。
- **B 端裸奔**：`mesh.grants` 默认 `read_only`，审批仍逐次进行；把默认改成可写，红。
- **回退**：清空 `mesh.grants` 或停 invoke 路由；A 账本已有条目保留。
