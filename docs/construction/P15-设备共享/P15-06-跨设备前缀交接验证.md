## 目标

产出验证工具与结论：同一应用版本的两台设备，B 从同步来的账本重建 `RequestPlan`，逐轮复算 `prefix_hash` 与 A 记录的比对，报告首个不一致位置；`layout_version` / `encoding_version` 不一致时显式走 `DeviceHandoff` 冷启动（日志 `context_rewrite reason=device_handoff`，不改写账本）；按供应商实测（Anthropic、OpenAI、DeepSeek）记录「相同前缀是否跨客户端共享缓存」与 TTL 窗口；全部结论写回 17 §8 与白皮书 §3.5。不实现主场迁移（Q-17-6）；不实现缓存感知路由。

## 实施步骤

1. 纯函数（先写「同输入两次结果相同」「篡改一字节 → 首个不一致位置正确」）。
2. 集成夹具：A 在 mock 供应商上跑 N 轮 → 同步到 B → B 重建比对（全轮一致）。
3. 版本维度：`layout_version` / `encoding_version` 不同 → 冷启动 + 日志断言。
4. 供应商实测（「需用户环境」）：Anthropic / OpenAI / DeepSeek 的缓存共享与 TTL 走访模板。
5. 结论写回 17 §8 / 白皮书 §3.5；`cargo xtask check`；提交：`test(mesh): 跨设备前缀交接验证`。

## 测试与守护

- **同版本**：N 轮 `prefix_hash` 全部一致（把逐轮比对降级为只比末轮，红）。
- **不一致定位**：篡改一字节 → `first_mismatch` 精确到 seq。
- **版本不同**：`layout_version` / `encoding_version` 任一不同 → 结果显式冷启动（`DeviceHandoff`）且有 `context_rewrite` 日志。
- **只读**：运行前后库文件与账本哈希不变（比对前后快照）。
- 先红后绿对照（PR 贴输出）：把逐轮比对降级为末轮比对一次。
