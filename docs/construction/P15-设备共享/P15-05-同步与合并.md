## 目标

同步只在用户确认后执行：`GET /api/v1/mesh/sync/heads` 取各会话 `(session, home_device, last_seq, last_prefix_hash, last_entry_hash)`；本机计算差异（新会话、延长、冲突、记忆条数等）展示计划，用户确认后分页拉取（500/页）、逐条校验哈希链、经 store 单写者应用；一方是另一方前缀则追加尾部；同 seq 内容哈希不同则本机保持原会话不变，把对方从最后公共 seq `p+1` 起的条目写成新会话（`session.forked{from_session, from_seq: p}`，标题标注来源设备）；同步不修改本机已有条目；进度记 `sync_cursors`、可断点续传；默认范围按 17 §7.1——凭据默认不同步（`mesh.sync.credentials = false`）、配置各设备独立、工作区文件非目标。

## 范围

- 做：
  - heads / diff / entries 三路由；`plan_from_heads` 纯函数与用户确认（未确认不拉取）。
  - 拉取方向（双向 / 只拉 / 只推）；逐条哈希链校验（断链中止该会话并报告 seq）。
  - 应用（追加 / 分叉）；不修改本机已有条目的守护；`session.forked` 事件。
  - `sync_cursors` 迁移列并入 10 §7.6（复核第 2 条）；断点续传。
  - 范围尾项：blob 按需、作业记录并集、记忆并集（墓碑不复发）；persona（询问：generation 较新者生效、另一份留历史版本）与知识库（文档级并集，同名不同内容保留两份并提示）。
  - `gqy mesh sync [--direction …] [--yes]`（复核第 5 条）。
- 不做：
  - 主场迁移（Q-17-6）；凭据同步（默认关）；工作区文件同步（非目标）；冲突内容的自动合并；界面（CLI 先落）。

## 接口草案

草案，以实现为准。

```rust
pub struct SessionHead { pub session: SessionId, pub home: DeviceId, pub last_seq: u64,
                         pub last_prefix_hash: Option<Hash>, pub last_entry_hash: Hash }
pub struct SyncPlan { pub new_sessions: u32, pub extended: u32, pub conflicts: u32,
                      pub memories: u32, pub direction: SyncDirection }
pub enum ApplyOutcome {
    Appended { session: SessionId, upto_seq: u64 },
    Forked { from_session: SessionId, from_seq: u64, new_session: SessionId },
    ChainBroken { session: SessionId, at_seq: u64 },
}
/// 纯函数：差异计划只依赖两侧 heads。
pub fn plan_from_heads(local: &[SessionHead], remote: &[SessionHead], direction: SyncDirection) -> SyncPlan;
```

## 测试与守护

- **并集**：前缀关系 → 追加且 `from_seq` 正确；同 seq 不同哈希 → 分叉、原会话保留（去掉分叉改成覆盖写，红）。
- **不改已有**：同步前后本机已有条目的哈希逐一比对（去掉保护，红）。
- **确认**：未确认不发起拉取（红用例）；计划数字与实际应用一致。
- **断链**：篡改一字节 → 该会话中止并报告首个断点 seq；其它会话继续。
- **墓碑**：遗忘的记忆并集后不复发（11 §9）。
- **续传**：应用中途杀进程，重启从 `applied_seq` 继续、不重复写入。
- 先红后绿对照（PR 贴输出）：把分叉改成覆盖、把确认改成默认执行各一次。
