## 目标

角色与降级成立：`mesh.role = auto / server / client` 按 17 §3.1 行为；server 对探测应答 `role` 与 `mesh_id`（复核第 3 条：`GET /api/v1/mesh/ping`，TXT 不扩字段）；client 启动与运行中以 2 秒超时探测服务器、连续 3 次失败后降级（探测间隔 30 秒）：UI 切到本机 host，状态条 “server offline — working locally”；主场在服务器上的会话在降级期只读（同步副本），继续时创建本机分叉（`session.forked`）；服务器恢复后提示用户切回并询问是否同步（用户决定，不自动）；降级 / 恢复记录日志并发 `notice`；浏览器与本机 UI 不直连 mesh——经本机网关代理远程请求（17 §5.6、复核第 8 条）。本单同时执行 **M5「多设备」** 全量验收并留档。

## 实施步骤

1. ping 应答与线上形态落 17（复核第 3 条）；`mesh status`。
2. 探测状态机（暂停时钟：2 秒超时 × 3 → 降级；恢复 → 提示）。
3. 服务器会话只读与继续即分叉（复用 P15-05 分叉器）；notice / 日志。
4. 本机代理（浏览器与 UI 经本机网关到服务器；远程会话事件一致）。
5. M5 验收执行与留档（施工图「每一步的图」）。
6. `cargo xtask check`；提交：`feat(mesh): 服务器角色、自动降级与 M5 验收`。

## 测试与守护

- **降级**：停服务器 → 3 次探测后降级（去掉连续计数，红）；恢复 → 提示且不自动切回 / 不自动同步（断言无自动动作）。
- **只读与分叉**：降级期在服务器会话上继续 → 产生本机分叉、服务器账本未被写；`from_seq` 正确。
- **角色**：`server` 应答含 `role` / `mesh_id`；`client` 优先连服务器；`auto` 本机 host 常驻。
- **代理**：远程请求经本机网关成功；事件流与直连服务器一致（view 对拍）。
- **notice**：降级 / 恢复各发一条 `notice`，日志含设备、状态与原因。
- 先红后绿对照（PR 贴输出）：去掉只读门、去掉「恢复不自动同步」各一次。

## 风险与回退

- **探测与用户操作竞态**：状态迁移集中在纯函数 + 单点驱动；探测与手动切换同一状态机（测试覆盖）。
- **同机双实例**：端口与数据目录必须不同（验收脚本给全套参数）；真机验收标注「需用户环境」。
- **回退**：`role = auto` 并手动连本机；停 mesh 监听不影响本机使用。
