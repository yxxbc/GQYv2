## 目标

新设备加入走 PAKE（口令 = 网格密码、不落盘；每 JoinRequest 5 次尝试、失败锁定 15 分钟；双方把各自 TLS 公钥指纹绑定进 PAKE 记录，中间人替换证书即失败；界面与 CLI 显示 4 个指纹词供肉眼核对）；成功后提交 `JoinRequest{device_id, pubkey, name, ver}`，由接收成员经 mesh 通道广播给全部成员，每台成员设备本机弹出「设备 N 请求加入」；全部成员签名 Approve 后写入 `Join` 条目（附全部签名）并分发账本；任一 Reject 作废、离线成员挂起、7 天过期（Q-17-1）；撤销：任一成员可撤销任一成员（含自己），撤销后 1 秒内被撤销设备的新 TLS 握手失败、已有连接被关闭；被撤销设备保留本机数据、降级独立使用；重新加入需重新配对。成员账本全链校验与分叉合并（`Revoke` 并集优先、`Join` 覆盖不足则挂起重征求）在本单落地。

## 接口草案

草案，以实现为准。

```rust
pub struct JoinRequest { pub device_id: DeviceId, pub pubkey: DevicePubKey, pub name: String, pub ver: String }
pub enum PairState {
    Awaiting { join: JoinRequest, approvals: BTreeSet<DeviceId>, rejections: BTreeSet<DeviceId>, expires_at: Timestamp },
    Approved, Rejected, Expired,
}
/// 纯函数：批准 / 拒绝 / 过期 / 全员到齐判定。
pub fn apply_answer(state: &PairState, from: DeviceId, answer: PairAnswer, now: Timestamp) -> PairTransition;
/// 撤销：写 Revoke 条目并让连接表在 1 秒宽限内关闭对端连接（复核第 6 条）。
pub async fn revoke(mesh: &Mesh, device: DeviceId, reason: &str) -> Result<MembershipEntry, MeshError>;
```

## 实施步骤

1. PAKE 评估结论写回 17 §5.3 并拍板（Q-17-5）；未拍板不选库。
2. PAKE 会话与指纹绑定、5 次尝试锁定（先写「中间人替换证书 → PAKE 失败」红用例）。
3. JoinRequest 往返与全员同意状态机（三设备夹具：拒绝 / 离线挂起 / 过期）。
4. 账本 `Join` / `Revoke` 校验与分叉并集。
5. 撤销即时生效（连接表 1 秒窗口关闭）；CLI 与 pending 展示。
6. `cargo xtask check`；提交：`feat(mesh): 全员同意配对与撤销`。

## 测试与守护

- **配对**：错误口令 5 次后锁定 15 分钟（暂停时钟）；PAKE 指纹绑定（去掉绑定，红）；口令正确且指纹一致才成功。
- **全员同意**：三设备网格——C 拒绝 → N 未加入；C 离线 → 请求挂起，C 上线批准后才加入；超 7 天 → 过期作废（时移时钟）。
- **账本校验**：伪造缺签名的 `Join`、非成员作者的 `Revoke`、断链全部被拒；分叉合并时 `Revoke` 取并集、`Join` 重新校验（去掉并集规则，红）。
- **撤销即时**：撤销后 1 秒内新握手失败 + 已有连接被关闭（去掉连接关闭，红）。
- **边界**：同一 `DeviceId` 重复 Join 拒绝；撤销自己 = 离开网格（本机数据保留）。
- 先红后绿对照（PR 贴输出）：去掉 PAKE 指纹绑定、去掉「1 秒内关连接」各一次。
