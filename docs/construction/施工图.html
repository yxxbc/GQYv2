        P00-01workspace 骨架

        已完成

        仓库从“只有文档”变成“可以照施工总纲施工的骨架”：一个 Cargo workspace + 17 个库 crate 空壳，外加一份把整个文件树定死的设计文档。

        • 根 Cargo.toml（resolver 3、edition 2024、rust-version 1.98.1、unsafe_code = "deny"）、rust-toolchain.toml（钉 1.98.1）、.gitattributes（全仓 LF）、Cargo.lock 入库、.gitignore 增 /target/。
        • crates/ 下 17 个空壳：每个只有 Cargo.toml 与写明职责、设计出处与分层规则的 src/lib.rs；名单与 01 §3 一一对应。
        • 新设计文档 21 代码文件树规范：目录、模块、测试与夹具位置、命名与守护方式（00 阅读顺序表与 01 §2 已接入）。

        验收：cargo build / test / fmt --check / clippy -D warnings 在 rustc 1.98.1 上全绿；cargo metadata 恰好 17 个 gqy-* 包、edition 全为 2024。提交：PR #6（docs(designs) 21 号文档 + feat(workspace) 骨架）。

        P00-02xtask 与分层/静态规则门禁

        已完成

        仓库有了第一道机器门禁：cargo xtask arch 会挡住接错方向的依赖、层表外的包与被禁的代码模式。

        • 新 crate xtask（库 + 二进制）与 .cargo/config.toml 的 cargo xtask 别名；退出码统一 0 / 1 / 2。
        • 层序门禁：直接解析 docs/designs/01-总体架构.md §3 的表格（不另存副本）并与 cargo metadata --no-deps 比对——unknown-package、layer-order、entry-layer、heavy-dep、daemon-assembly、connector-sdk-deps 六类规则。
        • 静态规则：task_local!、可变全局 static、#[instrument] 缺 skip_all；扫描 crates/*/src/**/*.rs 与 apps/**/*.rs（xtask/ 自身跳过）。
        • 测试 18 例（层序 8 + 扫描 10），含「关掉规则 → 对应测试必红」的区分能力对照。

        验收：cargo xtask arch 退 0（层表 21 条目标 / 18 个包 / 17 个文件）；手工红绿三组（接错方向、task_local!、图纸删行）都退 1。提交：PR #15。

        P00-08本地工作树安全同步

        已完成

        云端 main 合并后，可以先盘点所有 worktree，再显式更新安全候选；脏工作区和已发布分支不会被脚本改写。

        • scripts/sync-worktrees.sh 默认只 fetch 并报告 ahead/behind、脏状态及跳过原因。
        • --apply 只快进干净 main、rebase 干净且未发布的本地分支；冲突时 abort 当前 rebase 并停止，不推送或删除 worktree。
        • 临时 bare remote 测试覆盖只读模式、干净/脏/detached worktree、已发布和失去 upstream 的分支，以及冲突恢复。

        验收：bash scripts/tests/sync-worktrees.sh 与两份脚本的 bash -n 全部通过；PR 标题/changelog 检查通过；合入后运行默认报告模式，确认只报告、不改动分支。cargo xtask plan 在当前 xtask 中尚不存在，plan-data 另用 JSON 解析校验。提交：PR #18（1918151）。

        P00-03体积门禁与 clippy 规则

        已完成

        任何新代码在提交前都会被同一套门禁拦一遍：cargo xtask check 一条命令跑完格式、静态检查、文档、层序与体积；cargo xtask size 守住文件体积三档。

        • workspace lints 全量（19 §6.1 第 2 项）：missing_docs + clippy 11 条（unwrap_used、expect_used、panic、indexing_slicing、let_underscore_must_use、unused_result_ok、await_holding_lock、large_futures、missing_errors_doc、missing_panics_doc、disallowed_methods）；clippy.toml 4 条禁止调用（Runtime::new / block_on / unbounded_channel，带 reason）。测试代码用 #![cfg_attr(test, allow(...))] 样板放开，非测试代码仍 deny。
        • cargo xtask size：.rs/.ts/.css 的 800（警告）/ 1500（需说明拆分计划）/ 2000（红）三档（00 §3），报告按严重度排序、有红退 1；扫描跳过隐藏目录（含 .worktrees/）、target/、node_modules/。
        • cargo xtask check：注册表式组装 fmt / clippy / doc / arch / size，支持 --fast（提交前快检）、--docs（含 --document-private-items 的 rustdoc 断链）、--no-docs 与默认全集（19 §6.1、§8.3）。
        • fixture 三组共 20 例：gates_size（10，四档边界/排序/扫描范围）、gates_clippy（8，读真实 lints 配置 + 吞错误两条 + 测试放宽）、gates_docs（2，公开与私有断链的正反对照）。

        验收：cargo xtask check（默认 / --fast / --docs / --no-docs）全绿；cargo test --workspace 46 例通过；红绿对照五组（非测试 unwrap 探针、size 三档、公开/私有断链、删真实配置的 unwrap_used、把 Fail 档改成 Explain）见 PR 输出。提交：PR #28。
