## 目标

三件事落地：会话切换器（`Ctrl+S` 或 `/sessions`）、作业面板（`Ctrl+J` 或 `/jobs`）、子代理只读视图。列表数据来自既有 GET 路由 + 全局流，不用轮询；切换会话取消旧订阅、拉新 `view`、按 `as_of_seq` 续传，旧会话里在跑的回合不受影响；子会话复用同一套转录组件（`read_only = true`）。

## 范围

- 做：
  - 会话切换器（§8.1）：列表来自 `GET /sessions`，按最近活动排序，显示标题、场所图标、是否有活动运行、未答问题数；输入即过滤（标题子串；拼音首字母第一版不做，Q-14-5）；切换时取消旧会话 SSE 订阅 → 拉 `GET /sessions/{id}/view` → 重建转录状态。
  - 全局流 `session.updated` 更新列表徽标（无轮询）；`session.expired` 从列表移除。
  - 作业面板（§8.2）：宽度 ≥100 列时右侧抽屉（含 P10 README 复核清单要并入的自适应布局），窄终端为全屏浮层；数据来自 `GET /jobs` + `job.*`；每行：类型（后台命令、定时器、子代理后台）、状态、耗时、所属会话；选中显示输出尾部（`GET /jobs/{id}/output?after=&limit=`，跟随模式同 §5.3）；`c` 取消（带确认对话框）。
  - 子代理（§8.3）：`subagent.started` 在父转录产生 `SubagentLink` 条目；Enter 打开子会话只读视图（同套转录组件、`read_only = true`、输入框隐藏）；标题栏面包屑；Esc 返回父视图并恢复滚动锚点。
  - `/sessions`、`/jobs` 两个客户端命令登记进 P09-04 的 `CommandTable`。
- 不做：
  - 会话创建、归档、删除入口（走 CLI 与 Web；TUI 若要 `/new` 先改 14）；作业详情页（超出输出尾部）；会话过滤的拼音增强（Q-14-5）；多路同时观察（只订阅当前会话流 + 全局流）。

## 实施步骤

1. 会话列表与过滤纯函数（先红：空串 / 大小写 / 子串边界）。
2. 切换生命周期：取消旧订阅、拉 `view`、`as_of_seq` 续传（先红：旧订阅未取消）。
3. 作业面板、输出尾部跟随与取消确认。
4. 子代理只读视图与面包屑返回（锚点恢复）。
5. 全局流徽标；`/sessions`、`/jobs` 登记。
6. `cargo xtask check --fast`、`cargo test -p gqy-tui`；提交：`feat(tui): 会话、作业与子代理面板`。

## 测试与守护

- **切换不打断运行**：mock 双会话，A 有活动运行 → 切到 B → A 的运行继续，A 的事件仍在其流上；旧订阅未取消（测试红）。
- **续传口径**：切换 / `resync` 后以 `as_of_seq` 重连（13 §6.4；改回从头拉全量，测试红）。
- **过滤纯函数**：空串返回全部、大小写不敏感、子串命中位置稳定。
- **作业取消**：确认后才 `POST /jobs/{id}/cancel`；取消后行状态随 `job.finished` 更新。
- **输出跟随**：分页游标推进、尾部锁定、断流提示。
- **子代理只读**：`read_only` 下按键不产生提交请求；Esc 返回父视图锚点恢复（与 P09-02 锚点联测；锚点丢失，测试红）。
- **快照**：会话切换器（80×24）与作业抽屉（120×40）（完整矩阵在 P09-07）。
- 先红后绿对照（PR 贴输出）：把切换改成复用旧订阅、把只读标志去掉各一次。

- **回退**：面板相关模块可整体 revert；命令表退回到 P09-04 的首版命令集。
