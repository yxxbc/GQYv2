## 测试与守护

- **快照可读 diff**：故意改一个字符 → 输出按行 diff（去掉 diff 渲染，测试红）。
- **帧路径完整**：`tui/frame` 覆盖 `update + compute + draw`；把 compute 改成结果缓存（帧行为失真）时，“每帧恰好一次 compute”计数断言红。
- **M2 脚本**：mock 全绿；把审批步骤删掉（mock 直接允许）→ 脚本断言 `permission.decided` 缺失，红；把压缩一步跳过 → `context.compact_finished` 缺失，红。
- **沙盒断言**：Linux 用例标 `needs:linux-landlock` 并在 Linux CI 跑；macOS 断言「无沙盒」路径与卡片醒目标注字串（08 §6.4）。
- **字节前缀**：M2 长会话上第 N 轮请求是第 N−1 轮的字节前缀延伸（计划内改写除外，需 `context_rewrite` 行）。
- **配置**：`tui.*` 缺省时用默认值；越界值（如 `max_fps`）回默认并警告一行（测试断言日志）。
- **门禁口径**：新用例同步更新测试计数基线（19 §6.1 第 11 项）；新增依赖过 `cargo deny`（第 14 项）。
- 先红后绿对照（PR 贴输出）：把快照 diff 变成只输出“不一致”、把沙盒断言删掉各一次。

## 验收流程

```sh
cargo xtask test --filter tui          # 含快照；基准只报告，不作失败条件
cargo xtask check --fast
tests/e2e/m2.sh                        # mock 全绿；Linux 与 macOS 各按本平台断言
GQY2_TUI_FRAME_TRACE=1 gqy             # 手检（用户环境）：帧时间日志；10k 条目会话内存与滚动
# 需用户环境：真实供应商跑一轮「读 → 改 → 跑命令 → 审批 → 压缩」（标 needs:real-provider）
```

## 风险与回退

- **headless 驱动与真终端的差异**：交互手感保留手工清单（需用户环境），CI 以 `TestBackend` + mock 为主。
- **平台断言**：Landlock 断言只在 Linux 有效；macOS 用例断言“无沙盒 + 审批”路径，用 `needs:` 标签与跳过口径（19 §4.1）——不许跳过后算通过。
- **回退**：本单只加测试、脚本与配置读取；revert 后 TUI 功能不受影响，M2 验收退回人工清单。
