## 实施步骤

（L 单：每一步都能单独编译通过。）

1. 删 `NoToolsSeam`、接 `Dispatcher`（先写「工具失败不升级为运行失败」的会红断言，03 §12）。
2. 分组执行与按序落账（同一事务、配对完整）；`length` 零执行复验。

6. `cargo xtask check --fast`、`cargo xtask test`、`cargo test -p gqy-engine -p gqy-tools`；提交：`feat(engine): 工具循环接线与形状夹具`。

## 测试与守护

- **端到端（mock 供应商）**：一次响应给「两个 read + 一个 write + 一个 read」→ 组 `[R,R],[W],[R]`；结果按请求顺序落账；账本配对完整；去掉按序落账必红。
- **失败不连坐**：组内一个调用失败，兄弟继续；运行不失败（03 §12）。
- **`length` 截断**：有工具调用 → 零执行 + 合成结果（复用 P04-04 的用例接真分发）。
- **未知工具与 stub hint**：模型调用不存在/未加载的名字 → 各自文案。
- **截断与回取**：写入期截断的 `out:` 引用在引擎链路里可回取。
- **夹具**：变异一个描述字符 → 夹具红并指出工具名（测试内自动做变异，07 §12.1）；`refresh` 必须带 `--reason`。
- **门禁 13**：往描述里塞 CJK 的违规 fixture → 扫描红。
- 先红后绿对照（PR 贴输出）：删 `parallel_safe` 判定、把结果按完成顺序落账各一次。
