## 目标

一条工具调用有唯一入口：`Dispatcher::prepare` 完成查面、解析、收口、校验与评估（07 §7.1 步骤 1–6），`execute` 与分组完成执行路径（步骤 7–9）。做完之后：模型把 `start_line` 写成 `"1"` 会被按 schema 还原且留下 `Coercion` 记录；原始参数字节原样进入 `Raw` 通道；输出只在写入时截断一次、标记模板全仓唯一；错误文本统一为 `error[<kind>]: … expected … got …`。

## 范围

- 做：
  - 管线步骤 1–6 与 8–9：查面（含最近 3 个真名）、解析、收口、校验、`assess`、权限接缝；invoke 与 `resume` 由 `execute` 驱动（步骤 7）。
  - 收口全表照 07 §7.2（含 `items: string` 的单字符串还原；Q-07-5 按推荐先行）、`Coercion{path, from, to}` 记录、未知字段处理、enum 唯一大小写不敏感匹配还原。
  - 原始参数字节（含非法 JSON 的半截字符串）以 `RawArgs` 随结果交给账本的 `Raw` 通道调用点，永不净化（07 §7.2 末条）。
  - 未知工具：`error[unknown_tool]` + 最接近的 3 个真名（编辑距离）；stub 被直接调用且参数不合 schema 时附 `hint: call load_tools …`（模板归 P06-07，本单留出注入口）。
  - 截断（07 §8、05 §10）：`HeadTail` 与 `SelfBounded`、固定标记模板、Unicode 安全切片、全文进 blob 并登记 `out:` 引用；捕获侧 8 MiB 硬上限由 P06-05 执行，本单只消费。
  - 分组（03 §6.2）：从左到右切最大连续组；`ReadOnly`/`Presentation` 且 `parallel_safe = true` 才可并行，组内上限 `engine.tool_parallelism`（默认 8）；`Writes`/`Exec`/`Network` 各自成屏障；组内需要审批的调用由引擎逐个提问（接 P07-02），本单只保证分组与顺序。
  - 权限接缝：`PermissionGate` trait 与仅测试的 `TestAllowAllGate`（命名与文档标注；PR 描述声明不是发布形态）；P07-01 换成 08 §4 的纯函数，P07-02 接 `Ask` 流程。
  - `xtask arch` 规则：`gqy-tools` 之外禁止调用 `Tool::invoke`（07 §12.3 末条）。
- 不做：
  - 具体内置工具（P06-03 起）、stub 与 `load_tools` 的提示文本（P06-07）。
  - 真正的判定与审批（P07-01/P07-02）；引擎接线（P06-08）。
  - 四条入口（主回合、子回合、作业唤醒、斜杠命令）的一致性集成矩阵：先钉主回合路径，其余入口随 P13 落地（记 README 遗留）。

## 接口草案

草案，以实现为准。

```rust
// gqy-tools/src/dispatch.rs（照 07 §7.1；步骤 6 的决策来自注入的 gate）
pub struct Dispatcher { /* 注册表代际、配置快照、Clock、BlobWriter */ }
pub enum Prepared {
    Ready(PreparedCall),
    Ask(AskRequest),                                   // 过渡：P07-02 换成 08 §5.1 的 QuestionSpec（字段只增）
    Deny { layer: LayerRef, rule: RuleId, message: String },
}
pub struct AskRequest { pub summary: String, pub session_key_preview: Option<String> }
pub struct PreparedCall { pub call: CallId, pub name: String, pub args: Args,
    pub assessment: Assessment, pub coerced: Vec<Coercion>, pub raw: RawArgs }

impl Dispatcher {
    pub fn prepare(&self, ctx: &ToolContext, call: &ToolCall) -> Result<Prepared, ToolError>;
    pub async fn execute(&self, ctx: &ToolContext, p: PreparedCall) -> ToolOutcome;
}
/// 03 §6.2 的分组：纯函数，输入规范顺序，输出按组、组内保序。
pub fn group(calls: &[PreparedCall], parallelism: usize) -> Vec<Vec<PreparedCall>>;

// gqy-tools/src/truncate.rs（标记模板只此一份，05 §10 引用它）
pub fn truncate_for_ledger(text: &str, policy: OutputPolicy, out_ref: Option<&CallId>)
    -> (String, Truncation);
```

## 测试与守护

- **收口表驱动**：07 §7.2 每一行还原与不还原各一例（`"12"`→12、`"12.5"`→报错、`"true"`→true、`"yes"`→报错、`items: string` 单串→单元素数组），并断言 `Coercion` 记录与原始字节。
- **原始字节**：非法 JSON 的半截字符串原样出现在 `Raw`；去掉保存这一步必红。
- **未知工具**：报出名字与 3 个真名；空工具面只报名字不猜。
- **截断**：100,000 字符输出 → 头尾长度、`[… N chars truncated; full output: out:… ]` 模板字节、blob 可回取；`SelfBounded` 不再二次截断；多字节边界安全。
- **分组**：`R,R,W,R` → `[R,R],[W],[R]`；`parallel_safe = false` 的只读工具单独成组；`Writes/Exec/Network` 互相不并组。
- **唯一入口**：把收口挪出 `prepare` 的变异实验在评审中说明；arch 规则的违规 fixture 去掉规则即失效。
- 先红后绿对照（PR 贴输出）：去掉 `items: string` 还原、去掉分组里的 `parallel_safe` 判定各一次。
