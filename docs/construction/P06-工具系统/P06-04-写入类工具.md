## 目标

写入路径只有一条：`write`、`edit`、`apply_patch` 都归结为 `PatchOp` 序列，共用同一套预检与「临时文件 + fsync + rename」原子写入；`edit` 的冲突、`apply_patch` 的多文件回滚、`trash` 的系统回收站都跑通。做完之后，模型改文件不会留半成品，删除不落进「直接 unlink」。

## 范围

- 做：
  - `patch.rs`：`PatchOp`（`Add`/`Update`/`Delete`）、v1 文本格式解析、单一域限制、≤ 256 KiB / ≤ 64 文件、预检（上下文匹配、目标存在性）与原子应用（整单失败回滚，保留 `.gqy-bak` 直到补丁完成）。
  - `write`：整体写入、≤ 1 MiB、父目录不存在时创建、覆盖时报告原大小。
  - `edit`：`old_string` → `new_string` 精确替换；非唯一匹配且未设 `replace_all` 时报匹配次数；预检到写入之间文件哈希变化 → `error[conflict]`。
  - `apply_patch`：07 §9.2 文本格式接入；`Delete` 走回收站。
  - `trash`：单次 ≤ 64 个路径；经 `gqy-sys` 的系统回收站后端（`HostCap::Trash`，缺失时该工具不进工具面）；后端不可用（无桌面回收站规范、跨设备卷）时 `error[unsupported]` 并说明原因，**不退化为删除**。
  - `footprint`（reads / writes）随结果上报（07 §3.3，供 05 §7.2 的压缩足迹）。
  - 拒绝目标（保护名单）归 P07-03；本单把判定点接好：`assess` 产出目标，`Delete` 预检与 `trash` 调用 `danger::refuse_trash_target(...)`（本单为空表，文件与函数签名固定）。
- 不做：
  - 回合级文件变更 journal 与 `/undo`（00 §5 的「统一补丁与撤销」待并入 07，见 README 开工前复核第 3 条）。
  - 危险删除名单与命令侧规则（P07-03）；沙盒（P07-05/P07-06）。
  - `artifact:` 域写入与产物索引表（随 P12/P13 的提供者）。

## 接口草案

草案，以实现为准。

```rust
// gqy-tools/src/patch.rs（照 07 §9.2）
pub enum PatchOp { Add { path: String, content: String },
                   Update { path: String, hunks: Vec<Hunk>, move_to: Option<String> },
                   Delete { path: String } }
pub fn parse_v1(text: &str) -> Result<Vec<PatchOp>, ToolError>;
pub async fn apply_checked(ctx: &ToolContext, ops: &[PatchOp]) -> Result<ApplyReport, ToolError>;

// gqy-sys/src/trash.rs
pub fn capability() -> HostCapState;                        // Trash: Available | Missing
pub fn trash(paths: &[PathBuf]) -> Result<(), TrashError>;  // 失败即报错，不 fallback 删除

// gqy-tools/src/danger.rs（本单仅签名与空表；名单与规则归 P07-03）
pub fn refuse_trash_target(target: &ResolvedPath, cfg: &ConfigSnapshot) -> Option<RefuseReason>;
```

## 实施步骤

（L 单：每一步都能单独编译通过。）

1. `patch.rs`：解析 + 预检 + 原子应用（先写「中途失败要回滚」的会红断言，再实现）。
2. `write` / `edit` / `apply_patch` 接 `patch.rs`（写入路径只有一条）。
3. `gqy-sys` 回收站后端与能力探测；`trash` 工具（含不可用时的 `unsupported`）。
4. `danger::refuse_trash_target` 调用点（空表）+ `footprint` 上报。
5. `cargo xtask check --fast`、`cargo test -p gqy-tools -p gqy-sys`；提交：`feat(tools): 写入类工具与统一补丁`。

## 测试与守护

- **原子性**：预检不过 → 一个字节都不写；应用中途注入失败 → 已替换文件回滚（比对哈希）、`.gqy-bak` 被清理。
- **`write`**：≤ 1 MiB 边界；父目录创建；覆盖报告原大小。
- **`edit`**：唯一匹配替换；3 次匹配报次数与建议；`replace_all`；预检后换哈希 → `error[conflict]`。
- **`apply_patch`**：≤ 256 KiB / ≤ 64 文件边界；跨域补丁拒绝；`Delete` 走回收站（测试后端计数）。
- **`trash`**：`HostCap::Trash = Missing` 时不登记该工具（对 `compile_surface` 的断言）；后端报错 → `error[unsupported]`，测试后端断言未调用删除。
- **写入路径唯一**：把 `write` 改成直接 `fs::write` 的变异实验在评审中说明（应红）。
- 先红后绿对照（PR 贴输出）：去掉回滚、把 `Delete` 改成直接删除各一次。
