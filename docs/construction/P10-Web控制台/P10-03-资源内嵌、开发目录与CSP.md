## 目标

网关按需内嵌前端产物并整体加安全头：`rust-embed` 嵌入 `apps/web-console/dist/`；`build.rs` 只检查、不构建（release CI 用 `GQY2_REQUIRE_WEB=1`，缺产物编译失败；其它情况嵌占位页 + warning）；`GQY2_WEB_DIR` 开发覆盖照四条约束判定（失败即拒绝并打印错误，daemon 继续用内嵌资源）；所有 Web 响应带 15 §8 的安全头。做完之后，浏览器从 `/` 打开控制台（当前为占位骨架），改一行 CSS 无需重编。

## 范围

- 做：
  - `gqy-gateway` 静态资源路由：`web.enabled = true` 时提供 `dist/` 内容；关闭后静态资源不可达而 API 仍在（15 §12）。
  - `ETag`（内容 blake3）与 `Cache-Control`：`index.html` 为 `no-cache`；带哈希文件名的资源为 `immutable, max-age=31536000`（15 §7.1）。
  - `build.rs`：`dist/manifest.json` 存在且源树哈希与当前源一致 → 正常嵌入；否则 release CI 下编译失败（提示 `cargo xtask web build`），其它情况嵌入内置占位页（“Web console not built”）并输出 `cargo:warning`。
  - `GQY2_WEB_DIR`（§7.2 四条约束，全部由代码判定、失败即拒绝）：只认环境变量；只在 debug 构建生效（release 忽略并警告）；绝对路径、存在、是目录、含 `index.html`；不得位于数据目录（`GqyPaths::root`）之内、不得位于任何已登记工作区根之内（启动后新建工作区包含该目录时立即失效并记警告）。生效时启动日志与 `/info.features` 标 `web_dir_override`。
  - 安全头中间件（15 §8 全表）：CSP（无 `'unsafe-inline'`）、`X-Content-Type-Options`、`Referrer-Policy`、`Cross-Origin-Opener-Policy`、`Cross-Origin-Resource-Policy`、`Permissions-Policy`；静态与 API 响应都带。
  - `web.enabled` 默认值进 `gqy-config`（完整 schema / 热加载归 P11-01）。
- 不做：
  - 前端页面本身（P10-04 起）、桌面宿主（P16）、TLS 与局域网（P05-12 已有）、`GQY2_REQUIRE_WEB` 在 release CI 的接线（P16-05）。

## 实施步骤

（L 单：每一步都能单独编译通过。）

1. `build.rs` 检查与占位页；`GQY2_REQUIRE_WEB` 失败路径。
2. 静态路由与 ETag / Cache-Control。
3. 安全头中间件与逐条断言。
4. 开发目录四条约束、失效复查与 `/info.features` 标注。
5. `web.enabled` 与失败模式（拒绝覆盖、缺产物）。
6. `cargo xtask check --fast`、`cargo test -p gqy-gateway -p gqy-config`；提交：`feat(web): 资源内嵌、开发目录与安全头`。

## 测试与守护

- **构建期**：无 `dist/` 时 debug 嵌入占位页（断言占位文本 + warning）；`GQY2_REQUIRE_WEB=1` 且无 `dist/` 时 `cargo check -p gqy-gateway` 失败（CI 步骤；去掉环境变量分支，测试红）。
- **缓存头**：`index.html` 是 `no-cache`；带哈希资源 immutable；同内容 ETag 稳定，改一字节 ETag 变化（去掉 ETag 计算，测试红）。
- **安全头**：逐条断言 §8 头出现在静态与 API 响应；CSP 串不含 `'unsafe-inline'`（删一条头，测试红）。
- **开发目录**：四条约束各自的拒绝用例（工作区内路径、数据目录内、相对路径、release 构建）；新增工作区包含该目录 → 覆盖立即失效并告警；生效时 `/info.features` 含 `web_dir_override`（去掉工作区复查，测试红）。
- **`web.enabled=false`**：静态 404、API 正常且带安全头。
- 先红后绿对照（PR 贴输出）：去掉 ETag、去掉工作区判定各一次。

## 验收流程

```sh
cargo test -p gqy-gateway -p gqy-config
GQY2_REQUIRE_WEB=1 cargo check -p gqy-gateway   # 有 dist：绿；移走 dist 复跑：红（release CI 口径）
GQY2_WEB_DIR=/tmp/gqy-web cargo run -p apps/gqy -- daemon run   # debug 手检：覆盖生效 + features 标注
curl -sI http://127.0.0.1:8310/ | grep -i 'content-security-policy\|etag\|cache-control'
```

## 风险与回退

- **build.rs 的判定与 xtask 的源树哈希**（README 复核清单第 3 条）：同一算法先行写进 15，再实现；两处实现不一致会让开发构建误判。
- **TOCTOU**：`GQY2_WEB_DIR` 校验后目录可能被替换；按设计为运行期复查（新建工作区包含即失效），不追求文件系统级锁定。
- **回退**：`web/` 与 `build.rs` 是新文件；revert 后网关无静态资源，API 不受影响。
