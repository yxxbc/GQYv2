## 目标

`cargo xtask gen-ts` 把 `gqy-protocol` 的 TS 派生生成到 `apps/web-console/src/core/generated/`：每类型一个文件 + `index.ts` barrel，文件头标注“生成文件，勿手改”；生成物入库，CI 用 `--check` 防漂移（不一致即红，不自动改写）。覆盖 DTO、事件信封与事件体、`ApiError`、`CommandSpec`、`QuestionView` / `Answer` 等 13 §10 列出的形状。

## 范围

- 做：
  - `gqy-protocol` 的 `ts` feature（`ts-rs` 派生；可选依赖，不影响非前端构建）。
  - `xtask gen-ts [--check]`：默认输出到 `apps/web-console/src/core/generated/`；`--check` 生成到临时目录与入库内容逐字节比对，不一致 → 红并列出差异文件（不写盘）。
  - 生成物：每类型一文件 + `index.ts`；文件头“生成文件，勿手改——来源 `gqy-protocol`，`cargo xtask gen-ts`”。
  - 事件：`EventEnvelope` 与事件体联合；枚举的 `Unknown` 兜底变体随 Rust 侧派生（13 §10 规则 3）。
  - CI 接线：`gen-ts --check` 进 `cargo xtask web check`（19 §6.1 第 10 / 12 项）。
- 不做：
  - 分层检查器与同名校验（P10-04）、设置页对 `ConfigSchema` 的使用（P10-06）、协议夹具本身（P05-01 已有）。

## 接口草案

草案，以实现为准。

```rust
// xtask/src/web/gen_ts.rs
pub struct GenOutcome { pub written: Vec<PathBuf>, pub unchanged: usize, pub removed: usize }
pub fn generate(out: &Path) -> Result<GenOutcome, GenError>;
pub fn check(out: &Path) -> Result<(), GenError>;   // 与入库比对；差异文件列表进错误
```

## 实施步骤

1. `ts` feature 与派生（先写「改一个字段后 `--check` 变红」的会红用例）。
2. 生成器 + barrel + 文件头。
3. 覆盖清单核对（13 §10 列出的形状都有生成物）。
4. CI 接线；`cargo xtask web check` 汇总。
5. `cargo xtask check --fast`、`cargo test -p xtask -p gqy-protocol`；提交：`feat(protocol): TS 类型生成`。

## 测试与守护

- **`--check` 区分能力**：给任一 DTO 加字段、重新生成之前跑 `--check` → 红并列出文件（把 `--check` 改成自动改写，测试红）。
- **覆盖清单**：断言 `ApiError`、`EventEnvelope`、`QuestionView`、`Answer`、`CommandSpec`、`CommandOutcome` 都在生成物中（清单写死在测试里；漏一型即红）。
- **不手改**：每个生成物以文件头标记开头；生成物与 `gen-ts` 输出逐字节一致（手工改一个字符，测试红）。
- **夹具联动**：类型变更时协议夹具不动 → `--check` 红，提示同步更新夹具与协议版本（13 §10 规则 5）。
- 先红后绿对照（PR 贴输出）：去掉 `Unknown` 兜底、删一个字段各一次。

## 风险与回退

- **`serde_json::Value` / 泛型的 TS 表达**：`data` 一类字段的生成形状如实记录；必要时在 13 §10 加一行备注，不手写第二份类型。
- **生成物噪声**：barrel 与文件命名保持稳定，避免每次生成无关 diff。
- **回退**：删 `ts` feature 与生成目录，web 代码退回 P10-01 的占位入口。
