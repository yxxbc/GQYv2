## 目标

对话视图可用并成为 M3 的核心：`state/` 的归约器与 resync 状态机、`core/markdown` 的消毒渲染、SSE 流式（seq 去重、容忍空洞）、提交与取消、抽屉审批回答；与 TUI 用同一组夹具验证归约一致。做完之后，浏览器里可以完成「登录 → 发送 → 流式 → 审批 → 取消 → 断线 resync」整条链路。

## 范围

- 做：
  - `state/sessionStore.ts`、`state/eventReducer.ts`（唯一归约点）、`state/resync.ts`（13 §6.4：`resync_required` → 拉 `view` → 以 `as_of_seq` 重连；60 秒内至多 3 次；超出显示手动重连按钮）。
  - `core/api/sse.ts`：`Last-Event-ID`、`seq ≤ 本地最大` 去重、seq 空洞容忍；同源只开“当前会话流 + 全局流”两条；多标签共享流第一版不做（Q-15-4）。
  - `core/markdown/`：构建 DOM 节点，不拼 HTML 字符串；链接 `rel="noopener noreferrer"`、协议只允许 `http` / `https` / `mailto`；图片只允许同源 blob；模型输出永不直接进 `innerHTML`。
  - `features/chat/`：转录渲染（虚拟滚动）、提交（`POST /sessions/{id}/turns` 的 202 `Admission` 展示，含 `Queued` 位置）、流式 delta、`assistant.message` 校准、工具条目（可展开、空输出 “no output”）、`run.failed` 显示 message / code / request_id；取消按钮（`POST /runs/{run}/cancel`）。
  - `features/approvals/`：抽屉（与 P09-05 同一形状）渲染 `QuestionView` 与回答；`question.answered`（他人）收起。
  - 斜杠命令：补全来自 `GET /commands`；服务端命令执行与 `CommandOutcome` 按去向渲染。
  - 断线横幅与 `daemon.stopping` 提示；`run.failed` / `stream.resync_required` / cookie 过期（401 → 回配对）三类边界行为照 15 §11。
- 不做：
  - 设置页（P10-06）、浏览器断言（P10-07）、多标签共享流（Q-15-4）、桌面能力分支（P16）。

## 测试与守护

- **归约一致（与 TUI 同夹具）**：夹具驱动 reducer → 期望 JSON；TUI 侧同组夹具已在 P09-02 进 CI，两侧结果不一致即红（把 reducer 改成另写一份语义，测试红）。
- **resync**：`lagged` / `purged` / `too_far` 三因各一用例；预算 3 次后停止自动重连并出现手动按钮（去掉预算，测试红——v1 有 resync 死循环前科）。
- **seq 去重与空洞**：乱序 / 重复 / 空洞序列下最终状态正确（13 §6.4）。
- **消毒**：`<script>`、`onerror=`、`javascript:` 链接、外部图片 URL 全部不执行 / 不加载（全局标志；监听器缺失则红）。
- **流式校准**：丢掉 delta 后 `assistant.message` 抵达视图仍完整。
- **审批回答**：payload 形状与 `Dismiss` 语义与 P09-05 相同（同夹具）。
- **错误显示**：`run.failed` 的 message / code / request_id 三字段可见。
- 先红后绿对照（PR 贴输出）：去掉 seq 去重、去掉链接协议白名单各一次。
