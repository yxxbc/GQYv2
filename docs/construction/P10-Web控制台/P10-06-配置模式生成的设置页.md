## 目标

设置页由 schema 生成：按 `group` 分页、按 `ty` 选控件、**没有逐字段代码**；默认值只在 schema（来源 `gqy-config`）；secret 只显示“已设置 / 未设置”；保存走 `PATCH /config` + `If-Match: revision`，409 时显示差异让用户重试。做完之后，加一个配置字段 = 只改 Rust 字段表，前端零改动。

## 范围

- 做：
  - `features/settings/`：`GET /config/schema` 拉取与按 `group` 分页；字段渲染器（`ty` → `widgets/fields/*` 的最小集：Bool / Int / Float / Str / Enum / Duration / List / Map）；`restart_required` 徽标；`label_key` / `help_key` 走 i18n。
  - 恢复默认：读 `schema.default`；前端代码不出现任何默认值字面量（规则：`features/settings/` 下禁数值字面量，除 0 / 1——本单把规则补进 P10-04 的检查器）。
  - secret：只显示状态，修改走 `PUT /config/secrets/{path}`（只写、响应不回显）。
  - 保存：`PATCH /config` + `If-Match: revision`；409 → “配置已被其他端修改” + 差异视图与重试（13 §5.7）。
  - 依赖 P11-01 的完整字段表与 schema 端点；未落地前按已落地字段联调（范围写进 PR，字段表就绪后刷新验收）。
- 不做：
  - 热加载语义与保存单写者（P11-01 的引擎侧）、密钥后端（P11-02）、TUI 的 `/config` 菜单（P11）、设置页的浏览器断言（P10-07）。

## 实施步骤

1. schema 拉取与按 `group` 分页（先写「未知 ty 显式报错」的会红用例）。
2. `ty` → 控件查表；form 状态与改动集收集。
3. 保存与 `If-Match`、409 差异流程。
4. secret 状态与写入路径。
5. 数值字面量规则与自查样例。
6. `cargo xtask check --fast`、`cargo xtask web check`；提交：`feat(web): 由 schema 生成的设置页`。

## 测试与守护

- **零逐字段代码**：`features/settings/` 下 grep 字段 path 字面量 → 红（把某个字段硬编码进去，测试红）。
- **数值字面量规则**：样例报红（除 0 / 1；去掉规则，样例测试红）。
- **未知 ty 显式失败**：schema 出现未支持类型 → 页面显示错误条目而不是静默丢字段（失败关闭）。
- **409 流程**：显示他人修改、保留本地编辑、重试后成功；`If-Match` 缺失的保存请求不存在（唯一保存出口）。
- **secret**：响应中不含明文（夹具断言）；修改走 `PUT /config/secrets/{path}`。
- **默认值唯一来源**：改 fixture 的 `default` → 恢复默认的取值随之变化（把默认值写进前端常量，测试红）。
- **字段完整性**：每个 schema 字段在渲染输入 / 输出中恰好一次（浏览器断言在 P10-07）。
- 先红后绿对照（PR 贴输出）：把某个字段渲染写成硬编码、去掉 `If-Match` 各一次。
