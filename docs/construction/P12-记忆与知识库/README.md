# P12 · 记忆与知识库

> 状态：【规划】。本阶段把 11 号设计落成 `gqy-memory`：记忆表与可见性、写入与召回工具、关键词检索、联想注入、整理作业与遗忘、聊后复盘、知识库与 `kb:` 域、reset 语义与记忆代数。记忆是**模型之外的连续性**：召回只追加在回合尾部并化石化，不破坏前缀契约；删除只来自用户的显式操作（铁律 9）。
> 创建：AI 助手（Cline 会话），2026-09-28。改动本文件时，按根 `AGENTS.md` 规矩 7 更新这一行：写清谁改的、什么时候改的。

## 阶段目标

（与施工图 `plan-data` 同文）记忆表、写入/召回工具、关键词检索、整理作业、遗忘、聊后复盘、知识库、reset 语义。做完之后：

- 记忆可见性由代码判定：`public` / `principal` / `privileged` 写进 SQL 谓词；群聊即使发送者是 owner 也只读 `public` + 本人 `principal`；写入可见性按场所收窄，模型改不动；
- 写入即可召回：jieba + fst 倒排与记忆写入在同一写作业提交；BM25 + RRF 走通用路径（第一版只有关键词一路）；同一状态、同一查询输出字节完全相同；
- 联想注入只追加在 user 原文之后的不可信尾部并化石化；同一回合多个请求复用同一字节；召回登记、强度提升与短期续期在 `after_turn` 后台完成；
- 记忆自己长出内容并走完生命周期：`after_turn` 日记 → 整理器提炼 `fact` / `long_term` / `correction` → 强度衰减与遗忘（显式找回可恢复）；全是持久化作业（退避、重启不丢、耗尽进 `dead` 并发 `work.dead`）；
- 聊后复盘不改 system：结果在下一个用户回合以可信尾部追加一次（Q-11-1）；
- 知识库与记忆分开：`kb:` 是登记在 07 §9.1 的存储域；`manual` 域只读、扫描 60 s、`kb-index` 节在会话创建时冻结；
- reset 收敛为四个命令 + `gqy data wipe`：代数守护让后台作业不会“复活”已删除的记忆；物理删除、二次确认、`wipe` 前自动备份。
