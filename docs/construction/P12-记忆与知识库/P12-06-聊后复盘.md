## 目标

聊后复盘以“尾部追加一次”的方式回归：Owner 交互场所的回合完成后，会话闲置满 `review_idle_seconds`（默认 900，下限 300，0 关闭）入队一次 `memory.review` 工作项（不提交回合）；辅助角色 `review` 回看最近 12 个回合的 `Channel::Raw` 与最近 5 条 correction，产出不超过 3 条英文“下次注意什么”写入 `session_reviews`；下一个用户回合的第一个请求由 `before_request` 以**可信尾部**追加一次 `<self-review source="post-chat review">`，追加后回填 `delivered_entry_seq`。做完之后：复盘不再是前缀改写点（v1 的 system 末尾做法被替换）；复盘执行前出现新回合则放弃；`<self-review>` 只出现一次。

## 范围

- 做：
  - 计划与重排：Owner 交互场所（`Tui` / `Web` / `Desktop` / `Cli` 交互模式）终态后写入或更新一个 `timers` 行（`action = 'work'`、`catch_up = 'skip'`）；新回合覆盖旧计时，避免堆积。
  - 作业：`work_items.kind = 'memory.review'`，携带当时的 `last_turn_seq`；执行前与写回前都检查会话最新 `turn_seq`，有更新则放弃（新回合会重新安排）。
  - 请求：角色 `review`、档位 standard；输入 = 最近 `lookback_turns`（默认 12）个回合的 `Channel::Raw` 全文与最近 5 条 correction；输出不超过 `max_notes`（默认 3）条英文短句；解析失败按失败处理（复用 P12-05 的退避与取证）。
  - 写入 `session_reviews`：`session_id`、`last_turn_seq`、`notes_json`（WriteOnce）、`created_at`；`delivered_entry_seq` 留空待投递。
  - 投递：`before_request`（回合第一个请求）读取未投递的复盘，按 `review_id` 升序、每回合至多投递一条，以可信尾部块追加：

    ```text
    <self-review source="post-chat review">
    - Confirm the target distro before giving package commands.
    </self-review>
    ```

    追加后回填 `delivered_entry_seq`，之后随账本化石化回放（重启不重复）。
  - 配置：`[memory].review.idle_seconds`（默认 900，0 或 300–86400）、`review.lookback_turns`、`review.max_notes` 落进 `gqy-config`（11 §11）。
- 不做：
  - 整理 / 衰减（P12-05）；reset 与代数变更（P12-08）；复盘内容的二次整理（不在设计里）；`review` 模型的档位映射本身（06 已有）；TUI 的复盘展示样式（遗留）。

## 接口草案

草案，以实现为准。

```rust
/// 计时与重排：同一会话同时只有一个待触发计时。
pub fn schedule_review(timer: &TimerRepo, session: &SessionId, turn_seq: u64, cfg: &MemoryConfig)
    -> Result<(), MemoryError>;

/// 执行：检查 latest_turn_seq 与作业携带一致才发请求；不等 → Abandoned。
pub enum ReviewOutcome { Written { notes: u8 }, Abandoned { reason: &'static str }, Failed { retry_at: Timestamp } }

/// 投递：返回一个可信尾部块（system 角色），投递后回填 delivered_entry_seq。
pub async fn deliver_pending(store: &Store, session: &SessionId) -> Result<Option<TailBlock>, MemoryError>;
```

## 实施步骤

1. 计时与重排（先写「0 关闭」「新回合覆盖」用例）。
2. 作业执行：`last_turn_seq` 两次检查与放弃路径。
3. 辅助请求与 `session_reviews` 写入。
4. 投递与回填；联测前缀门禁（不改前缀）。
5. `cargo xtask check`、`cargo test -p gqy-memory`；提交：`feat(memory): 聊后复盘走尾部一次`。

## 测试与守护

- **复盘不改前缀**：复盘写入后，下一轮请求是上一轮请求的字节前缀延伸（04 门禁），且 `<self-review>` 只出现一次；按 v1 做法把复盘放进 system，红。
- **复盘放弃**：作业执行前插入新回合 → 不写 `session_reviews`（去掉检查，红）。
- **只投一次**：同一复盘重启 daemon 后不再追加（依赖 `delivered_entry_seq`，不靠内存）；去掉回填，红。
- **闲置与关闭**：`idle_seconds = 0` 不安排；低于 300 的配置被 `validate()` 拒收。
- **场所过滤**：非 Owner 场所与 Internal 回合不安排复盘。
- 先红后绿对照（PR 贴输出）：把复盘块改放 system 一次、去掉 `delivered_entry_seq` 回填一次。
