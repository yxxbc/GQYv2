## 目标

账本给出**那一刻要发的全部内容**：`plan(view, stable, tails, params, hints) -> RequestPlan`。区段顺序（`[S]` 恒定、`[A]` 追加、`[E]` 本回合新增）、运行时尾巴模板与"每逻辑回合一条"、辅助请求的隔离链——全部是纯函数、确定性输出。做完之后，P03-03 只需要把它的"待冻结"部分落库。

## 范围

- 做：
  - `plan()`：输入 = 纪元视图（P03-01）、`StableSection`（工具面 + system 文本；P03-04 产出）、尾巴输入（不可信/可信块、运行时尾巴是否生成）、`SamplingParams`、`CacheHints`、`expect_parent`；输出 `RequestPlan`（04 §4.5 字段照抄）。
    - **[E] 顺序**：user 原文 → 不可信尾巴 → 可信尾巴 → 运行时尾巴（04 §4.1；运行时在 user **之后**——v1 教训）。
    - **运行时尾巴**：模板 `<runtime now="…" cwd="…"/>`（分钟粒度；注入值，渲染函数不读时钟）；**每个逻辑回合一条**，只在回合第一次请求前生成（由入参 `is_first_request_of_turn` 控制；工具循环的后续请求传入 `RuntimeTail::AlreadyPresent` 一类语义），模板字节有夹具。
    - **尾巴块**：本单接收**已渲染的块文本**（记忆外壳在 P12、感知在 P11）；块与条目的对应关系写入 `[E]`；同一块在两次 plan 中字节相同（冻结注入的前半：值由调用方冻结一次，本层不重算）。
    - `CacheHints`：`session_key = f(SessionId)`（稳定字符串；辅助请求为 `None`）、`prev_request_end`（上次请求覆盖的最后条目）。
    - `entry_range`/`epoch`/`request_seq`/`purpose` 填装；`SamplingParams` 从 `ModelBinding` 与会话设置取（纪元内不变是 04 §12.1 第 1 条的前提）。
  - 辅助请求隔离（04 §11）：独立构造函数 `plan_aux()`——不带会话缓存标识、不读写会话账本（接口上不接收 `LedgerView`）、`epoch = 0`、`parent_prefix = None`。
  - 渲染函数禁则（04 §7）：签名只接收条目与冻结快照；`cargo xtask arch` 的 IO 依赖规则（P03-01 已加）覆盖。
- 不做：
  - 压缩/撤销引发的纪元切换与 `Checkpoint` 生成（05、P08）；`CompactFork` 的 fork 规划（P08）。
  - persona 代际（Q-12-2 拍板后、P11）。
  - 写库与冻结事务（P03-03）；链计算（P03-05）。
  - 工具面**构造**（P06）；本单接收 `StableSection`。

## 接口草案

草案，以实现为准。

```rust
// gqy-ledger/src/plan.rs
pub struct TailInputs {
    pub untrusted: Vec<BlockRef>,      // 已渲染块（昵称、群历史、联想记忆…）
    pub trusted: Vec<BlockRef>,        // principal 摘要、感知值、审核结果…
    pub runtime: RuntimeTailPlan,      // Generate { now_minute, cwd } | AlreadyPresent | None
}
pub enum RuntimeTailPlan { Generate { now_minute: i64, cwd: String }, AlreadyPresent, None }

/// 纯函数：给定不变量输入，输出逐字节确定的计划。
pub fn plan(
    view: &LedgerView, stable: &StableSection, tails: &TailInputs,
    params: &SamplingParams, hints: &CacheHints, budget_hint: (),
) -> Result<RequestPlan, PlanError>;

pub fn plan_aux(view: &AuxView, stable: &StableSection, params: &SamplingParams) -> Result<RequestPlan, PlanError>;
```

## 实施步骤

1. 先写运行时尾巴模板夹具与"每回合一条"的顺序测试（先红）。
2. `plan()` 的顺序装配：`[S]` + `[A]`（视图顺序原样）+ `[E]`（user → 不可信 → 可信 → 运行时）。
3. `CacheHints` 派生与 `entry_range` 填装；`plan_aux` 的隔离断言（无 session key、无视图输入）。
4. 确定性测试：同输入两次相同；打乱内部集合构造顺序相同；条目顺序与 `seq` 一致。
5. `cargo xtask check --fast`、`cargo test -p gqy-ledger`；提交：`feat(ledger): 请求规划与布局`。

## 测试与守护

- **顺序**：`[E]` 四段的字节顺序；运行时在 user 之后（把它移到前面 → 夹具红——v1 教训的回归）。
- **每回合一条**：`Generate` 只在首请求出现；`AlreadyPresent` 的后续请求不再追加（去掉该判定 → 红）。
- **模板字节**：`now` 为分钟粒度、`cwd` 原样转义规则（路径含引号/中文的用例）；夹具逐字节。
- **确定性**：两次 plan 的 `RequestPlan` 规范 JSON 相同；随机打乱 `TailInputs` 的构造顺序不影响输出。
- **Aux 隔离**：`plan_aux` 输出的 `cache.session_key == None`；接口上无法访问 `LedgerView`（编译层面）。
- **条目透传**：`[A]` 段条目不增删不重排（数量与顺序断言）。
- 先红后绿对照（PR 贴输出）：运行时尾巴前移、去掉"每回合一条"判定各一次。

## 风险与回退

- **`BlockRef` 的形态**：已渲染块与条目的映射若需要更多元数据（例如来源 venue），先改 04 §4.1 的注记再改类型。
- **`budget_hint` 之类的占位参数**：不给未定概念留假参数；需要什么加什么（本单草案里的占位在实现时裁掉）。
- **回退**：新增模块，revert 即可。
