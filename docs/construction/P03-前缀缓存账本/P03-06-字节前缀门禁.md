## 目标

"前缀即契约"有机器守着：在 mock 供应商上驱动场景，对记录的请求序列执行 04 §12.1 的四条判定（head 相等、去尾 `]}` 后字节前缀、链哈希出现在下一条链上、纪元变化必有 `context_rewrite`），三协议各跑一遍；每个场景配一个"变异版本会红"的反例；代表性请求体入 `tests/fixtures/request-shapes/` 并由 `cargo xtask fixtures refresh --reason` 守卫。

## 范围

- 做：
  - **迷你驱动**（无引擎）：用 `gqy-ledger`（plan/freeze）+ `gqy-provider`（encode/client）+ `MockServer` 驱动一个会话的请求序列；记录每次请求的 body 字节与落库状态。引擎就绪前的测试脚手架；P04/P05 起同一门禁改走真实引擎（见“接缝”）。
  - **判定函数**（库内，纯函数）：`check_prefix_sequence(records) -> Result<(), FirstDiff>`：按 04 §12.1 第 1–4 条；Anthropic 先剥离 `cache_control`（06 §11 的叠加物）再比；报错打印**第一个不同字节的偏移、前后 64 字节、所属条目 `seq`**（04 §13）。
  - **场景子集（P03 可跑）**：10 回合纯对话；工具循环（直连式：模拟三次工具结果追加）；冻结注入（运行时尾巴跨分钟——旧时间戳原样回放；参考 gqy 1-14：**上一回合首请求失败、下一回合**的中止通知顺序）；`load_tools` 的 stub 条目（不换纪元）；辅助请求穿插（主链不受影响、不带会话缓存标识）；daemon 重启（重建视图重新编码，与当初字节相同）。每场景 ×三协议。
  - **变异反例**（04 §12.3 的要求，`#[should_panic]` 或断言失败）：渲染里加当前秒数；运行时尾巴移到 user 之前；删除一条已发送的通知；tools 不排序——四个变异各自让门禁红。
  - **形状夹具**：`tests/fixtures/request-shapes/<protocol>/<scenario>.body`（代表性请求体全文）；`cargo xtask fixtures refresh --reason "<说明>"`：要求 `layout_version` 或 `encoding_version` 已变化（或手工豁免须在 PR 说明），差异打印同上一函数。
- 不做（接缝，随 P04/P05 补齐，本单在测试文件里留 `#[ignore]` 骨架或 TODO 注释并列出）：
  - 插话、打断、取消、流中断、`finish_reason=length` 的引擎场景（P04-04/05）；压缩/撤销/溢出恢复的纪元场景（P08）；子代理（P13-03）；persona 兼容/不兼容编辑（Q-12-2、P11-03）；Hybrid 合并加载（P06-02）。
  - 真实供应商联调（M1/M2 起按需）。

## 实施步骤

1. 判定函数 + 首差定位：先用手写字节样本写测试（含 anthropic 剥离、`]}` 去尾），再接到 mock 记录。
2. 迷你驱动跑通"10 回合纯对话 × openai-chat"，接三协议。
3. 逐场景加：工具循环、冻结注入（跨分钟 + 中止通知）、stub、辅助穿插、重启重编码。
4. 四个变异反例；确认每个都能让判定红（先红后绿各一次，写进 PR）。
5. `cargo xtask fixtures refresh` 与代表性 body 入库；实测场景矩阵耗时并记录（README 遗留 3）。
6. `cargo xtask check --fast`、`cargo test -p gqy-ledger --features gqy-provider/mock`；提交：`feat(ledger): 字节前缀门禁`。

## 测试与守护

- **判定自身**：单条请求通过；两条不延伸（改一个字节）→ 首差偏移正确；head 不同（改 `max_tokens`）→ 第 1 条红；链哈希不在下一条链上 → 第 3 条红；纪元变了但没有 `context_rewrite` 行 → 第 4 条红。
- **场景矩阵**（×3 协议）：每场景断言全序列通过；中止场景按 gqy 1-14 的教训排好顺序（通知与下一回合追加保持延伸）。
- **变异反例**：四个 `#[should_panic]`（或断言失败）用例；去掉判定里的任一规则 → 对应正例变红、变异用例照旧。
- **重启重编码**：同一冻结状态两次编码字节相同（I-2/I-7 的组件级守护）。
- **fixtures**：篡改一个 `.body` → 测试红并打印首差；`--reason` 缺版本变化时拒绝刷新（有测试）。

## 风险与回退

- **迷你驱动与真实引擎的差异**：驱动只覆盖"顺序正确"的部分；引擎带来的新走法（P04/P05）接入时门禁仍在，场景随那些单补齐（README 遗留 2）。
- **耗时**：三协议 × 场景矩阵在 CI 上若超预算，按 README 遗留 3 的实测决定是否拆长跑作业；**先测量**。
- **回退**：门禁是测试代码，revert 即可；不影响运行时。
