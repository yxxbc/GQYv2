## 目标

「先落库后发送」有一个能跑的实现：本回合 `[E]` 的待冻结条目在一个写作业里写入（`frozen = true`、链值由注入的 `ChainComputer` 计算、请求记录同时写入），提交成功后才允许发送；事务失败 → 请求不发送、运行以 `StoreUnavailable` 结束。冻结注入的规则（**注入点计算一次、存结果文本、之后不重算**）在本单立成文档与测试。

## 范围

- 做：
  - `freeze.rs`：`fossilize(store, session, pending: Vec<NewEntry>, chain: &dyn ChainComputer, record_seed: &RecordSeed) -> Result<FrozenRequest, LedgerError>`：
    - 一个 `Store::write` 作业内：分配序号 → 写条目（`frozen=true`）→ `chain.compute(...)` 得到各条目 `chain` 与 `prefix_hash` → 写 `llm_requests` 记录（字段来源 `RecordSeed` + 链结果）→ 提交；
    - 任何一步失败 → 整个作业回滚、返回错误；调用方（P04 起）以 `StoreUnavailable` 结束运行、**不发送**；
    - 返回 `FrozenRequest { entries, prefix_hash, ... }`，`plan` 的字节可据此重建（重发同一份字节由 P02-08 保证）。
  - `chain.rs` 的**接口**：`trait ChainComputer { fn compute(&self, epoch, stable_hash, entries) -> Result<(Vec<ChainValue>, PrefixHash), ChainError> }`；本单提供一个**恒值占位实现**（仅测试用，文档写明"生产路径必须用 P03-05 的实现"，编译上以 `#[cfg(test)]` 或名字里的 `Placeholder` 标注，防误用）。
  - 冻结注入的落地：运行时尾巴（P03-02 生成后即冻结）；感知值/记忆/来源元数据（本单接收已渲染块并原样冻结；P11/P12 提供块）。I-5 的测试：同一块在两次 plan 中被引用时字节相同（不重算）。
  - 纪元开始的 `StableSection` 条目写入：本单提供 `open_epoch(store, session, stable, reason)` 的**写入路径**（谁在何时调用由 P03-05 与 P04 决定；本单保证"每个纪元恰好一条、只追加"）。
- 不做：
  - 链的真实计算（P03-05 替换占位——本单的注入点就是为此设的）。
  - 压缩/撤销引发的纪元切换（05、P08）；persona 代际（Q-12-2）。
  - 工具循环的展开与状态机（P04）；本单只提供事务与序列。

## 接口草案

pub trait ChainComputer: Send + Sync {
    fn compute(&self, epoch: u32, stable_hash: &[u8; 32], entries: &[LedgerEntry])

// gqy-ledger/src/freeze.rs
pub struct RecordSeed { /* request_seq、purpose、wire_hash、surface_hash、profile_hash、parent_prefix 等（P03-05 定稿） */ }
pub async fn fossilize(

## 实施步骤

1. `chain.rs` 接口与占位实现；`freeze.rs` 的最短路径（单条目冻结 → 记录写入 → 提交）。
2. 失败语义：注入一个会失败的 `ChainComputer`（测试用），断言条目**没有**入库、记录没有入库、错误向上（先写测试）。
3. 冻结注入：把 P03-02 的运行时尾巴条目走一遍 `fossilize`；I-5 的"不重算"断言。
4. `open_epoch` 的写入路径与"恰好一条"测试（同 StableSection 重复调用 → 拒绝或幂等，按 04 §9.1“每个纪元开始时写一条”定；以实现为准并留痕）。
5. `cargo xtask check --fast`、`cargo test -p gqy-ledger`；提交：`feat(ledger): 化石化与冻结注入`。

## 测试与守护

- **先落库后发送**：冻结成功后条目 `frozen=true` 且 `chain` 有值；发送模拟失败后条目仍在（I-3：失败不回滚条目）。
- **事务原子性**：`ChainComputer` 返回错误 → 条目与记录都不存在；`Store` 降级（P01-04 的能力）→ 返回 `StoreUnavailable` 语义的错误。
- **重发同一字节**：冻结一次 → 两次发送（P02-08 的重试路径）→ mock 记录 body 逐字节相同。
- **I-5 不重算**：同一块两次被 plan 引用 → 字节相同；把渲染改成"每次读时钟"（测试改坏）→ 红。
- **重启延伸**：冻结后重建 `LedgerView` 再 plan → 与冻结前 plan 的 `[S]`+`[A]`+`[E]` 前段逐字节相同（08 §12.1 场景的组件级版本）。
- 先红后绿对照（PR 贴输出）：去掉 `frozen=true`（改回默认）→ 红；去掉事务回滚（先写条目再算链）→ 原子性用例红。

## 风险与回退

- **`RecordSeed` 的字段**：以 P03-05 的 `RequestRecord` 为准；本单预留字段由 `RecordSeed` 聚合，P03-05 定稿时同步（一处改）。
