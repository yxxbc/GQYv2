## 施工单 8-24：`gqy config` 打开终端界面的配置页

状态：已完成（2026-10-06 合进 main，提交 `bdd778a4`；三平台 CI 全绿 run 37355653734）。2026-10-04 项目主人提、当天定；2026-10-05「演示并进」合进 main 后开工。

### 目的

`gqy config` **不带子命令**时：

- **在终端里**：在这个终端里拉起终端界面，带 `--page config`，界面一起来就停在配置页；
- **不在终端里**（被脚本调、接管道）：照旧印帮助、退出码 2。

不做信号（2026-10-04 定的三条理由：界面没开着没人收；Windows 上没有这种信号；开着几个推给谁说不清）。

### 蓝图改哪几节

1. `cli/config.md`：
   - 「对外的样子」的子命令表加一行「（不带子命令）在终端里时拉起界面、停在配置页；不在终端里时印帮助、退出码 2」；参数那句加上「不带子命令又不在终端里」；
   - 「怎么走」加第 9 条：不在终端里怎么判、拉起谁（**主程序旁边的 `gqy-tui`**，走清单那套随 M9）、找不到说什么（退出码 1）、为什么不做信号；
   - 「在哪」加新文件 `config/head.rs`。
2. `tui.md`「全屏配置页」第 1 条：「核心 CLI 的启动约定随 8-24 接入；当前不修改核心 CLI」改成已接入（8-24 做完时）。

### 要拍板的

无（2026-10-04 项目主人都定过了：不做信号、拉起界面带 `--page config`、不做成子命令）。

### 不做什么

- **不照清单找**：清单那一套（`ui.head`、软件包发现）随 M9；这一步照 `gqy web` 的先例，找**主程序旁边的** `gqy-tui`（`sibling()`）垫着。
- 不动 `gqy`、`gqy web` 两个入口（它们改照清单找是 M9 的事）。
- 不改终端界面的代码（它已经支持 `--page config` 了）。

### 验收

1. 测试先写（红过再绿）：
   - `gqy-cli`：不是终端时 → 印帮助、退出码 2（不拉起界面）；是终端、旁边有 `gqy-tui` → 用 `--page config` 拉起它、退出码照它；旁边没有 `gqy-tui` → 说怎么装、退出码 1。
   - 照 `web.rs` 的 `web_on()` 那样做成可测的形状（主程序路径、语言、错误输出都传进来）。
2. 手写变异 8 个左右，全被逮住。
3. `cargo xtask check` 八项全过；三平台 CI 全绿。
4. 真机（本机）：终端里敲 `gqy config`，界面起来停在配置页；`gqy config | cat` 印帮助、退出码 2；把 `gqy-tui` 挪走再敲，说怎么装、退出码 1。

### 风险

- 拉起界面要占着终端（全屏），`Command::status()` 会等到它退出——这是对的（和 `gqy web` 一样等），但要确认不会把父进程的终端搞乱。
- `gqy-tui` 装在哪：这一步只认「和 `gqy` 同一个目录」，装法（各家的包）随发行那一步。
- 退出码要照 `gqy-tui` 的带上去（它自己会报「参数不认」这类）。

### 施工结果（2026-10-06 主会话）

1. 先改图纸（`cli/config.md`：子命令表加「不带子命令」一行、参数那句补上它、怎么走第 9 条、在哪表加 `config/head.rs`），再写测试，最后实现。
2. 实现：`Config.command` 改成 `Option<ConfigCommand>`（不带子命令时 clap 不报错）；`run()` 开头先拦这一支（在碰数据根、连核心之前）；新文件 `config/head.rs`：`head_on(tty, main, language, out, err)` 和 `in_terminal()`，找法照 `gqy web` 的 `web::sibling()`（**不重建**，直接复用）。
3. 测试 9 条：不在终端里印帮助 + 退出码 2（且**不**拉起）；没装的两种语言都说清怎么装、退出码 1；在、但跑不起来的和「没装」分开说；退出码照界面的（0/3/255 各一）；被信号杀的算没成（不是 0）；`both()` 四种组合。
4. 手写变异 7 个，全被逮住（`/tmp/mut-8-24.sh`）。**变异查出三处测试不够**：两条断言太弱（没盯住「怎么装」那句、没压住 `code()` 为 `None` 的情形）、`in_terminal` 根本没测；把终端判定抽成 `both(a, b)` 才测得到「一个是、一个不是」。
5. 真机（本机，伪终端）：`gqy config` 在终端里真的拉起了 `.../gqy-tui --page config`（看到进程）；`gqy config < /dev/null` 印帮助、退出码 2。
6. 帮助页（两份 `help/{zh,en}/config.txt`）跟着改：用法行 `[命令]`（可不写）、正文说清不写命令时两种去向。改的时候被 `help::tests::pages_fit_in_eighty_columns_and_end_with_one_newline` 拦了**两次**（中文、英文各一次超 80 列）——那条测试是逐行量宽度（汉字算两列）、行尾不许有空格、整页一个换行结尾，自己折行就行。
7. 三平台 CI：第一次（run 37350451573）**Windows 红**：假邻居（写 shell 脚本）标了 `#[cfg(unix)]`，但一条调用它的测试忘了标，Windows 上那条测试还在、方法却不在，`no method named neighbour found`。本机（macOS 属于 unix）看不出来。改成按平台分开：「不在终端里印帮助」跨平台都测、「不去拉起界面」单独一条标 `#[cfg(unix)]`；另把「在、但跑不起来」也标上（靠「空文件当程序」，只在 Unix 上有把握）、「找邻居」两边都 canonicalize（Windows 的 `\\?\` 前缀会让字面比假红）。本地验不了 Windows 完整编译（`gqy-cli` 依赖带 C 的 rusqlite），用脚本模拟 cfg 确认剩下 5 条不碰 unix-only 的东西。重推 `d58bb366`，三平台 CI （待填）。
