# P05 · 生产级网关

> 状态：【规划】。本阶段把 13 号协议文档落成一个**直接按生产级建设**的网关：传输硬化与连接上界、唯一的中间件栈与错误契约、鉴权与浏览器会话、限速、SSE 生产语义、局域网 TLS、优雅停机；同一阶段完成 M1 最小闭环（daemon → `gqy ask` → TUI）。
> 创建：AI 助手（Cline 会话），2026-09-28。改动本文件时，按根 `AGENTS.md` 规矩 7 更新这一行：写清谁改的、什么时候改的。

## 阶段目标

（与施工图 `plan-data` 同文）协议 v1、生产级网关（传输硬化与连接上界、中间件栈与错误契约、鉴权与浏览器会话、限速、SSE 生产语义、局域网 TLS、优雅停机）、客户端、daemon 生命周期、`gqy ask`、最小 TUI。做完之后：

- 唯一对外入口按 13 的完整形态运行：默认只监听回环 + UDS，局域网要显式开启并**强制 TLS**（13 §3.3）；
- 连接与请求都有上界（头超时、体限、请求超时、并发、速率），拒绝有稳定错误码；panic 与服务端错误不炸连接（13 §3.1、§3.2、§7）；
- 事件流可续传、不死循环，慢客户端被降级而不是拖垮服务（13 §6.4）；
- 停机先排空再强制退出；`daemon start/stop/status/logs` 与单实例锁就位（13 §12、01 §4）。

## 进入条件

- P04 完成（Supervisor / actor / 状态机 / 取消 / 事件总线 / 停机与恢复）；13 与 02、10、19 通读一遍；

## 退出条件

- 十三张单全部“已完成”；`cargo xtask check/test` 与三平台 CI 绿；
- **M1 验收**：干净临时数据目录下 `gqy daemon start` → `gqy ask "你好"`（mock 与真实供应商各一次）→ 重启 daemon 后会话可继续 → `gqy`（TUI）能对话；
- **生产项**：13 §14 的生产守护测试全绿（栈顺序、panic 隔离、慢头、体限、限速与锁定、可信代理、减载、含 SSE 的优雅停机、TLS、Host 校验、鉴权审计）。

## 遗留与发现

> 施工过程中发现的范围外问题记在这里；写单时发现、需要用户拍板的点也记在这里。

写单时的口径：

1. **“生产级”的验收硬指标**是 13 §14 的生产守护测试与 §3.1 的上界表；不因“先跑通”省任何一条——这正是本阶段改名与重排的原因。
2. **局域网与 TLS 归本阶段**（不等 17）：完整设备配对、mesh 与跨设备同步仍在 17；本阶段只保证「显式开启 + 强制 TLS + 凭据同回环 + `Host` 校验 + 审计」。
3. **路由随能力生长**：`/config`、`/personas` 依赖 P11，`/jobs` 的部分字段依赖 P13；本阶段只注册依赖已就位的路由，未就位的**不注册**（404，而不是返回假数据），归属表见 P05-06 的「不做」段。
4. **Q-13-4 仍待定**（是否继承 v1 `gqy stdio`）：P05-11 不实现该协议；若拍板要继承，另行开单。
5. **平台**：Windows 只要求编译与单元测试；UDS、对端凭据、TLS 相关测试按 `cfg` 排除，缺失能力失败关闭（00 §5）。
6. **性能**：连接上限、SSE 并发、限速桶的实测数据随 P05-03 / P05-05 / P05-08 的 PR 记录；与 19 §3.7 的预算不符时先改设计再改实现。
