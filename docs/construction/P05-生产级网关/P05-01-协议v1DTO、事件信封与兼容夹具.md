## 目标

`gqy-protocol` 成为线上形状的**唯一来源**：13 §5 的全部请求/响应 DTO、§6.1 的事件信封与强类型 `Event`（含 `Unknown` 兜底）、§9 的 `AskLine`、§7 的 `ApiError`、协议版本常量与能力位；兼容规则（只增）与夹具门禁就位。P04-06 的临时 `EnvelopeCodec` 在本单被唯一实现替换。

## 范围

- 做：
  - crate 骨架（L0；依赖 serde；可选 feature `ts` 启用 `ts-rs`）。
  - DTO 全量：§5.1 系统、§5.2 会话、§5.3 回合/运行/问题（含 `SubmitTurn`、`Admission` 线上投影、`QuestionView` 的 `drawer_id` 与 `Choice`）、§5.4 事件、§5.5 命令、§5.6 作业与用量、§5.7 配置与人格、§5.8 鉴权与 blob。
  - `EventEnvelope` + `enum Event`：覆盖 13 §6.2 事件目录的**每一行**；未知 `type` → `Event::Unknown { kind, data }`（不报错）；唯一序列化函数 `Event::to_envelope`。
  - `ApiError`（§7）与 `ErrorKind` 投影（新变体 `Overloaded`、`RequestTimeout` 在 P03-05 的 `gqy-core` 中补齐后此处引用）。
  - `AskLine` 与 `ask_line_from_event(&Event) -> Option<AskLine>`（§9.1）；退出码常量表（§9.2）。
  - 版本：`PROTOCOL = ProtocolVersion { major: 1, minor: N }`、`features: &[&str]`、`X-GQY-Protocol` 头名常量。
  - 兼容规则 1–4 的 xtask 检查（`deny_unknown_fields` 扫描等）与规则 5 的夹具门禁（`tests/fixtures/v1/`，每类型至少一份，blake3 清单只增不改）。
  - 序列化稳定性：map 一律 `BTreeMap`；写出经 `gqy_core::canonical_json`（P01-01）。
  - `xtask gen-ts` 与 `--check`：把 DTO 生成到 `apps/web-console/src/core/generated/`；目录不存在时 `--check` 跳过并提示（前端目录由 P10-01 建）。
- 不做：
  - SSE/HTTP 与任何路由（P05-02/03/06/07/08）。
  - 连接器帧的**实现**（16；本单只放帧类型骨架，实现在 P14-02）；mesh（17）。
  - 前端工具链与生成物入库（P10-01）；不引入 Node。

pub struct EventEnvelope {
    pub v: u16, pub seq: EventSeq,
    pub session: Option<SessionId>, pub run: Option<RunId>,
    pub kind: String, pub ts: String, pub data: serde_json::Value,
}
pub enum Event { /* 13 §6.2 全目录 */ Unknown { kind: String, data: serde_json::Value } }
impl Event {
    pub fn to_envelope(&self, seq: EventSeq, session: Option<&SessionId>, ts: &str) -> EventEnvelope;
}
pub fn parse_envelope(raw: &[u8]) -> Result<Event, ProtocolError>;   // 未知 kind 不报错

pub fn ask_line_from_event(ev: &Event) -> Option<AskLine>;
pub const ASK_LINE_VERSION: u32 = 1;

## 测试与守护

- **夹具门禁**：每类型至少一份 JSON 夹具；逐份反序列化 + 再序列化，断言关键字段不丢；夹具 blake3 清单被钉住（改已入库夹具 → 红）。
- **兼容违规**：给任一 DTO 加 `deny_unknown_fields`、删一个字段各一次 → 测试红。
- **事件目录覆盖**：§6.2 每行都有 `Event` 变体（缺一 → 测试红）；未知 `kind` 解析为 `Unknown` 且不报错。
- **序列化稳定**：同一事件两次序列化字节相同；`BTreeMap` 顺序不依赖插入序。
- **`ask_line_from_event`**：每类事件断言“产出 / 不产出”；产出行恒有 `"v": 1`。
- 先红后绿对照（PR 贴输出）：删目录一行、把 `Unknown` 改成报错各一次。
