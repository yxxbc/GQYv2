## 目标

每条请求都被解析成 `Caller { auth, principal, trust }`：UDS 走本地令牌 + 对端 uid，HTTP 走 bearer 或浏览器 cookie——**同一套判定代码**，不为 Web 开第二条路径。令牌与浏览器会话可创建、可吊销（5 秒内生效）、可审计；每一条路由都声明自己的 scope 集合，缺声明编译不过。

## 范围

- 做：
  - 身份提取层（栈第 9 层）：`AuthSource` 注入（UDS / HTTP 两种监听各自注入）→ `Caller`；`GET /health` 免鉴权，其余一律要凭据（**不信任回环**）。
  - 本地令牌：daemon 每次启动生成随机令牌写 `run/local.token`（0600；`run/` 0700）；UDS 请求必须携带；对端 uid 必须等于 daemon uid（附加检查，来自 P05-02 的 `peer_cred`）；daemon 重启即失效（客户端重读文件）。
  - bearer 令牌：格式 `gqy_<scope>_<32 字节 base32>`；库里只存 blake3 哈希；比较用 `subtle` 常数时间；scope = `client` / `member:<principal>` / `connector:<platform>` / `readonly`；`POST/GET/DELETE /auth/tokens`（明文只在创建响应里回一次）；吊销立即生效（按请求查库 + 5 秒 TTL 缓存 + 吊销时主动失效）。
  - 浏览器会话：`POST /api/v1/auth/pairing`（**仅 UDS**，Owner 动作）签发一次性配对码（8 位、5 分钟、单次）→ `POST /auth/login` 换 `gqy_session` cookie（`HttpOnly; SameSite=Strict; Path=/api`；TLS 下加 `Secure`）；非 GET 校验 `Origin` 同源 + `X-GQY-CSRF`（会话绑定值）；30 天滑动续期；`POST /auth/logout`。
  - 路由权限表：每条路由声明允许的 scope；编译期生成表，测试遍历断言“没有未声明 scope 的路由”。
  - `auth_events` 审计：`pairing_issued`、`login_ok`、`login_fail`、`token_created`、`token_revoked`（P05-12 再加 `lan_*` 与 `tls_cert_rotated`）。
  - SSE 吊销联动：订阅创建时登记令牌来源；吊销后 5 秒内关闭（与 P05-08 的联测）。
- 不做：
  - 局域网与 TLS 模式本体（P05-12；本单的 cookie `Secure` 依据“当前请求是否 TLS”一个开关）。
  - 登录限速与失败锁定（P05-05 消费本单的登录结果）。
  - 成员账号体系（12，P11）、连接器令牌的具体校验细节（P14）。

## 测试与守护

- **不信任回环**：从 `127.0.0.1` 无凭据访问任一非 `/health` 路由 → 401；去掉鉴权层此测试红。
- **UDS 凭据**：同 uid 无令牌 → 401；令牌错误 → 401；`run/local.token` 权限 0600（重启后旧令牌失效）。
- **对端 uid**：同 uid 通过；跨 uid 情形 `#[ignore]`（需特权，Linux `unshare` 跑）。
- **令牌生命周期**：创建响应含明文一次，库里只有哈希（查库断言）；吊销后 5 秒内 401（TestClock 边界）。
- **权限表**：遍历所有路由断言都有 scope 声明；`GET /health` 例外被显式登记。
- **浏览器会话**：配对码一次性与 5 分钟过期；`Origin` 不符 → 拒绝；缺 `X-GQY-CSRF` → 拒绝；`GET` 不需要 CSRF；cookie 属性（`Path=/api`、TLS 时 `Secure`）。
- **审计**：四类 `auth_events` 各一行；`GET /audit` 不含 `auth_events`（§8.6）。
- 先红后绿对照（PR 贴输出）：把令牌比较改成非常数时间（`==`）在评审中说明、去掉吊销主动失效各一次。

## 验收流程

```sh
cargo test -p gqy-gateway -p gqy-store   # 全绿
cargo xtask check --fast
# 手检：起 daemon 后
TOKEN=$(curl -s --unix-socket run/gqy.sock -H "Authorization: Bearer $(cat run/local.token)" -X POST http://gqy.local/api/v1/auth/tokens -d '{"scope":"client","label":"test"}' | jq -r .token)
curl -s -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8310/api/v1/info | jq .protocol
curl -s --unix-socket run/gqy.sock -H "Authorization: Bearer $(cat run/local.token)" -X DELETE http://gqy.local/api/v1/auth/tokens/<id>
curl -s -o /dev/null -w '%{http_code}\n' -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8310/api/v1/info   # 5 秒内应为 401
```

## 风险与回退

- **缓存与吊销的时序**：5 秒窗口是设计口径；任何“立即生效”的强化都要同步 13 §8.2 并加测试。
- **与 P05-08/P05-12 的接口**：SSE 关闭与 `Secure` 开关都依赖本单输出的 `Caller`/TLS 标记；先定接口再实现。
- **回退**：`auth/` 与 `gqy-store/src/auth.rs` 是新文件，revert 即可；三表的迁移随实现单落地，未发布前可合并调整。
