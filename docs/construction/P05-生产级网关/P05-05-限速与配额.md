## 目标

13 §11 的表逐行落地：登录按来源 IP 5 次/分钟、连续 10 次失败锁 15 分钟；每令牌写 30 次/秒（突发 60）；每令牌 SSE 并发 32；全局 SSE 256；超限一律 429 + `Retry-After`。实现形态是自写模块（令牌桶 + 计数上限 + 失败锁定，注入 `Clock`，LRU 上限 10k，不落库）——数值集中在 `gqy-config`，只能放宽到上限，不能关闭。

## 范围

- 做：
  - `rate.rs`：`TokenBucket`（速率 + 突发）、`CounterLimit`（当前并发数）、`FailureLockout`（连续失败与锁定期）；键**先哈希再入桶**；全部取时经注入 `Clock`；LRU 上限 10k，淘汰有计数。
  - 接入栈第 10 层（P05-03 的占位）：按 `RouteClass` 与 `Caller` 选桶——登录用 §8.5 解析出的真实 IP；写请求用令牌哈希；SSE 用“每令牌并发 + 全局并发”两个计数。
  - 拒绝语义：429 + `Retry-After`（秒），响应体是 `ApiError{ kind: RateLimited, retry_after_ms }`；锁定态与速率超限用不同 `code`（`locked` / `rate_limited`）。
  - 配置：`gateway.rate.*`（默认照 §11 表；上限校验；“不能关闭”有测试）。
  - 指标：桶键数、淘汰计数、429 计数（供 `/daemon/status`，19 §3.6）。
- 不做：
  - 连接器按 principal 的配额（16，P14）。
  - 引擎侧准入与队列（P04-03 已定，202 语义不变：429 只用于传输层限速）。
  - SSE 的订阅缓冲与降级（P04-06 的订阅 + P05-08 的响应层）。

## 接口草案

草案，以实现为准。

```rust
// gqy-gateway/src/rate.rs
pub struct RateLimiter { /* 配置 + LRU 表 + Clock */ }
impl RateLimiter {
    pub fn check_login(&mut self, ip: IpAddr, now: Timestamp) -> Result<(), RateDenied>;
    pub fn note_login_result(&mut self, ip: IpAddr, ok: bool, now: Timestamp);
    pub fn check_write(&mut self, token: &TokenFingerprint, now: Timestamp) -> Result<(), RateDenied>;
    pub fn acquire_sse(&mut self, token: &TokenFingerprint, global_used: usize) -> Result<SseGuard, RateDenied>;
    pub fn stats(&self) -> RateStats;
}
pub struct RateDenied { pub code: &'static str, pub retry_after: Duration }
```

## 测试与守护

- **登录速率**：第 6 次 429（TestClock 推进 60 s 后恢复）；`Retry-After` 合理。
- **失败锁定**：连续 10 次失败 → 锁 15 分钟；锁定期内即使密码正确也 429 `locked`；到期恢复。
- **令牌写速率**：30/s 突发 60（第 91 次在 1 秒内被拒）。
- **SSE 并发**：每令牌 32、全局 256；释放后可用；429 语义（每令牌）与 503（全局）按 §11 表。
- **可信代理**：非可信来源带 `X-Forwarded-For` 时按真实对端 IP 计数（§8.5）；可信来源按其声明的客户端 IP。
- **LRU**：10k+1 个键 → 淘汰最久未用并计数；内存有界。
- **不阻塞**：桶操作是 O(1)（结构断言：无遍历全表的代码路径；键数有上限）。
- 先红后绿对照（PR 贴输出）：把突发改成 0、把锁定判断去掉各一次。
