## 目标

事件流按生产语义上线：SSE（`Last-Event-ID` / `?after_seq=` 续传）、JSON 分页拉取、全局流、15 秒心跳、慢客户端 `lagged` → `stream.resync_required` 并关闭、`purged`/`too_far` 分支、连续 lagged 降级为只推持久化事件、`as_of_seq` 与 `view` 一致、令牌吊销 5 秒内关闭、停机先发 `daemon.stopping` 再关流。

## 范围

- 做：
  - `GET /sessions/{id}/events`：SSE；帧 `id: <seq>`、`event: <type>`、`data: <信封 JSON>`；`axum::response::sse::{Sse, Event, KeepAlive}`；心跳 15 秒（注释行 `: ping`，不占 seq）。
  - 续传：`L ≥ 当前最大 seq` → 实时；窗口内（条数 ≤ `gateway.events.replay_max`，默认 5000）→ 先补发再实时；被清或太远 → `stream.resync_required{reason: purged|too_far}` 并关闭。
  - 慢客户端：订阅缓冲（P04-06 的每订阅 1024）溢出 → 发 `stream.resync_required{lagged}` 并关闭；同一订阅连续两次 lagged（间隔 < 10 s）→ 降级为只推持久化事件，直到重连（13 §6.4）。
  - `GET /sessions/{id}/events?format=json&after_seq=&limit=`：同一数据的分页拉取（resync 与调试用）。
  - 全局流 `GET /events`（O）：全局 seq 空间；本阶段承载已就位的子集（会话列表变化、daemon 状态、作业事件随 P13）。
  - `as_of_seq` 与 `view` 的一致性：`view`（P05-06）生成后的事件一定 `> as_of_seq`；订阅交付按 seq 去重。
  - 吊销与停机：订阅记录令牌来源，吊销后 5 秒内关闭（与 P05-04 联测）；停机时先发 `daemon.stopping{deadline_ms}`（会话流与全局流都发）再关闭；`gateway.drain_ms` 控制排空宽限（P05-10 调用）。
  - 权限：会话流 O/M；M 只能订阅自己 principal 的会话。
  - 指标：订阅数、lagged 次数、缓冲深度（`/daemon/status`，19 §3.6）。
- 不做：
  - 前端消费（P09/P10）；连接器与 mesh 订阅（P14/P17）；流事件保留期作业（P13，按 10 §9.3）。

## 测试与守护

- **续传**：mock 回合产生 1000 个事件；在 seq=300 断开，用 `Last-Event-ID: 300` 重连 → seq 严格递增、无重复、持久化事件无遗漏（13 §14 的验收断言）。
- **慢客户端**：订阅故意不读 → 收到 `resync_required{lagged}` 且被关闭；生产者耗时不受影响；连续两次 lagged → 后续只收持久化事件。
- **resync 分支**：被清区间 → `purged`；`after_seq` 太远 → `too_far`。
- **心跳**：TestClock 推进 15 秒 → 收到一个 `: ping`（不占 seq；客户端容忍）。
- **吊销**：订阅期间吊销令牌 → 5 秒内连接关闭（TestClock 边界）。
- **停机**：先收 `daemon.stopping`，随后流关闭；`drain_ms` 内完成。
- **`as_of_seq` 一致性**：view 生成后的事件都 `> as_of_seq`。
- **并发上限**：每令牌 32、全局 256 → 429 / 503（与 P05-05 联测）。
- 先红后绿对照（PR 贴输出）：去掉补发分支、把心跳改成无事件才发各一次。
