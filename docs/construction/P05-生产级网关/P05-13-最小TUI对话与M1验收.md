## 目标

最小可日用对话界面 + **M1 验收**：`gqy`（无参数）检测并按需拉起 daemon 后进入 TUI；能输入、看到流式输出、取消运行、退出；M1 脚本在临时数据目录上跑通「daemon start → ask（mock 与真实供应商）→ 重启 daemon 后续聊 → TUI 对话」，并把结果写进施工图「每一步的图」。

## 范围

- 做：
  - `apps/tui`（`gqy-tui`，L7；只依赖 `gqy-client` / `gqy-protocol`）：最小布局（转录区 + 输入框 + 状态行）；`ratatui` + `crossterm` 单渲染路径。
  - 行为：Enter 发送；流式显示（`assistant.delta` 追加、`assistant.message` 校准）；Esc / Ctrl-C 取消当前运行；Ctrl-D 退出；`--session <id>` 续接；断线提示与重连（退避由 `gqy-client` 提供）；`daemon.stopping` 时提示并退出。
  - `apps/gqy`（无参数）：锁 + `ping` 判存活；未运行则按配置后台拉起（P05-10 的 `daemon start`），再进入 TUI。
  - M1 验收脚本 `tests/e2e/m1.sh`：干净临时 `GQY2_HOME`；mock 供应商断言输出与退出码；真实供应商一步标 `needs:real-provider`（用户环境）；重启后同一会话可继续（账本视图与 `assistant.message` 一致）。
  - `CHANGELOG.md` 的 `[Unreleased]` 记录 M1 用户可见的改动（新建会话、对话、`gqy ask`）。
- 不做：
  - 完整 TUI（P09 的七张单：布局体系、转录虚拟化、命令表、审批/提问界面、会话与任务面板）。
  - Web（P10）、桌面（P16）、主题与 i18n（P11）。

## 接口草案

草案，以实现为准。

```rust
// apps/tui/src/app.rs
pub struct App { /* client + 会话 + 转录缓冲 + 状态行 */ }
impl App {
    pub async fn run(&mut self, terminal: &mut Terminal<impl Backend>) -> Result<(), TuiError>;
    pub fn on_key(&mut self, key: KeyEvent) -> Action;   // 纯函数：键位 → 动作（可测）
}
```

## 实施步骤

（L 单：每一步都能单独编译通过。）

1. crate 骨架 + 首屏（`TestBackend` 快照）。
2. 输入与提交（走 `gqy-client`），流式显示与 `assistant.message` 校准。
3. 取消、退出、断线重连、`daemon.stopping` 提示。
4. `gqy` 无参数的判存活与按需拉起。
5. M1 脚本（mock 全绿；真实供应商用例标 `needs:real-provider`）。
6. `cargo xtask check --fast`、`cargo test -p gqy-tui -p gqy`、`tests/e2e/m1.sh`；提交：`feat(tui): 最小对话与 M1 验收`。

## 测试与守护

- **首屏与流式**：`TestBackend` 缓冲快照（首屏、收到 3 个 delta 后、完成后）。
- **键位**：`on_key` 纯函数表驱动（Enter/Esc/Ctrl-C/Ctrl-D/普通字符）。
- **取消**：取消后 UI 回到可输入态，运行终态为 `Cancelled`（mock 供应商）。
- **断线**：关掉 daemon → 提示；重启后重连并保持会话（同一 `SessionId`）。
- **M1 脚本**：`tests/e2e/m1.sh` 在临时目录全绿；断言 `gqy ask` 的 stream-json 最后一行 `done`、重启后续聊的回复里能看到上一轮内容。
- **CI**：无 TTY 环境不跑交互测试（`#[ignore = "needs:tty"]` 或 `TestBackend` 替代）；M1 脚本在 Linux 与 macOS 的 CI 各跑一次（15 分钟内）。
- 先红后绿对照（PR 贴输出）：去掉 delta 追加、把取消改成直接退出各一次。

