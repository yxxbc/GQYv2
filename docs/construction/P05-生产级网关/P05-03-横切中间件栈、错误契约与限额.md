## 目标

13 §3.2 的十一层栈成为**唯一**实现且顺序被测试钉住；错误体只有 `ApiError` 一种形状（`ErrorKind → HTTP` 穷尽映射，wildcard deny）；panic 不炸连接；`X-Request-Id` 贯穿；敏感头不进日志；超时、体限、并发与减载按 §3.1 的参数化规则落地（含 SSE 豁免与 `/blobs` 例外）。

## 范围

- 做：
  - 栈（顺序照 §3.2，`tower::ServiceBuilder` 组装，顺序有测试）：`LoadShed` → `ConcurrencyLimit` → `CatchPanic` → `Trace` → `SetRequestId`+`PropagateRequestId` → `SensitiveHeaders` → `Timeout` → `RequestBodyLimit` → 身份提取占位（P05-04 接真）→ 限速占位（P05-05）→ 业务 `Router`。
  - 错误契约：响应体 `{ "error": ApiError }`；`ErrorKind → StatusCode` 穷尽 match（`clippy::wildcard_enum_match_arm` 在本模块 deny）；`request_id` 必填；`retryable` / `retry_after_ms` 字段。
  - `gqy-core` 的 `ErrorKind` 补 `Overloaded`（503）与 `RequestTimeout`（408）（13 §7 表已定）。
  - 超时：默认 30000 ms；`/blobs` 上传 120000 ms；**SSE 豁免**——豁免用“路由属性”的单一来源声明，P05-08 注册 SSE 时复用同一属性。
  - 体限：默认 1 MiB；`/blobs` 16 MiB；有 `Content-Length` 预拒 413，无 `Content-Length` 读到上限断流；钉住“超限后连接可能关闭”（§3 的说明）。
  - 减载与并发：`LoadShedLayer` 最外层（过载即 503 `overloaded`）+ `ConcurrencyLimitLayer`（在途上限；写路由独立档）。
  - `GET /health`（免鉴权）与 `GET /info` 骨架（版本、`protocol`、`features`、构建 ID；不回显数据目录路径）。
  - 敏感头：`Authorization`、`Cookie`、`X-GQY-CSRF` 标记后，断言日志不含其值。
  - `conn.*` 日志：头超时、体超限、TLS 握手失败（P05-12 接线）各一条，字段含 request_id（若有）。
- 不做：
  - 鉴权判定（P05-04；本单只留 `Caller` 提取占位与测试用 `AuthSource`）。
  - 限速实现（P05-05；本单留层位置与配置键）。
  - 业务路由（P05-06/07）、SSE 路由本体（P05-08）。

## 测试与守护

- **栈顺序**：注入“全 500”内层服务断言顺序与终态；去掉 `CatchPanic` → panic 测试红；`LoadShed` 移到 `ConcurrencyLimit` 内侧 → 减载测试红。
- **panic 隔离**：处理函数 panic → 500 `Internal` + `request_id`；同连接下一个请求照常。
- **慢头**（与 P05-02 联测）：半截头 + 停顿 → 连接关闭，`conn.header_timeout` +1。
- **体限**：有 `Content-Length` 超限 → 413 且内层未被调用；无 `Content-Length` 的超限流 → 断流；超限后连接状态被钉住。
- **超时**：默认 408；`/blobs` 用 120 s；SSE 路由（用 mock 路由标记 `RouteClass::Sse`）**不超时**。
- **减载**：在途上限调 1 并挂起一个请求 → 第二个 503 `overloaded`。
- **请求 id**：响应带 `X-Request-Id`；客户端带 `X-Request-Id` 时被回传（Propagate 语义）。
- **敏感头**：用 tracing 测试订阅器断言 `Authorization`/`Cookie` 的值不出现在任何日志字段。
- **错误映射穷尽**：`ErrorKind → StatusCode` 的表驱动用例 + 无通配 match 的编译期守护。
- 先红后绿对照（PR 贴输出）：去掉 CatchPanic、把体限判断改成恒假各一次。
