## 阶段目标

Provider trait、SSE、四类超时、mock、三种协议适配器、用量、重试与密钥轮转（与施工图 `plan-data` 同文）。做完之后：

- `gqy-provider` 能对一个 `RequestPlan` 做**确定性编码**（单一路径、规范 JSON、消息数组最后）；
- 三种协议（openai-chat / openai-responses / anthropic）各自的编码、流解码、信封保真与错误分类有夹具钉住；
- mock 供应商在同一套真实 HTTP + SSE 路径上支持脚本与故障注入，成为 P03 字节门禁与场景测试的公共底座；
- 用量四桶映射、成本计算与 `gqy::usage` 日志行就位；重试、选钥与档位解析按 06 §8、§10 落地（含 2026-09-28 的降级池决策）。

写单时的口径（按 06 §20 的推荐实现，用户可推翻）：

1. **Q-06-1 默认选钥策略**：按推荐实现 `session_sticky`（06 §8.4）；若用户改判 `round_robin`，改 P02-08 与 06 即可。

4. **Q-06-3 CLI 中转**：按推荐作为扩展（18），不在 P02；`gqy-provider` 只保留 `prefix_hash` 续传接口的位置。
