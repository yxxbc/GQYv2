## 目标

把“发一次”变成“可靠地发完一次”：`ProviderClient::run` 成为回合引擎唯一调用的入口——编码一次、按 §8.2 重试（**已转发内容后永不重试**）、按 §8.4 选钥与冷却、按 §10 解析档位与旁路角色（含降级池）。做完之后，P03/P04 只需要 `run(plan)`。

## 范围

- 做：
  - `retry.rs`：单层重试策略（总尝试默认 4 = 首发 + 3；总墙钟 ≤ 3 min）；退避 `min(30 s, 1 s × 2^n)` 全抖动；`retry_after` ≤ 30 s 按它等，> 30 s 且无其他健康密钥 → 不等待、直接以 `RateLimited` 失败并给出建议等待时间；**`sink.forwarded_content()` 为真时任何错误直接上抛**（06 §8.2）；等待可被取消令牌打断；每次重试经 `EventSink` 发 `request.retrying { attempt, kind, delay_ms }`（P04-06 接总线）。
  - `keys.rs`：`KeyPool`（每供应商一个、内存态、重启清零）：密钥来自 `SecretResolver`（接口在此定义；真实解析在 P11-02，测试用内存 map）；选钥 `session_sticky`（默认：`blake3(session_id) mod n`、只在健康集合里选、失败换钥后粘住）与 `round_robin`；辅助请求恒 `round_robin`；冷却（`RateLimited` 按 `retry_after`，缺省 60 s；`QuotaExhausted` 1 h）；`Auth` → 禁用到配置重载并发 `provider.key_disabled`（经 `EventSink`）；失败重发的判定（是否换钥）严格照 06 §8.2 表。
  - `tiers.rs`：档位解析（`[models.roles]` 映射；缺档向上找；都没有 → 旁路降级并报告）与**降级池**（2026-09-28 决策：同档位按配置顺序取“第一个健康的”；瞬时类错误触发冷却；`Main`/`Compact` 不自动换）。
  - `client.rs`：`ProviderClient { provider: Arc<dyn Provider>, http, keys, tiers, retry }`；`run(&self, plan, events, cancel) -> Result<ProviderOutcome, ProviderError>`：`encode` 恰一次 → 发送（注入密钥头）→ 失败按策略重试（同一份 body，只换密钥头）→ 汇总 `ProviderOutcome { response, attempts, key_id }`。
  - 保温与写入宽限（投放层）：本单只落**接线与校验**（`PerRequest` 上开启报错已在 P02-01；`keepalive`/`write_grace_ms` 的调度属会话 actor，P04 起）——在单里注明归属。
- 不做：
  - 回合层语义：`FinishReason::Length` 的拒绝规则（03）、压缩触发（05）、事件总线（P04-06）。
  - secrets 的真实存取（P11-02）；真实供应商联调（M1/M2 之后按需）。

## 实施步骤

1. `retry.rs` 先写“暂停时钟下的等待与取消”测试，再实现退避与策略判定（矩阵照 §8.2 表逐格）。
2. `keys.rs`：选钥的粘性与冷却；用 mock 记录断言“重发同 body、只换密钥头”。
3. `tiers.rs`：角色表与降级池；健康状态接口 `PoolHealth`（本单内存实现）。
4. `client.rs` 串起来：编码一次、重试循环、`ProviderOutcome`。
5. `cargo xtask check --fast`、`cargo test -p gqy-provider --features mock`；提交：`feat(provider): 重试、选钥与档位`。

## 测试与守护

- **重试矩阵**（照 §8.2 逐格，mock 故障注入）：429 带 `retry_after=5` → 等 5 s（暂停时钟）；429 无 `retry_after` → 冷却缺省 60 s 且换钥；`Overloaded`/`Server` → 重试不换钥；`ConnectTimeout`/`Transport` → 重试；`StreamStalled` 未转发内容 → 重试、已转发 → 直接上抛；`Auth` → 换钥并禁用原钥（发 `provider.key_disabled`）；`QuotaExhausted` → 换钥 + 1 h 冷却；`ContextOverflow`/`BadRequest`/`Protocol`/`Cancelled` → 不重试。
- **上限**：4 次封顶；墙钟 3 min 封顶（暂停时钟下断言）；取消打断退避。
- **同一份 body**：两次请求的 mock 记录 body 逐字节相同、密钥头不同（去掉“重发原 body 只换钥”的实现 → 红）。
- **已转发不重试**：流中出错且已转发文本 → 不再请求（界面不出现重复文本的守护）。
- **选钥**：健康集合不变时同会话恒选同一钥；换钥后粘住；辅助请求走 `round_robin`；全部禁用 → 失败信息列出各钥指纹与状态。
- **档位**：角色映射表；缺档向上；`Main`/`Compact` 不参与降级池；降级池“第一个健康的”顺序；冷却中的模型被跳过。
- 先红后绿对照（PR 贴输出）：去掉“已转发不重试”判定、去掉密钥禁用各一次。

## 风险与回退

- **全抖动的确定性**：退避抖动注入可替换的随机源（测试固定种子）；断言等待上界与调用次数，不断言精确毫秒。
- **`ProviderOutcome.attempts` 口径**：含首发；与 P02-07 的 `attempts` 列同口径（一条断言盯住）。
- **回退**：删除新模块；`ProviderClient` 未接线到引擎（P04），revert 无连带。
