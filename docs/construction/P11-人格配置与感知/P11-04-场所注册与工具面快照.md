## 目标

场所从“入口各自拼凑”变成一张编译期注册表加运行值：`Venue { kind, trust, caps, interactive }`、`VenueCaps`、`VenueDecl`（配额类别、`supersede_on_new`、合并策略、上下文档案）全部集中定义；`[venues.<kind>]` 配置只能收窄不能放宽。会话创建时冻结 `SessionSurface`（principal、场所、persona 代际、工具面、`surface_hash`、模型绑定、system 字节、加载模式），加载时从库读取、不重算；跨入口继续同一会话时 Surface 不变、trust 不足返回 `VenueMismatch`。做完之后：工具面编译是纯函数（同输入同 `surface_hash`），换 persona id 走新会话（`parent_session_id`），会话内切换工具面不存在。

## 范围

- 做：
  - `Venue`、`VenueKind`（`Tui`、`Web`、`Cli`、`Desktop`、`Connector{platform, conversation}`、`Room`、`Timer`、`Job`、`Subagent`、`Review`、`Mesh`）、`VenueCaps`（`questions`、`markdown`、`images_out`、`files_out`、`streaming`、`max_message_chars`）。
  - 注册表常量（12 §6.2 两张表）：每种 kind 的 trust 来源（代码判定，不读平台昵称）、interactive、questions、配额类别、`supersede_on_new`、合并策略（群聊连续消息合并上限 20 条，细节归 16）、`context_profile`（P08 的尾巴预算接缝核对，不另造来源）。
  - `[venues.<kind>]` 收窄校验：放宽（例如给群聊开 `questions`）在 `validate()` 报错（P11-01 的校验扩展）。
  - 工具面编译接缝（复用 07 §5 的实现）：输入只有 `(PersonaSnapshot, Venue, ConfigSnapshot 的 NewSession 类字段, 工具注册表)`，纯函数；`surface_hash`、`LoadingMode` 一并进 `SessionSurface`。
  - 会话创建冻结：写 `sessions` 的 `WriteOnce` 列 + `system_blob`；会话加载从库读取；principal 编码沿用 v1（10 §4.4），由网关 `Caller` 推导（13 §8.4）。
  - 准入与继续：principal 必须等于会话 principal；场所 trust 不得低于创建时 trust，否则 `VenueMismatch`（03 §4 的拒绝路径）；连接器会话只能从同一 `session_bindings` 键进入。
  - 换 Surface 的三条路径：新建会话；压缩采用新 persona 代际（P11-03 已接）；`/persona reload` 或 `/model` 切换（记 `session_model_changes`、`ModelBindingChange` 冷启动）。换 persona id = 新会话 + `parent_session_id`。
  - `ToolSurface` 失败关闭核对：工具面编译失败（超预算、非法组合）→ 会话创建失败，不降级。
- 不做：
  - system 段渲染（P11-06）；感知与 doctor（P11-05）；`/model` 的 TUI 浮层与模型选择 UX（P09 / P11 遗留）；连接器侧（P14）与 mesh 侧（P15）的 Venue 构造；v1 主动发言与语音的场所登记（回归时先登记，见 12 §6.2）。

## 接口草案

草案，以实现为准。

```rust
pub struct Venue { pub kind: VenueKind, pub trust: Trust, pub caps: VenueCaps, pub interactive: bool }
pub enum VenueKind { Tui, Web, Cli, Desktop, Connector { platform: PlatformId, conversation: ConversationKind },
    Room { room: RoomId }, Timer, Job, Subagent, Review, Mesh { device: DeviceId } }
pub struct VenueDecl { pub quota: QuotaClass, pub supersede_on_new: bool,
    pub coalesce: Option<CoalescePolicy>, pub context_profile: ContextProfile }

pub struct SessionSurface {
    pub principal: Principal, pub venue: Venue, pub persona: (PersonaId, u32, PromptVariant),
    pub tool_surface: Arc<ToolSurface>, pub surface_hash: SurfaceHash,
    pub model: ModelBinding, pub system: SystemBytes, pub loading_mode: LoadingMode,
}

/// 纯函数：同输入必须同 `surface_hash`（12 §7.1）。
pub fn compile_surface(persona: &PersonaSnapshot, venue: &Venue, cfg: &ConfigSnapshot,
    registry: &ToolRegistry) -> Result<ToolSurface, SurfaceError>;
```

## 实施步骤

1. 值类型与注册表常量表；`[venues]` 收窄校验（先写「放宽报错」用例）。
2. `compile_surface` 纯函数核对与 `surface_hash` 复算测试（同输入同哈希）。
3. 会话创建冻结与加载读取；`sessions` 冻结列触发器核对。
4. 准入：principal 相等 + trust 单调（`VenueMismatch`）；连接器绑定键核对。
5. 继续与换 Surface 三路径；`/model` 切换的冷启动记录核对。
6. `cargo xtask check`、`cargo test -p gqy-engine -p gqy-core`；提交：`feat(engine): 场所注册与会话 Surface 快照`。

## 测试与守护

- **跨入口**：TUI 创建的会话从 Web 继续，`surface_hash` 不变；成员账号提交到 owner 会话返回 `VenueMismatch`（去掉 trust 检查，红）。
- **冻结**：会话创建后改 persona、`[venues]`、`tools.loading_mode`，10 轮请求 tools 与 system 字节不变。
- **纯函数**：同一 `(persona, venue, cfg, registry)` 编译两次 → `surface_hash` 相同；注册顺序打乱后仍相同（04 §8 排序规则）。
- **收窄**：`[venues.connector]` 给群聊放宽 `questions` → `validate()` 报错（去掉校验，红）。
- **换 persona id**：`/persona` 换到另一个 id → 走新会话且 `parent_session_id` 正确；在会话内改 id 的路径不存在。
- **失败关闭**：工具面超预算 / 非法组合 → 会话创建失败并给英文可读错误，不写半成品 `SessionSurface`。
- 先红后绿对照（PR 贴输出）：去掉 `VenueMismatch` 检查、把编译纯函数改为每回合重算各一次。
