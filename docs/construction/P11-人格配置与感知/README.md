# P11 · 人格配置与感知

> 状态：【规划】。本阶段把 12 号设计与 09 号设计落成：完整配置模式与热加载、单写者保存与密钥、persona 目录与代际、场所注册与会话 Surface 快照、感知矩阵与 `gqy doctor`、system 分段组装与 i18n。做到底：**没有“模式”，只有 persona**；配置默认值只有一个来源；模型看到的字节与 `gqy doctor --model-view` 看到的是同一份渲染。

## 阶段目标

（与施工图 `plan-data` 同文）完整配置模式与热加载、persona 代际、场所与工具面快照、感知提供者、system 组装、i18n。做完之后：

- 配置默认值只在 `gqy-config` 出现一次：JSON Schema、TS 类型、带注释默认配置三样产物 CI 无漂移；保存只有一个写者，`If-Match` 不一致返回 409，secret 不会被并发保存回滚（v1 教训）；
- 每个字段声明生效时机（`NextTurn` / `NewSession` / `Restart`），会改前缀字节的一律不是 `NextTurn`——逐字段测试让下一轮请求仍是上一轮的字节前缀延伸（04 门禁）；
- persona 是唯一的配置单位：`dev` 只是启用集不同的 persona，代码里没有 `AgentMode`；复制 `dev` 改名后 `surface_hash` 相同；
- 会话创建时冻结 `SessionSurface`（principal、场所、persona 代际、工具面、system 字节），跨入口继续不变；场所 trust 不足返回 `VenueMismatch`，不降级执行；
- 感知四维（Host / Workspace / Origin / Context）先成为类型化事实，再经唯一渲染函数变成模型可见文本；同一回合内尾部字节恒定；
- system 八节按枚举顺序确定性渲染、空节省略；模型可见文本英文集中在各 crate 的 `model_text` 模块并由 CJK 扫描门禁守护；界面文本走 i18n。
