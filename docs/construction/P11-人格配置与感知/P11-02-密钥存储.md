## 目标

密钥只以引用进入系统：配置里只有 `key_ref = "secret:<name>"`；`secrets.toml`（0600）为默认后端，`keychain` 为可选后端且不可用时**报错不回退明文**；`GQY2_SECRET_<NAME>` 可覆盖同名 secret；API 只提供写入与存在性查询，永不回传明文。同时把 `redact_known_secrets` 变成“文本进账本”的唯一脱敏点（08 §9.3），`Secret<T>` 的 `Debug`/`Display` 只输出 `***`。做完之后：日志、doctor、导出、备份、账本四处都找不到已知密钥值（canary 测试钉住）。

## 范围

- 做：
  - `SecretBackend` trait 与实现：`File`（默认；`config/secrets.toml`，0600，单写者原子写，流程同 P11-01 §3.4）、`Keychain`（macOS Keychain / Linux Secret Service：只做可用性探测与存取骨架，不可用时返回错误；Q-12-1 拍板前默认仍是 `file`）。
  - 环境覆盖：`GQY2_SECRET_<NAME>`（D-01 前缀）优先于文件，供 CI 与容器。
  - `P11-02` 实现 P02-08 定义的 `SecretResolver`：`resolve(&SecretRef) -> SecretString`；`KeyId`（指纹）由 P02-08 的 `KeyPool` 消费；解析结果不进日志。
  - 存在性查询：`{ name, set: true, hint: "sk-…a1b2" }`（只含头尾）＋ 写入 `PUT /config/secrets/{name}`（只写；响应不回显）。
  - `redact_known_secrets(text)`：按当前全部已知值的**精确匹配**替换为 `[REDACTED:<name>]`；接入账本写入前（工具结果、错误信息、感知块、钩子输出）、`gqy doctor` 输出、tracing 格式化层（`Secret<T>` 的 `Debug` = `***`）。边界如实写明：只能挡住已知值，不是“看起来像密钥”的识别器（08 §9.3）。
  - `gqy secret set/list/rm`；`validate()` 的 `key_ref` 存在性检查接上（P11-01 已留接口）；启动时 secrets 文件权限宽于 0600 → 收紧并 `warn`。
- 不做：
  - 多 key 轮转与冷却逻辑（06 / P02-08 已实现，本单只供值）；钥匙串的完整平台实现待 Q-12-1 拍板后补（拍板前接口与探测就位）；`gqy export` / 备份的脱敏工具（10 §11 已定规则，P16 落地时核对）。

## 接口草案

草案，以实现为准。

```rust
pub trait SecretBackend: Send + Sync {
    fn get(&self, name: &str) -> Result<Option<SecretString>, SecretError>;
    fn set(&self, name: &str, value: SecretString) -> Result<(), SecretError>;
    fn remove(&self, name: &str) -> Result<(), SecretError>;
    fn hint(&self, name: &str) -> Result<Option<String>, SecretError>;   // 只含头尾 4 位
}

pub struct SecretRegistry { /* 启动与重载时快照：(name, SecretString) */ }
impl SecretRegistry { pub fn redact(&self, text: &str) -> String; }      // [REDACTED:<name>]
```

## 实施步骤

1. `Secret<T>` 与 `redact_known_secrets`（先写「canary 出现原值 → 红」）。
2. 文件后端 + 原子写 + 权限收紧；环境覆盖合并；`gqy secret set`。
3. `SecretResolver` 接上 provider 的 `KeyPool` 替身位置。
4. `PUT /config/secrets/{name}` 与存在性查询；`validate()` 的 `key_ref` 检查接上。
5. 脱敏接入账本写入前、doctor、tracing；`cargo xtask check`；提交：`feat(config): 密钥存储与脱敏单一出口`。

## 测试与守护

- **canary（19 §3.5）**：配置含已知假密钥 `sk-test-CANARY…`，跑一个完整回合（含失败重试与供应商错误），扫描 `logs/` 全部文件、stderr 捕获、账本、审计、doctor 输出，断言都不含该字符串；把 `Secret` 的 `Debug` 改回派生，此测试红。
- **明文拒绝**：配置文件里直接写 `api_key`/明文 → 校验失败并给 `gqy secret set` 提示。
- **API 不回显**：查询响应不含明文；`hint` 只含头尾（夹具断言）。
- **不可用不回退**：把后端设为 `keychain` 且探测为不可用 → 解析报错，回退到文件的行为不存在（去掉报错分支，红）。
- **并发保存**：两个写入同时提交 → 单写者串行、最终值可解释（不出现互相回滚）。
- **环境覆盖**：`GQY2_SECRET_<NAME>` 设置后优先于文件；未设置时用文件值。
- 先红后绿对照（PR 贴输出）：去掉脱敏、把 `keychain` 不可用改为回退文件各一次。
