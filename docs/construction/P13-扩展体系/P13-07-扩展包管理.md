## 目标

`gqy ext install/list/update/remove/verify/rollback` 可用，扩展包成为可信边界的落点：安装 = 下载到 `<data>/extensions/.staging/` → 校验清单与上限（≤ 2,000 个文件、≤ 64 MiB）→ 计算规范化内容哈希（路径排序、仅内容与可执行位）→ **展示能力声明并等用户确认**（默认 `require_capability_confirm = true`）→ 原子移动到 `<data>/extensions/<name>/` → 写锁文件 → 后台刷新来源（P13-04/05/06 接上）；启动时校验内容哈希，不符（被手工修改或篡改）→ 该包被禁用、doctor 报 `content_hash mismatch`，`gqy ext verify --accept` 或重装才恢复；**升级时能力扩大必须再次确认**（未确认 = 安装中止且旧版本仍在）；升级成功后旧版本保留一个副本，可 `gqy ext rollback`；扩展数据写在 `<data>/extensions-data/<name>/`，扩展不能直接写 `gqy.db`。

## 范围

- 做：
  - 清单：`gqy-extension.toml` 的 `[package]`（`name` / `version` semver / `kind: extension | persona` / `description` / `requires-gqy` / `license`）、`[provides]`（`skills` / `scripts` / `mcp` 片段（含 `[[mcp.servers]]`）/ `personas`）、`[capabilities]`（`fs` / `network` / `exec` / `platforms`）；`requires-gqy` 不满足时拒绝并给出期望与实际。
  - 来源：`<path>`、`git-url[@rev]`（记录解析后的完整提交号）、`tarball-url#sha256=…`（下载后校验 sha256）；v1 的 tap 索引不做（Q-18-2）。
  - 安装流水线与锁文件 `<data>/extensions/gqy-extensions.lock`（`name` / `version` / `source` / `rev` / `content_hash` / `capabilities_hash` / `installed_at` / `approved_capabilities` 照 18 §7.2）。
  - 能力确认：确认内容用 doctor 同款摘要（fs / network / exec 解释器 / platforms / 需要单独确认的 MCP server 片段）；`--yes` 只在能力与上次一致时接受。
  - 启动校验与禁用；`verify --accept` 只接受哈希变化并写审计，不静默通过。
  - 升级（能力 diff、原子替换、旧副本保留、rollback）与卸载（保留 `extensions-data/`，打印路径；提示 20 的导入归属）。
  - `[provides]` 分发：技能 / 脚本 / MCP 片段进入对应来源（刷新由 P13-04/05/06 的扫描器完成）；`kind = persona` 的包把 persona 目录放进 persona 区，代际切换照 12 §5.4 生效；非法路径（`..`、绝对路径、指向包外的符号链接）拒绝安装。
  - 扩展数据目录创建（权限 0700）与备份核对（10 §9.1 已登记 `extensions-data`）。
  - 配置：`[extensions].require_capability_confirm` = true。
- 不做：
  - 签名与 `gqy ext trust`（Q-18-1 第二阶段，第一版不做任何签名校验代码路径）；
  - tap / 商店（Q-18-2）；
  - 包提供钩子（Q-18-3）；
  - v1 伴侣数据的实际迁移（P16 / P20；本单只保证目录存在与备份包含）。

## 接口草案

草案，以实现为准。

```rust
pub struct ExtManifest { pub package: PackageMeta, pub provides: Provides, pub capabilities: Capabilities }

/// 规范化文件树哈希：路径排序、内容与可执行位；确定性（顺序无关）。
pub fn content_hash(root: &Path) -> Result<ContentHash, HashError>;

pub enum InstallOutcome {
    Installed { name: String, hash: ContentHash },
    NeedsCapabilityConfirm { diff: CapabilityDiff },
    Rejected { reason: InstallError },
}

pub async fn install(source: ExtSource, accept: Option<CapabilityHash>) -> Result<InstallOutcome, InstallError>;
```

## 实施步骤

1. 清单解析与上限校验（先写「路径逃逸拒绝」用例）。
2. 规范化内容哈希与锁文件读写；启动校验与禁用。
3. 安装流水线与 staging 原子移动；能力确认交互（CLI）。
4. 升级 / rollback / remove；`[provides]` 分发与 persona 类包。
5. `extensions-data` 创建与备份核对；`cargo xtask check`；提交：`feat(ext): 扩展包管理`。

## 测试与守护

- **篡改**：安装后修改一个文件 → 启动禁用 + doctor `content_hash mismatch`；`verify --accept` 后恢复（去掉校验，红）。
- **升级确认**：`network: false → true` 未确认 → 安装中止、旧版本仍在（断言目录与锁未变）；确认后原子替换且旧版本可 rollback（两条用例）。
- **上限**：2,001 个文件 / 65 MiB 拒绝并给期望与实际；去掉上限检查，红。
- **路径逃逸**：`provides` 指向 `../`、绝对路径、指向包外的符号链接 → 拒绝。
- **确定性**：同目录树两次哈希一致；遍历顺序打乱结果不变（排序保证）。
- **锁文件**：`approved_capabilities` 与安装时确认的一致；手工改哈希后重装校验失败，红。
- 先红后绿对照（PR 贴输出）：去掉内容哈希启动校验、去掉升级能力确认各一次。

## 风险与回退

- **首次安装信任（TOFU）**：如实写进确认文案，不伪造“已验证发布者”；能力摘要必须可读。
- **P13-04/05/06 未就位**：安装仍可完成（`[provides]` 落盘），来源刷新随其落地接线；doctor 提示“包已安装、来源未启用”。
- **回退**：`remove` + 锁文件回退；`extensions-data/` 不删（用户数据，铁律 9）。
