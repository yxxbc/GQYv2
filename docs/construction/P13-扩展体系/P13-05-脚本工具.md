## 目标

脚本成为工具：`<scope>/scripts/` 下的单文件以“shebang 后的注释块 + `键: 值`”声明头部（`id` / `description` / `summary` / `parameters` / `argv` / `timeout` / `trust` / `permission` / `platform` / `group` / `example` / `requires`）；未知注释行跳过（v1 `# -*- coding: utf-8 -*-` 截断头部的事故有回归夹具）、`parameters` 非法 JSON 则工具不编译（不回退空 schema）；解析结果进入 `ToolSource("scripts")` 的**内存快照**，后台扫描（去抖 / 全量校验）刷新，不在回合路径上；工具名 `script_<id>`；调用时参数收口后 JSON 写 stdin（写读并发，脚本不读 stdin 也不死锁）、`argv=flags` 展开 `--key=value`、在 08 §6.3 的子进程环境中以独立进程组运行、按 `timeout`（默认 60 / 上限 600）终止；效果类别由 `permission` 决定，`trust` 只能收紧；stdout 为结果文本，`GQY-IMAGE: <path> | <caption>` 整行摘出为图片内容（路径越界 / 超 10 MiB / 格式不符时替换为 `[image rejected: <reason>]`）；解释器缺失或平台不满足 → 不编译并在 doctor 显示“缺失增强能力”，不静默失败。

## 范围

- 做：
  - 头部解析器：紧跟 shebang 的注释块；未知行跳过；只读前 32 KiB；`id` 默认文件名去扩展名（命名冲突照 07 §4.3）；`summary` 缺省取 `description` 第一句截断。
  - 来源与快照：built-in / global / persona 三个可信来源（来源 id `scripts`）；目录 / 头部扫描在后台（inotify / FSEvents 去抖 2 s，另每 `rescan_interval_min`（默认 5）全量校验）；`ToolSource::snapshot` 只读内存。
  - 执行器：stdin 并发写读；`argv=flags`；环境白名单与私有临时目录；进程组 + 超时按 02 §6 终止（SIGTERM → 2 s → SIGKILL）；退出码非 0 → `error[upstream]: script_<id> exited with 2: <stderr 尾部 2,000 字符>`。
  - 输出：stdout 结果文本（截断照 07 §8）；`GQY-IMAGE` 提取与四类边界（合法 / 工作区外 / 超大 / 非图片）。
  - 效果与信任映射（18 §9）：`read-only` → `ReadOnly`（只读沙盒强制）；`workspace` → `Workspace`；`network` → `Network`（doctor 如实写“无法强制”）；`full` → `Exec`（仅 Owner 可批准 + doctor 警告）；`trust` 只收紧安装作用域默认值；External 场所不编译 `Exec` 类脚本，`read-only + trust: external` 可以编译。
  - `platform` / `requires` / `group` / `example` 进 `meta`，复用 07 §5.1 的筛选与 §6 的 stub。
  - 配置：`[scripts].timeout_default_s` = 60、`timeout_max_s` = 600、`rescan_interval_min` = 5 落进 `gqy-config`。
- 不做：
  - 扩展包安装与内容哈希（P13-07）；
  - workspace 脚本来源（与 Q-18-4 的技能同口径，拍板前不加）；
  - 脚本转后台作业（`JobKind::Script` 触发条件未定，见 README 复核第 2 条；本单脚本超时即按失败处理）；
  - 沙盒内脚本回调 daemon 的桥（Q-08-4 第一版不提供）。

## 接口草案

草案，以实现为准。

```rust
pub struct ScriptHeader { pub id: String, pub description: String, pub parameters: serde_json::Value,
    pub argv: ArgvMode, pub timeout_s: u32, pub trust: Option<Trust>, pub permission: Permission,
    pub platform: Option<Vec<String>>, pub group: Option<String> }

/// 跳过未知注释行；只读前 32 KiB；错误带行号与键名。
pub fn parse_header(bytes: &[u8]) -> Result<ScriptHeader, HeaderError>;

pub enum ImageOutcome { Image { path: PathBuf, caption: Option<String> }, Rejected { reason: String } }
```

## 实施步骤

1. 头部解析器与夹具（先写「编码声明行不终止解析」红用例）。
2. 来源扫描与快照；`ToolSource("scripts")` 注册。
3. 执行器：stdin 并发写读、argv、环境、进程组、超时。
4. 效果映射与信任；External 过滤。
5. `GQY-IMAGE` 四例与图片内容回传。
6. `cargo xtask check`；提交：`feat(ext): 脚本工具`。

## 测试与守护

- **头部夹具**：编码声明行、`//` 注释、中文键名（`描述`）、缺 description、非法 parameters、超 32 KiB 各一例；去掉“跳过未知行”实现，第一例红（v1 回归）。
- **不死锁**：不读 stdin 的脚本仍能完成（写读并发）；改成“先写完再读”且管道填满，红。
- **沙盒映射**：映射表每一行一个用例；`read-only` 脚本尝试写工作区被拒（Landlock 生效平台上）；去掉映射改为固定策略，红。
- **`GQY-IMAGE`**：四例结果逐字断言；越界路径替换为 `[image rejected: …]`。
- **解释器缺失**：`#!/usr/bin/env python3` 而 PATH 无 python3 → 工具不编译、doctor 显示原因（不静默失败）。
- **超时**：`timeout` 为 1 s 的脚本 `sleep 10` → 按 02 §6 终止进程组，错误文本含期望 / 实际。
- 先红后绿对照（PR 贴输出）：去掉未知注释行跳过、去掉 `GQY-IMAGE` 路径校验各一次。
