## 目标

一个文本回合从准入到终态跑通唯一一条代码路径：转移核是**纯函数** `next(state, event) -> Result<(RunState, Vec<Effect>), IllegalTransition>`，异步外壳 `run_turn` 只负责把 Effect 落到 IO（`ledger.plan` → `fossilize_pending` → `provider.run` → 落账 → 安全点）。做完之后：状态机的每个转移都有穷举测试；任何非 `Completed` 终态都在同一个事务里完成配对收尾；`finish_reason=length` 的截断规则生效；插话只在安全点落账。

## 范围

- 做：
  - `RunState`（照 03 §3.1，含 `Queued` 的表示口径）、`RunEvent`、`Effect`、`IllegalTransition`、`RunOutcome`。
  - 转移核 `next(...)`：覆盖 03 §3.2 转移表的每一行；非法转移返回错误不 panic；**所有** `(状态, 事件)` 组合有穷举断言。
  - 异步外壳 `run_turn(ctx, deps)`：照 03 §6.1 骨架；三步 `plan → fossilize → provider.run` 接 P03 的 `LedgerRepo`（`freeze` 注入 P03-05 的 `ChainComputerImpl`）；`append_assistant`、`append_tool_results`、`append_steers` 的调用时机与事务边界照 03 §3.3/§6.2。
  - 终态收尾（03 §3.3）：进入任何非 `Completed` 终态时，同一事务里补合成工具结果（文案按效果类别分档，先按 03 §13.1 的两档立接口，P06 提供完整类目）、追加 `TurnAborted` 注记、被中断的流式文本只写 `Display` 且 `partial=true`。
  - `finish_reason=length` 规则（03 §7）：有工具调用 → 零执行 + 逐调用合成结果 + 连续 `max_length_rejections`（默认 2）次后 `Failed(OutputTruncated)`；无工具调用 → `Completed` 且 `truncated: true`。
  - 插话安全点：本批工具结果全部落账之后、下一次 `Planning` 之前，`ctx.steer_inbox.drain()` 落账并 `steer.applied`；运行以「无工具」完成时剩余插话转队首（与 P04-03 的队列接口协作）。
  - 预算检查点：`TurnBudget` 类型的**字段与检查点**在本单冻结（照 03 §7：`max_requests`/`max_tool_calls`/`max_wall`/`max_length_rejections`，子代理档位留字段）；计量实现（墙钟豁免审批、计数器）归 P04-05，本单提供计数器 + `TestClock` 的测试形态并接通 `Cancelled(Budget)` 路径。
  - 失败映射：`ProviderError → FailureKind → RunFailure`（03 §12）与 `run.failed` 的事件字段（13 §6.2）；工具失败不升级为运行失败（P06 起）。
  - 用量接线：每次请求结束（成功/失败/取消都写）填充 P02-07 的 `UsageLogContext`（纪元、`prefix_hash`、`prefix_bytes` 来自 P03 的冻结结果）并写 P03-05 的请求记录。
  - 接缝 trait（真实现归后续阶段，本单给 **仅测试用** 的替身并在名字与文档里标注防误用）：`Compactor`（P08）、`ToolCycle`（P06/P07）。
  - P03-06 门禁的四个引擎场景（插话、取消、流中断、`length`）从 `#[ignore]` 骨架改成断言。
- 不做：
  - 真实工具执行与审批（P06/P07）：本单的 `NoToolsSeam` 对非空工具调用返回一条带「工具系统未接线」语义的合成结果，只用于测试，**不是发布形态**（P06-08 接线后删除）。
  - 压缩算法与溢出恢复（P08）：本单只实现转移表里的 `Compacting` 状态与屏障一次的口径，压缩器是替身。
  - 取消树的构建与 1 秒停止时限（P04-05）、事件总线实现（P04-06，本单用测试 sink）。
  - 子代理、作业、定时器（P13）。

## 接口草案

草案，以实现为准。

```rust
// gqy-engine/src/machine.rs
pub enum RunState { Queued, Planning, Compacting, Streaming, AwaitingApproval, ExecutingTools,
                    Completed, Failed(RunFailure), Cancelled(CancelReason), Interrupted }

pub enum RunEvent {
    Admitted, PlanReady { request_seq: u32 },
    NeedCompaction { stage: Stage, trigger: Trigger }, CompactionDone { skipped: bool },
    StreamStarted, StreamEnded { finish: FinishReason, has_tool_calls: bool },
    QuestionsAnswered { denied: u32 }, BatchDone,
    CancelRequested { reason: CancelReason }, BudgetExhausted, OverflowBarrier { used: bool },
}

/// 纯函数：不读时钟、不碰 IO；`Vec<Effect>` 只描述外壳要做的事（03 §3.2）。
pub fn next(state: &RunState, ev: &RunEvent)
    -> Result<(RunState, Vec<Effect>), IllegalTransition>;

pub enum Effect {
    Plan, Fossilize, SendRequest, AskApproval { calls: Vec<CallId> }, ExecuteBatch { calls: Vec<CallId> },
    AppendAssistant, AppendResults, AppendSteers, EnterTerminal { finalize: TerminalFinalize },
    Emit(EngineEvent),
}

// gqy-engine/src/run_loop.rs
pub struct EngineDeps<'a> {
    pub ledger: &'a LedgerRepo, pub provider: &'a ProviderClient,
    pub compactor: &'a dyn Compactor, pub tools: &'a dyn ToolCycle,
    pub events: EventSink, pub clock: Arc<dyn Clock>,
}
pub async fn run_turn(ctx: Arc<TurnContext>, deps: EngineDeps<'_>) -> RunOutcome;

// gqy-engine/src/seams.rs（仅测试替换实现；真实现归 P08 / P06+P07）
pub trait Compactor: Send + Sync {
    async fn needs(&self, ctx: &TurnContext, stage: Stage) -> bool;
    async fn run_in_run(&self, ctx: &TurnContext, trigger: Trigger) -> Result<(), CompactError>;
}
pub trait ToolCycle: Send + Sync {
    async fn execute_batch(&self, ctx: &TurnContext, calls: &[ToolCall]) -> Vec<ToolResultDraft>;
}
```

## 测试与守护

- **状态机穷举**：所有 `(RunState, RunEvent)` 组合断言；删掉任意一行转移，测试红（03 §16 第一条）。
- **配对完整性（属性测试）**：随机注入取消、流错误、`length` 截断，断言账本中每个 `tool_call` 恰有一个 `tool_result`；去掉终态收尾的第 1 步必红；账本只追加、不回滚。
- **`length` 规则**：mock 返回 `finish_reason=length` + 两个工具调用 → 零执行、两条合成结果；连续 2 次 → `Failed(OutputTruncated)`；无工具调用的截断 → `Completed{truncated: true}`。
- **插话安全点**：工具执行中途插话，断言插话条目位于该批全部结果之后；随后复跑 P03-06 的字节前缀门禁。
- **失败映射**：表驱动 fixture（认证、限流耗尽、流停滞、协议畸形、溢出等）逐项对照 `FailureKind` 与 `run.failed` 字段。
- **预算**：`max_requests` 用尽 → `Cancelled(Budget)` 且收尾完整（墙钟与审批豁免的完整计量在 P04-05 的测试里）。
- **屏障**：一次溢出错误且本回合未恢复过、尚无输出 → 进 `Compacting`（假压缩器）；第二次溢出 → `Failed(ContextOverflow)`。
- **无嵌套重试**：断言一次请求对应恰一次 `provider.run` 调用（重试全在供应商层，03 §8）。
- 先红后绿对照（PR 贴输出）：删一行转移、去掉终态收尾的合成结果各一次。

## 风险与回退

- **「纯转移核」被侵蚀**：Effect 只描述、不执行；一旦 Effect 变体里出现句柄或 IO 调用，停下来改设计（03 §3.2 的约束）。
- **与 P03 接口**：`LedgerRepo`/`ChainComputerImpl` 的签名若不足，先改 04 的草案再动代码。
- **P03-06 门禁耗时**：四场景接真引擎后若明显拖慢 CI，按 P03 遗留 3 的口径拆到 Linux 长跑作业（先实测再决定）。
- **回退**：`machine.rs`/`run_loop.rs`/`failure.rs`/`seams.rs` 是新文件，revert 即可；P03-06 的断言改动随单回退。
