## 目标

事件总线的唯一实现：会话内单调 `seq`、**先落库再广播**、每订阅者有界（1024）溢出即 `stream.resync_required{reason: lagged}`、增量事件按 50 ms / 4 KiB 合并、`events` 表持久化、`replay`（上限 5000）与 `as_of_seq`。做完之后，P05 的 SSE、JSON 拉取与 `gqy ask` 都复用同一实现；「前端 resync 死循环」在协议层有界。

## 范围

- 做：
  - 强类型 `EngineEvent`：覆盖 03 §11 的全部引擎事件（run / queue 与代际 / steer / request / 流 / 工具 / 问题 / 上下文 / 子代理 / 作业与定时器 / 会话 / 供应商），**规范名与字段照 13 §6.2**（全局流与会话元数据事件随 P05-01 扩展）。
  - `EventSink`（P02-01 立的最小定义在此扩展为具体类型，**字段只增**）与 `EventBus`；每会话一条发送序列 + 独立全局序列。
  - 落库：按 13 §6.2 的「持久化」列写 `events` 表（不可 UPDATE；`assistant.delta`/`reasoning.delta`/`tool.output` 也先落库再广播；保留期删除只提供 API，作业在 P13 按 10 §9.3 执行）。
  - 背压：每订阅者 1024（有界通道，02 §7）；溢出 → 发 `stream.resync_required{reason: lagged}` 并关闭该订阅，**不阻塞生产者**；同一订阅连续两次 lagged（间隔 < 10 s）→ 降级为只推持久化事件直到重连。
  - 合并：`assistant.delta` / `reasoning.delta` / `tool.output` 按 `(run, 类型, call)` 合并，窗口 50 ms **或** 4 KiB（先到者触发；注入 `Clock`）；合并后分配一个 seq、落库、广播（13 §6.3）。
  - 补拉：`replay(after, limit ≤ replay_max 5000)`；被删区间 / 太远 → `resync_required{reason: purged|too_far}`；`as_of_seq(session)` 返回生成时刻已广播的最大 seq（供 P04-02 的 `Snapshot` 与 P05 的 `view`，13 §6.4）。
  - 序列化接缝：`EnvelopeCodec`（`EngineEvent` → 13 §6.1 形状的 JSON）；本单提供测试 codec，**P05-01 换成 `gqy-protocol` 的唯一实现**（字段只增由后者守护，替换必须写进该单的 PR 描述）。
  - 指标：订阅数、lagged 次数、缓冲深度（供 `/daemon/status`，19 §3.6）。
- 不做：
  - HTTP/SSE/JSON 拉取端点与心跳（P05-02）、TS 类型生成（P05-01/P10）。
  - 保留期作业调度（P13）、连接器投递幂等与水位（P14）。
  - 会话元数据事件（`session.created` 等）的**产生**：源在 P05-01 起的网关侧；本单只保证总线能承载。

## 测试与守护

- **seq 单调**：多生产者并发写同一会话，seq 严格递增；全局流独立空间、不依赖会话数。
- **先落库再广播**：订阅者收到的每个持久化事件都能在 `events` 表查到（把广播挪到落库前必红）。
- **lagged**：慢订阅者（不读）→ 收到 `stream.resync_required{lagged}` 且订阅被关闭；生产者耗时不受影响（断言上界）；连续两次 lagged → 降级只推持久化事件。
- **合并**：50 ms 窗口内多条 delta → 一条（seq 连续、内容拼接正确）；4 KiB 先到 → 立即一条；不同 `call` 不合并。
- **补拉**：`replay_max` 边界（5000 / 5001）；被删区间 → `purged`；过远 → `too_far`。
- **`as_of_seq` 一致性**：view 生成之后的事件都 `> as_of_seq`，不重复不遗漏（13 §6.4 的不变量）。
- **不可 UPDATE**：`events` 表触发器拒绝改行（复用 P01-06 的触发器测试路径）。
- 先红后绿对照（PR 贴输出）：把广播改到落库前、把订阅缓冲改成无界各一次。
