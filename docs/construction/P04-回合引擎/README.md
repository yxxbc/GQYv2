# P04 · 回合引擎

> 状态：【规划】。本阶段把 02 的所有权模型与 03 的回合语义落成一个可测试、可观察、可取消的引擎：TurnContext 与会话快照、Supervisor 与 SessionActor、准入/排队/代际、回合状态机、取消树与预算、事件总线、停机与启动恢复。
> 创建：AI 助手（Cline 会话），2026-09-28。改动本文件时，按根 `AGENTS.md` 规矩 7 更新这一行：写清谁改的、什么时候改的。

## 阶段目标

TurnContext、会话 actor、Supervisor、准入与排队、状态机、取消、停机、事件总线（与施工图 `plan-data` 同文）。做完之后：

- 一个会话卡住时其他会话照常推进（02 §1 目标 1）：执行权由 `SessionActor` 独占，耗时工作一律 spawn 成子任务（03 §2 的 v1 事故在结构上不可能重演）；
- 回合状态机的转移核是**纯函数**（03 §3.2），全表穷举可测；异步外壳只负责把 Effect 落到 IO（评审采纳项「纯转移核 + 异步外壳」，docs/reviews/2026-09-28 §6.4）；
- 取消、超时、预算、停机是协议的一部分：从入口一路传播到供应商请求与子进程（02 §5、§6、§9）；
- 事件先落库再广播、会话内单调 `seq`、慢订阅者收到 `resync_required`，为 P05 的 SSE 与 `gqy ask` 提供唯一事件源（02 §7、13 §6）。

## 进入条件

- P03 完成（账本条目、请求规划、化石化、工具面与 surface_hash、前缀链、字节前缀门禁就位）；
- 02 与 03 通读一遍（本阶段设计依据的主干）；`gqy-core`（ID/Clock/规范 JSON）、`gqy-store`（单写者）、`gqy-provider`（`ProviderClient::run`）、`gqy-ledger`、最小 `gqy-config` 已可用。

## 退出条件

- 七张单全部“已完成”；`cargo xtask check/test` 与三平台 CI 绿；
- P03-06 门禁里依赖引擎的四个场景（插话、取消、流中断、`finish_reason=length`）改走真实引擎并有断言；
- P05 可以直接开始：`Supervisor::submit` 是唯一准入入口（02 §3.3），事件总线提供订阅、补拉与 `as_of_seq`（13 §6.4），停机与恢复接口 `shutdown(deadline) -> ShutdownOutcome` / `recover(…) -> RecoverySummary` 可供 `gqy-daemon` 组装处调用。

## 遗留与发现

> 施工过程中发现的范围外问题记在这里；写单时发现、需要用户拍板的点也记在这里。

写单时的口径：

1. **待确认项按推荐先行**：Q-03-1（预算耗尽不补发收尾请求）、Q-03-2（子代理深度 1）、Q-03-3（重启时交互式排队项丢弃、非交互按 TTL 保留）、Q-03-4（空闲期不自动压缩）在对应单中按 03 §18 的推荐写进口径并标注「待用户确认」；拍板前不得实现相反行为。
2. **接缝归属**：压缩器（回合内与手动）是 P08；工具分发与审批是 P06/P07；作业与定时器的调度器是 P13-02/03；感知帧的生产是 P11-05；工具面编译与人格快照换面是 P06/P11-04；v1 主动发言与语音没有场所登记前不得出现（12 §6.2）。本阶段只交付接缝 trait 与测试替身。
3. **子代理**：03 §9 的子代理、`WakePolicy::OnFinish` 作业唤醒不在本阶段；P04 只保证「带 `parent` 的普通回合」在 `TurnRequest`、队列与快照里是数据，不特判、不开第二条路径。
4. **性能与门禁**：02 §10 的隔离回归、压缩隔离、取消传播、停机测试按「先红后绿」写入对应单；P03-06 的门禁改走真实引擎后，耗时变化要在 P04-04 实测记录（若明显拖慢，与 P03 的遗留 3 一并处理）。
