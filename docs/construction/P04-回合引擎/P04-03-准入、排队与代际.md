## 目标

所有回合发起方（TUI、Web、`gqy ask`、连接器、定时器、作业唤醒、子代理）都走同一条准入路径：构造带 `Venue` 的 `TurnRequest` → `Supervisor::submit` → actor 内做**纯状态转移**的准入判定 → `Admission`。做完之后，「谁能不能起回合、起第几个、排队还是插话、被谁覆盖」都有唯一答案，且判定过程不碰 IO（副作用以 Effect 返回）。

## 范围

- 做：
  - `TurnRequest` / `Admission` / `RejectReason` 类型（照 03 §4；`TurnRequest.venue` 由网关按 12 §6 推导，引擎只消费）。
  - `admit(state, req, now) -> (Admission, Vec<AdmitEffect>)`：顺序照 03 §4——幂等键查重 → principal 与会话冻结值比对（`PrincipalMismatch`）→ 场所配额与全局许可的**判定**（`VenueQuota`）→ 按 `mode` 与会话状态给出 `Started` / `Queued` / `Steered` / `Rejected`；纯函数，不碰 store。
  - 会话队列：有界 FIFO（`session_queue_capacity` 默认 8），满时 `Rejected(QueueFull)`（02 §7 的「拒绝」策略）；排队项落 `turn_queue` 表（字段照 10 §7.4：`run_id/session_id/venue_json/generation/mode/input_summary/input_blob/idempotency_key/state/enqueued_at/left_at`），出队/取消/丢弃只写 `state` 不删行。
  - 代际：`generation: u64` 单调；`mode = Interrupt` 与场所 `supersede_on_new = true`（12 §6.2 表）各让代际加一；加一时队列中旧代际项以 `Cancelled(Superseded)` 结束、当前运行以 `Superseded` 取消；运行终态时比较代际，**过期运行的对外投递被抑制**（提供布尔标志/查询接口，实际抑制点归连接器与通知的投递层，P14/P13），并发 `generation.superseded`（字段照 13 §6.2）。
  - 插话：`SteerInbox`（有界 8，`steer_inbox_capacity`）；`Admission::Steered { into }`；发 `steer.accepted`。**安全点落账**（`steer.applied`、`append_steers`）在 P04-04；本单只保证收件箱语义与「插话永不插在 tool_call 与 tool_result 之间」的接口位置。
  - 资源：`RunPermits`——全局活动回合许可（`Semaphore`，`max_active_runs` 默认 16）与场所配额类别计数（Interactive / Connector 8 / Timer 4 / Internal；12 §6.2、02 §3.1）。提供 `acquire`/`release` 与「`AwaitingApproval` 期间释放、回答后重新获取、终态释放」的钩子点（调用点在 P04-04）。
  - 重启重建接口 `rebuild_after_restart(rows, now)`：交互式场所（Tui/Web/Cli）一律丢弃并 `queue.dropped{reason: restart}`；非交互在 `engine.queue_restart_ttl`（默认 30 min）内按原序重新准入、超时丢弃并记录（03 §13.5）——**待用户确认（Q-03-3）**，确认前按此推荐口径实现；调用方是 P04-07。
  - 合并策略接口 `CoalescePolicy` 的**判定点**（出队时合并相邻同会话连续消息、上限 20 条）；规则细节归 16，本单只留类型与测试替身。
- 不做：
  - 状态机与循环（P04-04）、事件总线的投递实现（P04-06；本单只调用 `EventSink` 接口）。
  - 子代理池与作业（P13）；连接器合并规则细节（16 §8）。
  - `Venue` 的推导（网关侧，13 §8）与场所注册表常量（12 §6.2，P11-01 落配置）。
  - 幂等键在网关层的去重（13），引擎侧只保证「重复提交返回原结果」。

## 接口草案

草案，以实现为准。

```rust
// gqy-engine/src/admission.rs
/// 纯函数：不做 IO；需要的落库/事件/加载以 Effect 返回，由 actor 执行（03 §4）。
pub fn admit(state: &mut SessionState, req: TurnRequest, now: Timestamp)
    -> (Admission, Vec<AdmitEffect>);

pub enum AdmitEffect {
    PersistQueueRow(QueueRow), SpawnRun(RunId), EmitQueueEnqueued { run: RunId, position: u16 },
    EmitGenerationSuperseded { session: SessionId, from: u64, to: u64 },
    CancelQueued { run: RunId, reason: CancelReason }, SuppressDeliveriesBefore { generation: u64 },
}

// gqy-engine/src/permits.rs
pub struct RunPermits { /* global: Arc<Semaphore>, venue: QuotaTable */ }
impl RunPermits {
    pub async fn acquire(&self, venue: &Venue) -> Result<PermitGuard, AdmitRejected>;
    pub fn release_for_approval(&self, guard: PermitGuard) -> ApprovalPause;
    pub async fn resume_after_approval(&self, pause: ApprovalPause) -> Result<PermitGuard, AdmitRejected>;
}
```

## 测试与守护

- **准入顺序**：同一请求依次触发各分支——幂等键重复返回原 `Started`（不新起运行）；principal 不一致 `PrincipalMismatch`；队列满 `QueueFull`；场所配额满 `VenueQuota`；停机标志 `ShuttingDown`；`Steer` 但当前运行不接受 → `SteerNotAccepted`（或按 03 §5.4 转队列，口径写进代码注释）。
- **代际**：连续 3 次 `supersede` 提交，断言只有最后一个运行对外投递（去掉抑制标志必红，03 §16）；旧排队项终态为 `Cancelled(Superseded)`；账本条目保留不回滚（与 02 §5 一致）。
- **队列持久化**：入队行与请求逐项一致；出队/丢弃写 `state` 而不删行（`turn_queue` 触发器会拒绝 DELETE）。
- **重启重建**：交互式三场所（Tui/Web/Cli）丢弃并解释；非交互 TTL 内按原序重排、超 TTL 丢弃并记录（TestClock 推进边界 ±1 s）。
- **许可**：16 个并发运行后第 17 个停在 `Queued`；`AwaitingApproval` 期间许可被释放（用假状态机驱动钩子）；终态释放。
- **插话**：收件箱超过 8 条的策略断言；插话不落账直到安全点（与 P04-04 的联测写在 P04-04）。
- 先红后绿对照（PR 贴输出）：把 `supersede` 的抑制标志去掉、把队列上限改成无界各一次。
