## 目标

取消与上界成为协议的一部分：daemon → session → run → request/tool 的令牌树；取消原因写进运行终态；取消到停止 ≤ 1 秒（模型流）；子进程组按宽限流程终止（SIGTERM → 2 s → SIGKILL → reap；PTY 先 SIGHUP）；`TurnBudget` 的计量实现（墙钟**豁免审批等待**）接通 P04-04 的 `Cancelled(Budget)` 路径。做完之后，「每一处等待都有上界、每一步都能被取消」不再靠自觉，而是有测试与配置校验兜底。

## 范围

- 做：
  - `CancelTree`：`CancellationToken` 树（`daemon` → `session` → `run` → `request`/每个工具调用）；`run` 层带原因槽，终态写入 `CancelReason`（02 §5）。
  - 取消的账本语义（与 P04-04 的路由协同）：已落库条目保留不回滚；未完成的工具调用写「已取消」结果，保持 `tool_call`/`tool_result` 配对。
  - 停止时限：模型流在 1 秒内停读并关闭连接（与 P02-02 的流实现协同，联测写在本单）；子进程按 02 §6 处理；`ProcessTerminator` trait（真实现是 P07-04 的 `gqy-sys`；本单提供 fake，断言调用序列与宽限时长）。
  - `TurnBudget` 的**计量实现**：请求数、工具调用数、墙钟（进入 `AwaitingApproval` 时暂停、回答后恢复）、`max_length_rejections` 计数（由 P04-04 消费）；耗尽返回 `BudgetExhausted` 并走 `Cancelled(Budget)`。
  - 配置：`engine.budget.max_requests` / `max_tool_calls` / `max_wall`（默认 100 / 400 / 2 h；上限 12 h，照 03 §15）；**不可关闭、只能放宽到上限**（02 §6）——越界或 0 在加载时报错，错误写期望值与上限。
  - 超时核对表：把 02 §6 的每一行映射到「实现它的单」（供应商 P02、工具 P06、store P01-04、审批无超时、停机宽限 P04-07……），引擎侧的行写进模块文档；一条测试断言核对的常量表与 02 §6 行数一致（漏一行即红）。
- 不做：
  - 子代理池、嵌套取消与独立许可（P13；父取消传子运行的语义在其中实现）。
  - 长命令软超时转作业（P06-05 的判定、P13 的作业表）、定时器与作业取消（P13）。
  - 停机编排与宽限期总控（P04-07）；信号安装（P05-05）。
  - 压缩的取消算法（P08 复用本单令牌；事务未提交即回滚由 P08 保证）。

## 接口草案

草案，以实现为准。

```rust
// gqy-engine/src/cancel.rs
pub struct CancelTree { daemon: CancellationToken }
impl CancelTree {
    pub fn session(&self, session: &SessionId) -> CancellationToken;
    /// run 令牌挂在 session 下；`CancelSlot` 记录最终原因（先到先得）。
    pub fn run(&self, session: &CancellationToken, run: &RunId) -> (CancellationToken, CancelSlot);
}
pub enum CancelReason { User, Superseded, Timeout, Shutdown, Budget, Admin }

// gqy-sys/src/terminate.rs（接缝；真实现 P07-04）
pub trait ProcessTerminator: Send + Sync {
    /// SIGTERM → 等 2 s → SIGKILL → reap；`pty = true` 时先 SIGHUP（02 §6）。
    fn terminate_group(&self, pgid: i32, pty: bool) -> Result<(), SysError>;
}

// gqy-engine/src/budget.rs
pub struct BudgetMeter { /* clock, started_at, requests, tool_calls, approval_paused */ }
impl BudgetMeter {
    pub fn before_request(&mut self, now: Timestamp) -> Result<(), BudgetExhausted>;
    pub fn note_tool_call(&mut self, now: Timestamp) -> Result<(), BudgetExhausted>;
    pub fn pause_for_approval(&mut self, now: Timestamp);
    pub fn resume_after_approval(&mut self, now: Timestamp);
    pub fn elapsed_excluding_approval(&self, now: Timestamp) -> Duration;
}
```

## 测试与守护

- **取消传播**（02 §10）：取消运行后 1 秒内 mock 流关闭连接（假流记录“停读”时间戳）；去掉令牌接线必红。
- **树形传播**：取消 session → 其下 run/request/工具令牌全部取消；取消 daemon → 全部会话。
- **子进程序列**：fake 记录 SIGTERM →（TestClock 推 2 s）→ SIGKILL → reap；PTY 场景出现 SIGHUP；顺序或时长错必红。
- **预算豁免**：审批停 2 h、总墙钟 3 h 不触发（TestClock 驱动）；`max_requests` / `max_tool_calls` 到达边界 → `Cancelled(Budget)`。
- **配置不可关闭**：`max_wall = 0`、超上限、试图关闭的写法都被拒绝；错误信息含期望值与上限。
- **核对表完整**：02 §6 的每一行都有归属单；映射常量表被测试钉住。
- 先红后绿对照（PR 贴输出）：去掉审批豁免、把 SIGTERM 宽限改成 0 各一次。
