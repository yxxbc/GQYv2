## 目标

聊天室成立：`room_messages(room_id, seq, speaker, text, ts)` 只追加、是唯一真相；每个 persona 成员一个 `hidden = true` 的 `room-member` 会话（场所 `VenueKind::Room{room}`，信任 `Internal`）；轮到成员发言时把 `(last_room_seq, now]` 之间的房间消息打包成一条用户消息（每行 `[HH:MM] <name>: <text>`，`name` 与 `text` 经 `safe_prompt_field`）——只追加新消息、不重写旧内容，成员会话的第 N 次请求是第 N−1 次的字节前缀延伸（04 门禁复用）；默认按成员列表顺序轮流、每轮每人至多发言一次、用户发言后重新开始一轮、轮次上限 `rooms.max_rounds_per_user_message = 3`；房间成员会话工具面为空（无审批、无工具）；房间内使用 persona 公开版提示词（12 §5.6）；`room.message` 事件照 13 §6.2 发；房间可以经连接器对外（群里的一个房间），也可以只在 TUI / Web 中存在（第一版先落 CLI 与引擎）。本单同时执行 **M4「伴侣回归」** 的全量验收并留档。

## 范围

- 做：
  - 房间模型与存储：`room_messages` 只追加（触发器与测试钉住不可 UPDATE / 删行）；`seq` 分配；每成员会话的游标 `last_room_seq`。
  - 最小 CLI：`gqy room create <name> --members <persona>…`、`gqy room add/remove/list`、`gqy room say <room> <text>`（用户发言入口；TUI / Web 界面不在本单，复核第 6 条）。
  - 轮流器：默认顺序、每轮每人至多一次、用户发言重开一轮、上限 3；成员发言经 `Supervisor::submit`（唯一准入，03 §4），无旁路。
  - 喂入与冻结：打包契约（`[HH:MM] <name>: <text>` + 转义）、空区间不发言（无新内容则跳过）；成员会话 system 用公开版 persona 并在创建时冻结；喂入变化只追加新行。
  - 工具全关：成员会话 `VenueCaps` 为空（编译期剔除 + 运行时二次拒绝），无审批路径。
  - 事件与可见性：`room.message`（字段照 13 §6.2）；`hidden` 会话不出现在 `GET /sessions` 默认视图，事件流与审计仍可查。
  - 连接器映射：房间可映射到连接器群会话（可选路径；映射表写进 16 §9 的实现注记，不改协议）。
  - M4 验收：串起 persona、记忆、QQ / iMessage（真机或假连接器）与不可信输入的完整清单，产出验收记录（见「验收流程」）。
- 不做：
  - TUI / Web 的房间界面（另开单，结论写回 16 §9）；
  - 房间内工具与审批（设计明确全关）；
  - `private_initiative`；房间归档与级联删除策略（第一版只提供 `gqy room remove`，数据保留，PR 说明）。

## 测试与守护

- **前缀**：三个成员轮流 5 轮，断言每个成员会话第 N 次请求是第 N−1 次的字节前缀延伸（16 §12；把喂入改成重写全文，红）。
- **轮流**：每轮每人至多一次；上限 3 后停止；用户发言重开一轮（三例）。
- **工具全关**：成员会话工具面为空（编译断言 + 运行时调用 `unknown_tool`）；无任何审批问题产生。
- **公开版**：房间会话 system 不含私有关系档案（夹具对比）。
- **过滤**：`hidden` 会话不在默认列表；`room.message` 字段齐全（room、member、text、entry）。
- **只追加**：对 `room_messages` 的 UPDATE / DELETE 被触发器拒绝（去掉触发器，红）。
- 先红后绿对照（PR 贴输出）：把喂入改成重写全文、去掉轮次上限各一次。
