## 目标

`gqy-connector/1` 在 daemon 的连接器端点成立：`GET /api/v1/connector/ws?platform=<平台名>` 在 HTTP 升级前完成鉴权（`Authorization: Bearer <token>`、scope 必须是 `connector:<平台名>`、`connectors.<platform>.enabled = true`；**不认本机回环**）；升级后 10 秒内必须到 `hello`（`platform` 与 URL 一致，协议 / 平台不符回 `error{bad_hello}` 并断开）；`welcome` 下发 `connection`、`max_frame_bytes`、`max_attachment_bytes`、`max_inflight`（默认 32；超过时 daemon 不读新帧即 WebSocket 背压，而不是丢弃）；同一 `(platform, account)` 只保留一条连接，新连接顶替旧连接且旧连接等待中的 `send` 立即以 `superseded` 失败；`event` → 会话绑定 `(platform, account, conversation.id)` → `TurnRequest`（`idempotency_key` = 事件 id）→ **处理完才 ack**（`processed` / `ignored` / `duplicate`）；`send` 一帧一个气泡或一个附件（拆气泡与打字停顿在 daemon），纯文字 30 秒、附件 180 秒内没回 `send_result` 记 `delivery_unknown`（不自动重发）；`ping` 每 30 秒、90 秒收不到任何帧断开。

## 范围

- 做：
  - 帧类型进 `gqy-protocol`（13 §10 类型单一来源）：§3.2 的 `hello` / `welcome` / `event` / `ack` / `send` / `send_result` / `ping` / `pong` / `error` 全字段；未知字段与未知 `type` 忽略（对未知 type 回 `error{unknown_type}` 但不断开）。
  - 鉴权与升级：scope 检查走 13 §8.2 的路由权限表；失败在 HTTP 层（401 / 403，含回环无令牌）；平台未启用直接拒绝。
  - 连接管理：hello 超时 / 版本不符 / 平台不符；连接表与顶替语义；会话绑定与解绑；`/new`、`/topic N`、`/topics` 的服务端命令子集按 `Availability` 对连接器场所暴露（14 §6.2）。
  - 入站：`event` 字段校验（`conversation.kind`、`sender`、`text`、`reply_to`、`attachments`）；附件按 blake3 落 blob（MIME 白名单、单附件 16 MiB、单帧 32 MiB、每事件 ≤ 10 个超出丢弃并记日志——单位统一 MiB，修 v1 混用）；文本进 `TurnRequest`；ack 语义：`Admission`（`Started` / `Queued` / `Steered` / `Rejected`）与回合终态映射到 `processed` / `ignored`；处理中重复提交同一事件只等待不重复入队。
  - 出站：`send` 生成（`max_bubbles` 默认 4、`bubble_pause_ms` 默认 1200、`req` 为 ULID）；`send_result` 处理（`ok` / `message_id` / `error` 映射）；连接断开时等待中的 `send` 立即失败（v1 OneBot 卡 180 秒的回归由 P14-05 复跑）。
  - 心跳与断开：30 秒 ping、90 秒无帧判定；水位语义（只推进连续已 ack 前缀）的记录面在本单，执行面在 SDK（P14-02），去重面在 P14-04。
  - 启动恢复口径：连接器（非交互）场所的排队项在 `queue_restart_ttl`（30 min）内重启保留（Q-03-3；接 P13-02 第 5 步）。
  - 配置：`[connectors]` 的 daemon 侧键（`enabled`、`contacts`、`owner_host_tools`、`group_admin_host_tools`、`max_bubbles`、`bubble_pause_ms`、`memory_write`、`limits.*`）落进 `gqy-config` 唯一来源（16 §11）。
- 不做：
  - SDK、重连与水位执行（P14-02）；信任映射与不可信通道（P14-03）；限速与幂等闸（P14-04）；QQ / iMessage 平台实现（P14-05 / P14-06）；
  - `private_initiative`、语音入口（另单）；`DriverQuirks` 行为（待并入 16，复核第 1 条）。

## 接口草案

草案，以实现为准。

```rust
pub enum ConnectorFrame {
    Hello(Hello), Welcome(Welcome), Event(EventIn), Ack(Ack),
    Send(Send), SendResult(SendResult), Ping, Pong, Error(FrameError),
}

pub struct ConnectorEndpoint { /* 连接表 + 绑定表 + inflight 窗口 */ }
impl ConnectorEndpoint {
    /// 处理完（回合跑完或判定不回复）才返回；Rejected / ignored 立即返回。
    pub async fn on_event(&self, conn: ConnId, ev: EventIn) -> Ack;
    pub async fn send(&self, conn: ConnId, req: SendRequest) -> Result<SendResult, SendError>;
}
```

## 测试与守护

- **协议（假连接器走真 WebSocket）**：握手（超时、版本错、平台不符）、鉴权（无令牌、错 scope、回环无令牌）、ack 只在处理完后发出、重复 id 直接 ack（去重表接 P14-04 后复核）、`send` / `send_result` 超时、顶替旧连接、90 秒无帧断开（暂停时钟）——逐条对应 16 §12。
- **水位**：连接器推 10 个事件、daemon 乱序完成，断言水位只推进到连续已 ack 前缀；第 5 个处理中途杀 daemon → 重启后恰好重放未 ack 的事件、回合不重复。
- **断连**：断开侧后 1 秒内所有等待中的 `send` 失败（去掉断连清理，红）。
- **单位**：单帧 32 MiB / 单附件 16 MiB 边界（v1 单位混用回归）；超限附件丢弃且事件其余部分照常处理。
- **背压**：`max_inflight` 满 → daemon 不读新帧（不丢弃、不无限缓冲）；改成丢弃，红。
- **重启保留**：连接器场所排队项在 TTL 内重启保留、交互式场所丢弃（Q-03-3 口径）。
- 先红后绿对照（PR 贴输出）：把 ack 改为收到即回、去掉顶替语义各一次。
