## 目标

连接器共享逻辑只有一处实现：`gqy-connector-sdk`（L5，只依赖 `gqy-protocol` + `tokio-tungstenite`）——WS 连接与 `hello`/`welcome` 握手校验、ping/pong 心跳、指数退避重连（0.5 s → 30 s）、`max_inflight` 窗口、水位推进（只推进连续已 ack 前缀；重启后从未 ack 的第一条重放）、`send` / `send_result` 往返与 `req` 去重（同一 `req` 重复收到返回上次结果，不重复调用平台）、断连时所有等待中的发送立即失败。平台连接器实现一个 `Connector` trait（取事件、处理发送、声明 `capabilities` 与 `DriverQuirks`）即可接入——第一方连接器因此约等于“平台适配 + main 装配”。`gqy connector install|uninstall|status <name>` 生成 / 移除 launchd plist 或 systemd --user unit（固定路径、随用户登录启动，打印日志路径与 reload 命令），daemon 不管理连接器生命周期（00 §5 已定）。

## 范围

- 做：
  - crate 骨架与依赖边界（只 `gqy-protocol` + WS 客户端；`cargo xtask arch` 规则加 L5 检查）；第一方连接器的 `main` 模板（读配置、装配 SDK、处理信号）。
  - 连接生命周期：握手、`welcome` 校验（`max_frame_bytes` / `max_attachment_bytes` / `max_inflight`）、心跳发送与超时判定、断线重连退避 0.5 s → 30 s（带抖动）；收到 `error{superseded}` 后停止重连（新连接已在位）；`error{bad_hello}` 失败关闭并输出可读原因。
  - 水位：按事件顺序推送；只推进连续已 ack 前缀；配合 daemon 的去重表（P14-04）保证“重放不重复跑回合”。
  - 发送侧：窗口内并发 `send` 处理、`send_result` 回填、断连即失败（OneBot 1 秒 / 通用按超时）、`req` ULID 去重缓存（每连接 256 条、按时间清理）。
  - `DriverQuirks`：结构定义 + 随 `hello` 上送（字段待 README 复核第 1 条并入 16 后定形；先以加法字段占位，默认空）。
  - 连接器配置：连接器自己的配置文件（daemon 地址、`connector:<platform>` 令牌、平台侧地址 / access token；0600；不进版本库、不进日志、不进命令行参数）；`--check` 子命令做自检并给出可读结论。
  - `gqy connector install|uninstall|status <name>`：服务文件生成（macOS LaunchAgent / Linux systemd --user）、卸载、状态查询（是否已安装、文件路径）；不代管进程、不自动启动。
  - 测试工具：`testing` 模块提供 `run_fake_daemon`（真 WebSocket 的假 daemon）供各连接器与 SDK 自己的测试复用。
- 不做：
  - 具体平台实现（P14-05 / P14-06）；
  - 独立中继进程（00 §5：以后可加，不改连接器）；
  - 非 Rust 语言的官方绑定（协议语言中立，第三方自便）；
  - daemon 侧端点（P14-01）。

## 接口草案

草案，以实现为准。

```rust
pub trait Connector: Send + 'static {
    async fn next_event(&mut self) -> Option<EventIn>;              // 平台 → daemon
    async fn handle_send(&mut self, part: OutPart) -> SendResult;   // daemon → 平台
    fn capabilities(&self) -> Capabilities;
    fn quirks(&self) -> DriverQuirks { DriverQuirks::default() }
}

/// 建立并维持与 daemon 的连接；返回即代表“已断开且不再重连”（superseded / bad_hello）。
pub async fn run(cfg: SdkConfig, connector: impl Connector) -> Result<(), SdkError>;
```

## 测试与守护

- **水位**：daemon 乱序 ack → 水位只推进连续前缀；杀 daemon 重启 → 恰好重放未 ack 事件（乱序、重复 id 各一例）；去掉连续前缀判断，红。
- **重连**：断连后按 0.5 s → 30 s 退避（暂停时钟断言序列）；收到 `superseded` 停止重连（不再重连，红）。
- **发送**：断连 1 秒内所有等待中的发送失败（去掉断连清理，红）；同一 `req` 重发返回上次结果且平台调用计数不增加。
- **边界**：SDK 不依赖 L1–L4（arch 门禁为必需状态检查）；无无界通道（lint）。
- **服务文件**：生成 / 卸载幂等；路径与二进制一致；文件不含明文令牌；`status` 结论可读。
- **配置**：令牌只从 0600 配置文件 / 环境读取；启动参数与日志中不出现明文（断言）。
- 先红后绿对照（PR 贴输出）：去掉水位连续前缀判断、去掉 `superseded` 停止重连各一次。
