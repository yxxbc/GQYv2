## 目标

判定成为纯函数：给定 (venue, principal, mode, assessment, scope, sandbox, grants, policy) 得到 `Allow{by}` / `Ask` / `Deny{layer, rule, message}`，七步顺序照 08 §4，每一步的 `RuleId` 可追溯。做完之后：档位按场所上限钳制并可在会话中切换（工具面字节不变）；`ReadOnly` 挡下写与执行；无沙盒后端的平台上 Owner 的 Exec 走「unsandboxed + 每次审批」键。

## 范围

- 做：
  - `decide()` 的七步骨架与 `DecisionInput` / `Decision` / `Layer` / `RuleId`（08 §4）；第 1 步的命令策略表本单为空（P07-03 填），第 4–6 步从输入取 risk / grants / policy。
  - 档位矩阵 §4.1：`ReadOnly` / `Workspace` / `Full` × 五个效果类别；场所上限钳制照 §7（Owner→`Full`、Member→`Workspace`、External→`ReadOnly`、Internal 继承创建者且不超过父运行档位）；`read_anywhere` 仅 Owner。
  - 第 3 步沙盒可用性：`SandboxAvailability::{Available, Unavailable}` 为输入；Member / External / Internal 在 `Unavailable` 时 `Exec` 失败关闭（Owner 除外）；Owner 的无沙盒执行加 `unsandboxed:` 审批键前缀（Q-08-2 口径）；`Full` 不经过此步。
  - 第 7 步：`Ask` 且 `interactive == false` → 按 §5.5 处理（本单先按失败关闭的临时口径，P07-02 接完整流程）。
  - 会话档位：默认值（Owner `Workspace`，受场所上限钳制）、切换命令与 `session.mode_changed` 事件、`<mode-update mode="…"/>` 尾部通知；切换不再改工具面字节（07 §5.1 第 5 条）。
  - 事件：`permission.decided`（仅 deny / ask 发 UI）、`sandbox.unavailable`（第 3 步遇到不可用时，逐会话去重）——字段与登记照 08 §9.2。
  - 分发接线：`Dispatcher::prepare` 第 6 步换成 `decide`；`Ask` 在 P07-02 就位前**失败关闭**（`error[denied]: approval flow not wired`——过渡、有测试钉住、PR 描述声明不是发布形态）。
- 不做：
  - 审批通道与授权落库（P07-02）、命令策略与危险识别（P07-03）、路径守卫（P07-04）、沙盒探测本体（P07-05 / P07-06）。
  - 审计行写入（P07-07）；TUI `/mode` 界面（P09）与 HTTP 路由（按 P05-06 的口径归 P09 / P14）。

## 接口草案

草案，以实现为准。

```rust
// gqy-tools/src/permission.rs（08 §4；纯函数、无 IO）
pub struct DecisionInput<'a> { pub venue: &'a Venue, pub principal: &'a Principal,
    pub mode: CapabilityMode, pub assessment: &'a Assessment, pub scope: &'a WorkspaceScope,
    pub sandbox: SandboxAvailability, pub grants: &'a GrantSet, pub policy: &'a ApprovalPolicy }
pub enum Decision { Allow { by: RuleId }, Ask(QuestionSpec),
    Deny { layer: Layer, rule: RuleId, message: String } }
pub fn decide(input: &DecisionInput<'_>) -> Decision;

// gqy-engine（会话档位；SessionCmd 的扩展照 02 §3.2）
pub fn clamp_mode(mode: CapabilityMode, trust: Trust) -> CapabilityMode;   // §7 档位上限
// SessionCmd::SetCapabilityMode { mode } + session.mode_changed + <mode-update> 尾部
```

## 测试与守护

- **判定表（笛卡尔）**：(trust × mode × effect × sandbox × grant × interactive) 表驱动，期望值照 §4 / §4.1 / §7 逐行；删掉 §4 任何一步，至少一行红。
- **失败关闭**：注入 `Unavailable` → Exec 被拒且未 spawn（spawn 计数器）；移除第 3 步此测试红。
- **unsandboxed 前缀**：Owner `Workspace` 在 `Unavailable` 下 → `Ask` 且键带 `unsandboxed:`；沙盒内得到的会话授权**不**命中（08 §8 的行）；`Full` 不经第 3 步。
- **档位不回写工具面**：切档前后 `surface_hash` 与字节相等（07 §5.1 第 5 条）。
- **Dangerous 优先级**：`risk == Dangerous` → `Ask`，不受第 5、6 步影响。
- **配置**：`exec_unsandboxed = "allow"` → 配置校验失败并指出字段。
- 先红后绿对照（PR 贴输出）：把第 4 步挪到第 6 步之后、删 `unsandboxed:` 前缀各一次。
