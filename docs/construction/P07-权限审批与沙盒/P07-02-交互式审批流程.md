## 目标

`Ask` 有真正的落地：Question 落库、`question.asked` 广播、运行停在 `AwaitingApproval`、三种回答（AllowOnce / AllowForSession / Deny）生效、会话授权写入并在同前缀命令上不再提问、Dangerous 永不被授权覆盖。做完之后，mock 供应商触发的 `run_command` 端到端走完「提审 → 三种回答 → 授权 → 撤销后再次提审」。

## 范围

- 做：
  - 流程时序照 §5.1：QuestionId 生成 → `questions` 落库（status=pending）→ `question.asked`（字段照 §5.1 的 `QuestionAsked`：`choices`、`sandbox`、`session_key_preview` 等）→ `AwaitingApproval`（02 §6：无超时、可取消、不占全局回合配额）→ 回答经 `SessionCmd::Answer` → 先到先得、落库 status=answered、`question.answered` 广播。
  - 三种决定：`AllowOnce` 执行本次；`AllowForSession` 写 `session_grants`（`created_by_question`）后执行；`Deny` 生成 `error[denied]` 结果并附用户备注（trusted 文本，§5.1）。
  - 会话授权匹配：命中 `approval_key` 不再提问（第 5 步）；Dangerous 仍提问（第 4 步）；撤销立即生效（按请求查库，02 §8；路由已在 P05-07）。
  - 组内逐个提问（03 §6.2 第 3 条）：全部回答后整组才执行；被拒调用写合成结果，其余照常执行（失败不连坐）。
  - 取消与停机：运行取消 → 未答问题 `closed{run_ended}`、事件 `question.closed`；重启恢复时 `closed{expired}`（§8）。
  - 非交互场所 §5.5：Timer / Job 用创建时写入的**预授权集**（类型与判定点在本单；数据来源归 P13-02）；不在集内 → `Deny` + `question.unanswerable`；Subagent 冒泡带 `origin_run`（父会话按 §5.5 的父规则）。
  - 回答者校验 §5.6：principal 相等或 Owner；External 永不回答；模型输出永远不是回答。
  - `[approval]` 默认值（§5.2）：`exec_sandboxed = ask`、`exec_unsandboxed`（只接受 `ask | deny`）、`exec_full = allow`、`network = ask`、`auto_allow_commands`（按 §5.3 的同一匹配器，且只在沙盒可用时生效）。
- 不做：
  - 审批界面（P09 / P10）、连接器 Owner 私聊文本审批（P14）、`gqy ask --approve`（P05-11 口径）。
  - 危险识别与命令策略（P07-03）；`audit_log` 写入（P07-07，本单只产出其输入字段）。
  - Timer / Job 预授权集的创建路径与存储（P13-02）。

## 接口草案

草案，以实现为准。

pub enum ApprovalDecision { AllowOnce, AllowForSession, Deny }

## 实施步骤

（L 单：每一步都能单独编译通过。）

1. `questions` 状态机与仓储（先写「先到先得、后到拒绝」的会红断言）。
2. `ask` 与 `AwaitingApproval` 接线；`question.asked` / `question.answered` 两条事件。
3. 三种回答、授权写入与匹配；撤销立即生效的联测。
4. 组内逐个提问与失败不连坐；非交互场所与预授权集类型。
5. `[approval]` 默认值与 `auto_allow_commands` 匹配器。
6. `cargo xtask check --fast`、`cargo test -p gqy-engine -p gqy-store -p gqy-tools`；提交：`feat(perm): 交互式审批流程`。

## 测试与守护

- **端到端三答**：mock 触发 `run_command` → 收到 `question.asked` → 三种回答各一轮，断言工具结果、授权表、事件与审计输入字段。
- **授权生效**：`AllowForSession` 后同前缀命令不再提问；Dangerous 命令仍提问（与 P07-03 的识别做联测；P07-03 未完成时先留断言骨架）。
- **非交互**：Timer 场所无预授权 → 1 s 内 `Deny`，回合不挂起（§11 的「非交互」口径）。
- **双答与取消**：两个客户端同时回答 → 先到先得、后到者 409（协议层 P05-07 已有，本单断言引擎侧状态一致）；取消 → 未答问题 `closed` + `question.closed`。
- **回答者校验**：M 回答他人会话 → 被拒；External 的回答不生效。
- **备注文本**：Deny 的 note 出现在结果里且为 trusted 文本。
- 先红后绿对照（PR 贴输出）：去掉 Dangerous 的优先级、去掉授权命中检查各一次。

## 风险与回退

- **组内顺序与并发**：审批先于执行、逐个提问按 §6.2 第 3 条；与 P06-08 的分组实现联调，不另起第二条顺序逻辑。
- **预授权集数据缺口**：P13-02 未落地前只测「不在集内 → Deny」；「在集内」的用例随 P13-02 补。
- **回退**：`approval.rs` 是新文件；事件与授权接线随单 revert，`Ask` 回到 P07-01 的失败关闭占位。
