## 目标

每次判定与每次执行都有一行 `audit_log`（只追加）：`allow/ask/deny` 带 `layer`/`rule_id`/`decided_by`（`policy:<id>` / `grant:<id>` / `user:<principal>` / `auto`）；执行行带退出码、耗时、字节数与截断标记；`args_digest`/`args_summary` 按 §9.1 口径落库；`/audit` 返回真数据；180 天保留例程只删整日并写 `gc_runs`；四路（账本、事件、审计、日志）假密钥扫描全绿。

## 范围

- 做：
  - `audit_log` 仓储：追加写（`seq` 全局序号）、`?session=&since=` 查询、保留删除（只删早于保留期的整日数据；每次执行写一行 `gc_runs`）；`audit_log` 不可 UPDATE/DELETE 与 10 §4.4 触发器联测。
  - 三类写入点接线（07 §7.1 步骤 9 之后）：判定行（P07-01/02 的 `Decision` + `QuestionId`，仅 deny/ask 发 UI 事件而三类都入审计）、问题生命周期行、执行行（`ToolOutcome.facts` 的 `exit_code`/`bytes_out`/`truncated` 等）。
  - `decided_by` 映射：grant 命中 → `grant:<grant_id>`；用户回答 → `user:<principal>`；自动策略 → `policy:<id>`；机械放行 → `auto`。
  - `args_digest` = 原始参数字节的 blake3（原文在账本 `Raw` 通道）；`args_summary` 经 `redact_known_secrets`；`sandbox_json` 先按 `Unavailable` 占位定 schema（P07-05/06 接通真实 `SandboxView`，字段只增）。
  - 密钥四路守护（08 §9.3）：`redact_known_secrets` 在账本（四通道写入前）、事件、审计、日志四处的调用点补齐；`sk-test-CANARY…` 假密钥的完整回合扫描测试（P06-05 的 DoD 在此收口）。
  - `[audit].retention_days` 默认 180；保留例程入口 `run_retention_once(now)`（定时调度随 P13-02；本单提供入口与测试）。
  - `GET /audit`（P05-06 骨架）换真数据：不含 `auth_events`（13 §8.6）。
  - 纪律：判定值与 `permission.decided` 事件同源产生（同一条 `Decision`，不另算一次）——照 19 §3.3 的「单一路径」写法。
- 不做：
  - `auth_events`（P05-04 已有）与其他保留作业（P13-02 调度）；`sandbox_json` 的完整内容（P07-05 接通）。
  - TUI `/audit` 界面（P09）；审计导出（17/20 另有口径时再开）。

## 测试与守护

- **四类行**：allow / ask / deny / exec 各一例，字段与 §9.1 逐列对照；去掉任一类写入，对应用例红。
- **只追加**：对 `audit_log` 的 UPDATE/DELETE 被拒（触发器）；保留删除只删整日且写 `gc_runs`。
- **`decided_by`**：grant 命中 → `grant:<id>`；用户回答 → `user:<principal>`；自动策略 → `policy:<id>`；机械放行 → `auto`。
- **四路假密钥**：账本（四通道）、事件、审计、日志各扫一遍找不到 `sk-test-CANARY…` 原值；去掉任一路的脱敏调用，该路断言红。
- **`/audit`**：`?session=&since=` 过滤与分页；不含 `auth_events`；M 不可见他人会话行。
- **args**：`args_digest` 与账本 `Raw` 原文的 blake3 相等；`args_summary` 为脱敏摘要。
- 先红后绿对照（PR 贴输出）：去掉触发器、去掉审计路径的脱敏各一次。
