## 阶段目标

（与施工图 `plan-data` 同文）能力档位、交互式审批、Landlock、macOS 无沙盒审批路径与 Seatbelt 研究、路径守卫、审计。做完之后：

- 判定是纯函数、七步顺序照 08 §4，每一步的 `RuleId` 可追溯；失败关闭（沙盒不可用、保护路径、命令策略）在代码里，不在提示词里（铁律 7）；
- `Ask` 有真正的流程：问题落库、`AwaitingApproval`、三种回答、会话授权可撤销；Dangerous 永不被授权覆盖；非交互场所按 §5.5 如实拒绝；
- Linux 上 Exec 在 Landlock 内（写根 = 工作区，数据目录 `run/`、`config/` 硬规则）；macOS 上按「无后端」规则走审批后无沙盒执行，Seatbelt 结论写回 08 §6.4 待拍板；
- 路径守卫五步与保护路径对 `Full` 同样生效；`openat2` 缺失时如实标注 TOCTOU；
- 每次判定与每次执行在 `audit_log` 留下可查询、可脱敏的记录；密钥四路（账本 / 事件 / 审计 / 日志）扫描全绿。

**开工前复核清单**（00 §5 的「并入」项与跨文档不一致；先改设计文档、再开工）：

1. **`SessionCmd::SetCapabilityMode`**：02 §3.2 的 `SessionCmd` 草案里没有档位切换命令；P07-01 开工前把具名命令（或走 `Submit` 的明确路径）并入 02 §3.2。
2. **`sessions` 缺档位列**：10 §7.2 的 `sessions` 草案没有会话档位列；先回填 10，再按只增迁移补列（P07-01）。
3. **审计是否存原始参数**：07 §7.2 说「原始参数字节……保存在账本的 `Raw` 通道和审计记录中」，08 §9.1 的 `audit_log` 只有 `args_digest` + 脱敏 `args_summary`（原文只在账本）。推荐按 08 §9.1（审计不净存原文）——拍板后回填 07 §7.2，再实现 P07-07。
4. **`[exec]` 的值域**：08 §10 的 `sandbox = "required_if_available" / "required"` 需要与 P07-01 的判定输入对齐（`required` 在无后端时 Owner 也拒绝）；P07-05 开工前明确校验归属（`Config::validate`）。
5. **`questions.prompt_json` 与 13 §5.3.2 的 `QuestionAsked`**：两处的字段名与形状要对齐；P07-02 开工前对照 13 的 DTO 与 10 §7.4 的列定义，不一致先修设计。
6. **值类型归属**：`SandboxAvailability` / `SandboxView` / `SandboxPolicy` 放 `gqy-core` 还是 `gqy-sys`；P07-01 与 P07-05 开工前写进 01 §3 表或 08 §4 脚注——同一个事实只允许一处定义。
7. **Seatbelt 研究清单的时效**：08 §6.4 的 ①–⑤ 按当前 macOS 版本先复核再开 P07-06；研究项本身可能获得结论「不采用」。
