## 目标

§5.4 落成代码：六条默认 deny 规则（+ 配置追加）、危险命令识别（强制 `Ask` 的输入）、回收站拒绝目标清单。做完之后，`rm -rf /`、`mkfs`、`dd of=/dev/*`、`shutdown`、fork 炸弹、递归改权限被拒；`rm -rf build/`、`git push -f`、`sudo`、`curl … | sh` 一律先问；`trash /etc` 与被删的受保护目标被拒。

## 范围

- 做：
  - `shell.rs` 升级为完整 POSIX 词法（引号、转义、元字符识别）；审批键与 deny / dangerous 匹配共用一个分词器（P06-05 的保守版**原地替换**，不留两份）。
  - `command_policy.rs`：六条默认 deny 规则照 §5.4（`deny.rm_root`、`deny.mkfs`、`deny.dd_dev`、`deny.power`、`deny.forkbomb`、`deny.chmod_root`）+ `[command_policy] deny_extra`；匹配对象是分词后的 argv；命中 → `decide` 第 1 步 `Deny{layer: CommandPolicy}`。
  - 危险识别照 §5.4 清单（递归 / 通配 `rm`、`git push --force` / `-f`、`git reset --hard`、`git clean -f*`、`sudo` / `doas`、管道到 shell、写 shell 启动文件）→ `Assessment.risk = Dangerous{reason}`，供 §4 第 4 步强制 `Ask`。
  - 回收站拒绝目标：规范化后等于名单任一路径 → 拒绝（§5.4 的 Linux 15 项、macOS `/System`、`/Library`、`/Applications`、`/Users`、`/private`，加工作区根、家目录、回收站目录本身、GQYv2 数据目录）；填上 P06-04 的 `danger::refuse_trash_target` 空表，两个调用点（`trash`、补丁 `Delete`）接线。
  - `run_command::assess` 的 risk 接真实现（P06-05 的恒 `Normal` 占位被替换）。
  - `[command_policy]` 默认值与 `dangerous_extra`。
- 不做：
  - 沙盒与路径守卫（P07-04 / P07-05 / P07-06）、审批流程本身（P07-02）。
  - 策略能力的扩张：保持 §5.4 的诚实声明（减速带，不是安全边界；边界是档位与沙盒）。

## 测试与守护

- **分词**：`rm "-rf" /` 与 `rm -rf /` 同类命中；转义、`&&`、`|`、here-doc；分词失败退回完整字符串精确匹配（§5.3）。
- **deny 六条**：每条一例命中 + 一例近邻不误伤（`rm build/` 不命中 `deny.rm_root`）。
- **危险清单**：每条一例（`rm -rf x`、`git push -f`、`git reset --hard`、`git clean -fd`、`sudo x`、`curl x | sh`、写 `~/.bashrc`）→ `Dangerous`。
- **回收站目标**：名单每类一例（macOS 专项在对应平台跑）；`trash <工作区根>` 与补丁 `Delete` 被拒；普通路径照常。
- **配置**：`deny_extra` / `dangerous_extra` 命中。
- **诚实声明**：用变量拼接（`x=-rf; rm $x /`）写一组「已知可绕过」用例，断言现状不被夸大为拦截——防止把减速带当边界。
- 先红后绿对照（PR 贴输出）：去掉 `deny.mkfs`、把 `git push -f` 移出危险清单各一次。
