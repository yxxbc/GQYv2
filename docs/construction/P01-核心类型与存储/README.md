## 阶段目标

领域类型、SQLite 单写者、迁移框架、核心表、blob、备份、路径与最小配置（与施工图 `plan-data` 同文）。做完之后：

- 内容寻址 blob 与备份/恢复在库层面可验收（CLI 接线在 P05）。

本阶段不产出任何用户可见功能；里程碑 M1 在 P05。

## 遗留与发现

> 施工过程中发现的范围外问题记在这里；写单时发现、需要用户拍板的点也记在这里。

写单时发现的拍板点（均已于 2026-09-28 定案，见 00 §5）：

1. **blob 去重时是否刷新 mtime**（P01-07）：10 §6.2 的“目标已存在 → 比对大小一致则删除临时文件（去重）”没有说要不要把文件的 mtime 刷成现在。GC（§6.3）的宽限期按 mtime 计算，若刚被去重的旧文件保持旧 mtime，存在“GC 与其后提交的引用行竞态”的窗口。gqy 3-3 的做法是去重时刷新 mtime（git 存对象同款）。**推荐采纳**：在 10 §6.2 补一句“已存在的目标把 mtime 刷成现在（给 GC 宽限期用）”，然后进 P01-07。**已定（2026-09-28）**：采纳；10 §6.2 已补该句，P01-07 按此实施。
2. **`GqyPaths::ensure()` 遇到“已存在、非空、但不是我们的目录”**（P01-03）：10 §3 只写了创建缺失目录与权限收紧，没有写“碰撞”的处置。gqy 3-1（补/再补）的语义是：不是空的又没有标记文件 → 报错、什么都不建。GQYv2 用 `~/.gqy2`（D-01 已避开 v1 的目录），风险比 gqy 低，但 `GQY2_HOME` 可以指向任何目录。**推荐采纳**（小成本）：ensure() 在创建前检查：根目录已存在、非空且没有 `.gqy2-root` 标记 → 报错，不动里面的任何东西；需在 10 §3 补一句话。**已定（2026-09-28）**：采纳（错误名 `NotOurs`）；10 §3 已补标记与拒绝语义，P01-03 按此实施。
3. **“吞错误”的机器守护**（P00 阶段已提，见 P00 README 遗留 3；**已定，2026-09-28**：`let_underscore_must_use` + `unused_result_ok`，见 00 §5）。
4. **时间与本地日期换算的实现**（影响 P00-05、P01-01；**已定，2026-09-28**：`jiff` 为唯一时间库，见 00 §5）。
