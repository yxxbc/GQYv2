## 目标

`gqy-core` 补齐两块领域数据：**消息与内容块**（`WireRole`、`ContentPart`、`ToolSpec`——账本、适配器、工具系统共用的值类型）和**安全文本工具**（按 Unicode 标量做边界安全的切片/截断，05 §10 的写入期截断与 07 §8 的输出策略都依赖它）。做完之后，P02 起任何“模型看得到的文本”都走同一对切片函数，多字节字符不会 panic、不会切出半个码点。

## 范围

- 做：
  - `message`：`WireRole`（User / Assistant / Tool / SystemLate，04 §4.3）；`ContentPart`（Text / Image / File，见接口草案）；`ContextPayload { role, parts }`（04 §4.3）。
    - 命名说明：01 §3 的 `Message` 与 04 §4.3 的 `ContextPayload` 指同一概念。本单**只实现一个类型**（铁律 6），选 `ContextPayload` 这个名字；实施时同步把 01 §3 行里的 `Message` 字样改为 `ContextPayload`（一行小改，PR 里写明）。
  - `tool_spec`：`ToolSpec`（07 §3.1 的四个字段：`name`/`summary`/`description`/`schema`），`Cow<'static, str>` 形态照设计。
  - `text`：安全切片——`prefix_chars`、`suffix_chars`、`truncate_middle`（返回结构体，不拼接字符串；省略标记由调用方负责，模板在 07 §8）；按 **Unicode 标量（Rust `char`）** 计数（07 §…“按 Unicode 标量计数，切片走 `gqy-core` 安全切片”）。
  - 测试：多字节/emoji/组合字符的边界；proptest 属性测试。
- 不做：
  - 工具注册表、`ToolMeta`、`OutputPolicy`、参数收口（在 `gqy-tools`，P06）。
  - 09 §7 的 `safe_prompt_field`（在 `gqy-perception`，P11-05）。
  - 05 §10 的截断标记模板与 `HeadTail` 的渲染（07 §8 定义模板，P06 落地）。
  - `RawValue` 原样 JSON 类型（P02 供应商单随 `AssistantEnvelope` 一起做）。

## 接口草案

草案，以实现为准。

```rust
// gqy-core/src/message.rs

/// 线上逻辑角色（04 §4.3）。`SystemLate` 映射成什么由适配器按
/// `ProviderProfile.late_system_role` 决定（06 §4）；它不承担鉴权（铁律 7）。
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub enum WireRole { User, Assistant, Tool, SystemLate }

/// 消息里的内容片段。出现新形态时先改设计再加变体（本枚举 `#[non_exhaustive]`）。
#[derive(Clone, PartialEq, Debug)]
#[non_exhaustive]
pub enum ContentPart {
    Text { text: String },
    /// 图片必须带尺寸：尺寸由入口在执行器里量好；量不出尺寸的不当图片、当文件
    /// （miyu 1-2 的同款决定：图片宽高必填）。
    Image { mime: String, blob: BlobHash, width: u32, height: u32 },
    /// 一般附件（名称 + MIME + blob 引用）。
    File { name: String, mime: String, blob: BlobHash },
}

/// 账本 `Context` 通道的载荷（04 §4.3）：角色 + 片段。
#[derive(Clone, PartialEq, Debug)]
pub struct ContextPayload { pub role: WireRole, pub parts: Vec<ContentPart> }
```

```rust
// gqy-core/src/tool_spec.rs

/// 工具的对外规格（07 §3.1）。`schema` 是 JSON Schema 原文；
/// 规范化与校验在注册时做（P06），本类型只承载数据。
pub struct ToolSpec {
    pub name: Cow<'static, str>,        // ^[a-z][a-z0-9_]{0,63}$
    pub summary: Cow<'static, str>,     // ≤ 60 字符，英文短句
    pub description: Cow<'static, str>, // 完整契约，英文；不得插值运行时值
    pub schema: Cow<'static, str>,
}
```

```rust
// gqy-core/src/text.rs

/// 按 Unicode 标量计数，最多 `n` 个字符的前缀；`n` 不小于字符数时原样返回。
/// 这把切片是 05 §10 写入期截断与 07 §8 输出策略的唯一实现。
pub fn prefix_chars(s: &str, n: usize) -> &str;
pub fn suffix_chars(s: &str, n: usize) -> &str;

/// 头尾截断的结果：不拼接字符串（省略标记由调用方渲染，模板见 07 §8）。
pub enum Truncated<'a> {
    /// 没有超限，原样。
    Intact(&'a str),
    /// 超限：前 `head` 个与后 `tail` 个字符的切片，以及被省去的字符数。
    Split { head: &'a str, tail: &'a str, omitted_chars: usize },
}

pub fn truncate_middle(s: &str, head: usize, tail: usize) -> Truncated<'_>;
```

## 实施步骤

1. `message.rs`：三个类型 + serde 派生（`ContentPart` 用标签枚举，`#[serde(tag = "type", rename_all = "snake_case")]` 一类——线上字节的最终形态由 P02 的编码单对齐，本单以保证“可序列化且规范 JSON 稳定”为准）。
2. `tool_spec.rs`：四字段 + 构造校验所需的最小解析（`name` 正则与长度校验从 P06 起强制；本单只定义文档约束）。
3. `text.rs`：三个函数 + `Truncated`；先写边界测试（多字节）再实现。
4. 属性测试（proptest）：任意字符串与任意 `n`，断言不 panic、前缀是原串前缀、`head + tail` 不重叠、`omitted_chars` 准确。
5. 更新 `docs/designs/01-总体架构.md` 的 `Message` 字样；`cargo xtask check --fast`、`cargo test -p gqy-core`。
6. 提交：`feat(core): 消息、内容块与安全文本切片`。

## 测试与守护

- **边界**：ASCII、中文、emoji（多标量组合）、组合字符、空串、`n = 0`、`n > 字符数`、恰好等于——全不 panic、字节边界正确。**区分能力**：把实现换成按字节 `&s[..n]`，多字节用例必红（这正是要防的 panic 与半个码点）。
- **`truncate_middle` 语义**：`omitted_chars = total − head − tail`；`head = 0` / `tail = 0` 的退化形态；无超限时返回 `Intact`。
- **proptest**：随机字符串（含非 ASCII）与随机 `n`，断言 `prefix_chars(s, n).len() <= s.len()`、是合法 UTF-8、且是原串前缀；`truncate_middle` 的 `head`/`tail` 是原串的前缀/后缀切片。
- **serde 往返**：`ContextPayload` 三个变体各一例，规范 JSON 写出再读回相等（用 P01-01 的写出器）。
- 失败信息含期望值/实际值（19 §4.1）。

## 风险与回退

- **变体取舍**：`File` 变体在 07 附件落地前的使用点很少；若 P06/P07 施工时确认某一变体在首个真实使用前不需要，删掉不加（不以“以后可能用”为由保留）；新增变体时改设计再动。
- **`truncate_middle` 与省略标记**：标记模板（`[… N chars truncated; full output: …]`）属 07 §8，不在本单；避免“标记随实现漂移”，P06 落地时对照 05 §10 的示例逐字断言。
- **回退**：纯新增类型，revert 即可。
