## 目标

第一个真实迁移 `0001_core.sql`：元数据（`meta`、`blobs`）、会话（`sessions`、`session_bindings`、`session_model_changes`）、回合与账本（`turns`、`runs`、`ledger_entries`、`ledger_watermarks`、`compactions`）——全部 `STRICT`、外键打开、约束照 10 §7 草案。同时把两条写纪律变成机器守护：**WriteOnce 列**（BEFORE UPDATE 触发器拒绝）与**不可变表**（`ledger_entries` / `ledger_watermarks` 拒绝 UPDATE；DELETE 只在会话清除路径放行），并给 P03 起的 repo 立两条扫描规则（按列名读、禁 `SELECT *`）。

## 接口草案

草案，以实现为准。表 DDL 以 10 §7 的草案为准，本单照抄并把触发器补上（示例）：

```sql
-- 0001_core.sql（节选）
CREATE TABLE sessions ( /* 照 10 §7.2 */ ) STRICT;
CREATE TABLE ledger_entries ( /* 照 10 §7.3 */ ) STRICT;

-- WriteOnce：只在 INSERT 时写入的冻结快照（10 §4.4）
CREATE TRIGGER sessions_venue_wo BEFORE UPDATE OF venue_json ON sessions
  BEGIN SELECT RAISE(ABORT, 'write-once column: venue_json'); END;

-- 不可变表：追加型数据（10 §4.4）
CREATE TRIGGER ledger_entries_no_update BEFORE UPDATE ON ledger_entries
  BEGIN SELECT RAISE(ABORT, 'immutable table: ledger_entries'); END;
CREATE TRIGGER ledger_entries_delete_only_purge BEFORE DELETE ON ledger_entries
  WHEN NOT EXISTS (SELECT 1 FROM sessions s
                   WHERE s.session_id = OLD.session_id AND s.purge_state = 'purging')
  BEGIN SELECT RAISE(ABORT, 'ledger_entries delete requires session purge'); END;
```

```rust
// 最小 repo 样板（写纪律的示范）
pub struct SessionRepo;

impl SessionRepo {
    /// 插入（`NewSession` 里没有的列走默认值）。
    pub fn insert(tx: &WriteTx<'_>, new: &NewSession) -> Result<(), StoreError>;
    /// 按 ID 读；列按名字取（扫描规则拦数字下标）。
    pub fn get(conn: &ReadConn, id: &SessionId) -> Result<Option<SessionRow>, StoreError>;
}
```

## 实施步骤

1. 照 10 §7 抄 DDL（逐列核对；`STRICT`、`CHECK`、`REFERENCES` 一个不漏），补触发器。
2. 注册 `0001`；在临时库上应用；`cargo xtask migrations` 绿后用 `--refresh` 登记 CHECKSUMS。
3. 写边界值往返测试（10 §8.3.4 的“含边界值”精神）：空串、最大长度、NULL、多字节文本各落到相关列。
4. 触发器与约束负例：每个 WriteOnce 列一次违规 UPDATE、不可变表两种 DELETE 情形、`channel` 枚举越界、`payload` 与 `payload_blob` 同空/同非空、`STRICT` 类型错误。
5. 最小 repo 与扫描规则（先 fixture 红再实现）。
6. `cargo xtask check --fast`、`cargo test -p gqy-store -p xtask`；提交：`feat(store): 0001 核心表与写纪律守护`。

## 测试与守护

1. **应用**：空库 → `migrate` → 9 张表都在（`sqlite_master` 断言）；再跑一次幂等。
2. **往返**：会话行（含 `venue_json` 多字节）、账本行（`payload` 行内与 `payload_blob` 两种）写入读回一字不差。
3. **WriteOnce**：`UPDATE sessions SET venue_json=…` 等 4 处 → `RAISE` 拒绝，错误含列名。
4. **不可变**：`UPDATE ledger_entries` 拒绝；`DELETE` 在 `purge_state='none'` 时拒绝、改成 `'purging'` 后放行（10 §4.4 的两条删除路径之一）。
5. **约束**：`channel` 非法值、payload XOR blob、`turns.status` 非法值、`STRICT` 类型（往 INTEGER 列写文本）各断红。
6. **外键**：`turns.session_id` 指向不存在的会话 → 拒绝（`foreign_keys=ON`）。
7. **扫描规则**：`row.get(0)` 与 `SELECT *` fixture 断红；按列名读的样板不报。
8. **真实链守护**：P01-05 的 schema 差分/行级不变装置对 `[0001]` 跑绿。

## 风险与回退

- **触发器与 `purge` 的耦合**：`ledger_entries` 的 DELETE 放行条件依赖 `sessions.purge_state`；会话清除流程在 P12-08 落地，本单只把守护做出来（负例覆盖两种状态）。
- **`STRICT` 与类型亲和**：SQLite 的 `STRICT` 对列类型要求严格，抄 DDL 时逐列确认类型拼写（INTEGER/TEXT/BLOB/REAL）。
- **迁移冻结**：`0001` 一旦登记 CHECKSUMS，之后的修改必须走新迁移（门禁会拦）；若本单施工中发现问题，在 `--refresh` 之前随意改。
- **回退**：删除 `0001` 与触发器、移除注册行即可（尚未发布，无兼容包袱）。
