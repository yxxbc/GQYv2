## 目标

压后模型仍能工作：`Checkpoint` 带 `<read-files>`/`<modified-files>`/`<saved-memories>` 三块（并集、字节确定、≤200 项/块），`Rehydrate` 回灌最近被触碰的文件（≤5 个、单 4000 token、总 `min(24000, w/8)`），折叠原文归档为 `history:fold/<epoch>` 可回查。做完之后：工具改名后足迹仍非空（v1 教训 7 关闭）；LLM 无法改写三块；回灌读取即冻结。

## 范围

- 做：
  - 足迹并集：折叠区内 `ToolOutcome.footprint`（reads / writes / memories 自报）∪ 上一份 `Checkpoint` 的足迹（`BTreeSet`，字节确定）；**不维护「哪个工具算读文件」的名单**（v1 教训 7）。
  - 三块渲染：由代码生成，每块 ≤ 200 项、超出保留最近 200 项并注明省略数量；LLM 无权改写——送入更新模板前先 `strip_blocks`（P08-03 已留接口）。
  - 回灌（§7.3）：候选 = 折叠区足迹中最近被读或写的文件（按最后触碰倒序）；排除尾巴中已读过的、不存在的、二进制的、工作区外的、GQY 数据目录内的；上限 5 文件 / 单 4000 token / 总 `min(24000, window / 8)`；超限的文件只列路径（仍占名额）；读取发生在压缩任务内（blocking 池，02 §2），写入即冻结。
  - 渲染：从磁盘重新读取当前内容，`"N: line"` 带行号，包在 `<rehydrated-files>`；`Rehydrate` 条目可为空（空时不写）。
  - 折叠原文归档（§7.4）：折叠区渲染为 Markdown → blob → `compactions.transcript_blob`；`<compact-transcript ref="history:fold/<epoch>"/>` 最多列最近 5 份（`compact.transcript_refs`）；`read` 工具面中有读工具时该引用才出现（07 §9.1 口径）。
  - `history:` 存储域提供者：只读、只能读本会话、数据来自 `compactions.transcript_blob`；在组装处按 07 §9.1 的清单注册（P06-03 已留注册位）。
  - 配置：`compact.rehydrate_files` / `rehydrate_file_tokens` / `rehydrate_total_tokens` / `transcript_refs` 默认值。
- 不做：
  - 摘要正文（P08-03/04）、闸门（P08-05）、溢出恢复（P08-07）。
  - `<saved-memories>` 的数据源（P12：本单先发空块或如实省略，PR 说明）；会话删除对转录 blob 的级联联测（随 P13 的清理作业与 10 §9.3）。

## 实施步骤

## 测试与守护

- **足迹来源**：测试替身工具改名后足迹仍非空（v1 教训 7 回归；去掉 `ToolOutcome` 来源改读名单，测试红）。
- **并集确定性**：两种输入顺序产出字节相等；上一份 `Checkpoint` 的足迹并入。
- **三块上限**：201 项 → 200 + 省略数量；把三块混进摘要文本 → 断言被剥离（LLM 无权改写）。
- **回灌**：五条排除规则各一例；三类上限边界；超限只列路径（仍占名额）；`N: line` 行号与内容对照。
- **冻结**：回灌写入后改文件 → 账本字节不变（重读发生在下次压缩）。
- **转录**：blob 写入且 `transcript_blob` 非空；`read history:fold/<epoch>` 回取成功；`<compact-transcript>` 最多 5 份；跨会话读取被拒。
- 先红后绿对照（PR 贴输出）：去掉排除规则、把回灌读取挪到规划期（异步路径）各一次。

## 风险与回退

- **读取时机**：回灌读取发生在压缩任务内、写入即冻结（04 §7）；挪到规划期会破坏字节确定性——禁止。
- **blob 生命周期**：转录随会话；会话删除的级联按 10 §9.3，与 P13 的清理作业联测（登记在 README 遗留）。
- **回退**：三个新文件与域提供者 revert；`Checkpoint` 缺三块仍可解析（解析方向本单保证）。
