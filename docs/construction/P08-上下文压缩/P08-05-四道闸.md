## 目标

压缩入口先过四道闸，任何一道拦下都发 `context.compact_skipped{gate}`（手动压缩以错误信息返回给用户）：经济性、无可折叠、卡死闩锁、抖动。做完之后：闸 3/4 的闩锁使自动压缩暂停并各发一次通知；复位**先于一切分支**（v1 教训 11 的专测钉住）；`thrashing` 只由用户操作复位；手动与溢出恢复按 §5.2 豁免。

## 范围

- 做：
  - `CompactGateState`（`consecutive_over_trigger`、`stuck`、`recent_compact_turns: [Option<u32>; 3]`、`thrashing`、`notice_sent`）进 `SessionState` 并随会话持久化（承位列先按复核清单回填 10；与 P08-01 的占用状态合一处存）。
  - 复位纪律：每次计量后第一件事是 `reset_if_below_trigger`（占用 < 触发线 → 计数清零、`stuck = false`），然后才进入任何可能 return 的分支；`thrashing` 只由手动压缩成功、`/context reset-gates`、新会话复位。
  - 闸 1 经济性：折叠区估算 < `context.economy_min_fold_tokens`（默认 400）且不是强制档 / 溢出恢复 / 手动 → 跳过。
  - 闸 2 无可折叠：切点之前没有任何可折叠回合 → 跳过（**溢出恢复也受它约束**，05 §9 第 3 条）。
  - 闸 3 卡死闩锁：连续 `context.stuck_after`（默认 2）次压缩后占用仍 ≥ 触发线 → 置 `stuck`，暂停自动压缩，发一次通知（英文文案照 §5.2，界面文本走 i18n）；闩锁期间自动压缩跳过；手动与溢出恢复不受影响。
  - 闸 4 抖动：压缩后 ≤ `context.thrash_window_turns`（默认 3）个回合内再次触发，连续 `context.thrash_limit`（默认 3）次 → 置 `thrashing`，停用本会话自动压缩并提示「可能有单个超大输出，建议分块读取或新开会话」。
  - 闸门判定为纯函数（`GateInputs → GateVerdict`），入口调用；`context.compact_skipped` 与两类通知事件的接线。
  - `/context reset-gates` 的引擎侧命令（入口界面随 P09/P10）。
- 不做：
  - 水位计量（P08-01）、提交管线与撤销（P08-02）、摘要路径（P08-03/04）、溢出识别（P08-07）。
  - 通知的界面渲染与 i18n 文本（P09/P10；本单只发事件与英文常量）。

## 接口草案

草案，以实现为准。

```rust
// gqy-engine/src/compact/gates.rs（判定与状态更新分离）
pub struct GateInputs<'a> { pub fold_tokens: u32, pub foldable_turns: u32, pub trigger: Trigger,
    pub occupancy_ratio: f32, pub turn_seq: u32, pub stage: Stage }
pub enum GateVerdict { Pass, Skip { gate: Gate } }
pub enum Gate { Economy, NoFoldable, Stuck, Thrashing }
pub fn evaluate(input: &GateInputs<'_>, st: &mut CompactGateState) -> GateVerdict;

// 复位纪律：每次计量后先调这个，再进任何分支（v1 教训 11）
pub fn reset_if_below_trigger(st: &mut CompactGateState, occupancy_ratio: f32);
pub fn reset_thrashing(st: &mut CompactGateState);   // 手动成功 / reset-gates / 新会话
```

## 实施步骤

1. `evaluate` 与 `reset_if_below_trigger` 纯函数 + 逐闸会红用例；先写闸 3 复位专测（v1 教训 11）。
2. 状态进 `SessionState` 与持久化；`context.compact_skipped` 与两类通知文案。
3. 闩锁 / 抖动的自动跳过与手动 / 溢出豁免接线。
4. `/context reset-gates` 引擎侧命令。
5. `cargo xtask check --fast`、`cargo test -p gqy-engine`；提交：`feat(context): 四道闸`。

## 测试与守护

- **每闸两例**（触发 + 刚好不触发）：闸 1 的 400 边界；闸 2 全在尾巴预算内；闸 3 连续 2 次的第 2 次；闸 4 的 3 回合窗口边界（各去掉一闸，对应用例红）。
- **闸 3 复位专测**：把复位挪到某分支之后（变异版本），测试红——这是 v1 教训 11 的回归钉。
- **豁免**：闩锁期间手动压缩成功并复位 `stuck`；溢出恢复不受闸 3/4 影响（与 P08-07 联测）。
- **事件**：每次跳过一条 `context.compact_skipped{gate}`；闩锁与抖动通知各恰好一次（重复计量不重复发）。
- **复位来源**：`thrashing` 只在这三个操作后清零（自动路径永不清零）。
- 先红后绿对照（PR 贴输出）：删闸 3、把 `thrashing` 复位改成自动各一次。

## 风险与回退

- **误停自动压缩**：闸 3/4 的阈值来自 v1 实测；调整必须带用例并同步 05 §14。
- **状态漂移**：闸门状态与占用状态同列持久化；复位口径只在 `reset_if_below_trigger` 一处实现，不允许第二处清零。
- **回退**：`gates.rs` 删除后入口回到「无闸直通」（P08-02 的形态）；状态列保留不用。
