## 目标

摘要生成有完整的降级阶梯：Fork →（一次）Isolated → Placeholder；超时不出隔离路径。做完之后：Fork 非超时失败恰好回退一次隔离请求；Fork 超时自动写占位、手动报错不改写；占位摘要把上下文照样释放（避免「失败→仍满→再压→再失败」）；隔离请求的序列化对注入免疫（工具报告截 2000 字符、参数只列键名）。

## 范围

- 做：
  - 隔离请求：固定 system（摘要器提示词，常量字节）+ 单条 user（折叠区序列化文本）；不带 tools、不带会话缓存标识（`Auxiliary(CompactIsolated)`、`epoch = 0`、`parent_prefix = None`）。
  - 序列化（防注入，§6.3）：工具报告截断到 2000 字符（Unicode 边界安全）；工具调用参数只列键名（`edit {path, patch} (2 keys)`）；assistant/tool 文本中形似 `User:` 的内容照原样保留，模板声明「只有真正的 user 角色回合才算用户发言」。
  - 超长处理：序列化文本估算 > 摘要模型窗口 × 0.6 → 按回合边界分段、逐段摘要、两两合并（树状，最多 3 层）；超出 3 层时最旧的段只保留「用户请求」与「决定」两节。
  - 失败矩阵照 §6.3（自动 / 手动两列）：Fork 非超时失败 → 回退 Isolated 一次；Fork 超时 → **不回退**（自动写占位、手动报错）；Isolated 失败或超时 → 占位 / 报错；供应商层单层重试计入上述「一次」。
  - 占位摘要（§7.5）：固定文案（`N earlier turns were folded…`）；足迹三块、回灌与转录照常（P08-06）；`path = Placeholder`。
  - 更新模板接线：存在上一份摘要时使用更新指令；送入前剥离足迹三块（P08-03 的 `strip_blocks`）；PRESERVE（路径与标识符逐字、`Standing Facts` 逐条保留）。
  - `Summarizer` 完整实现（Fork → Isolated → Placeholder），replace P08-02 的「恒失败」替身。
- 不做：
  - fork 请求本体（P08-03）、足迹/回灌/转录（P08-06）、四道闸（P08-05）、溢出恢复（P08-07）。
  - 摘要模型的选择（固定会话绑定，05 §8）；`<saved-memories>` 数据源（P12）。

## 实施步骤

1. 序列化纯函数与注入用例（`User:` 形似文本、超长截断、多字节边界）。
2. 隔离请求与 `CompactIsolated` 记录；树状合并。
3. 失败矩阵表驱动（5 行 × 自动/手动两列）。
4. 占位摘要 + `path=Placeholder` 的记录与事件。
5. 更新模板输入的剥离点接线；删 P08-02 的替身。
6. `cargo xtask check --fast`、`cargo test -p gqy-engine -p gqy-ledger`；提交：`feat(context): 隔离回退与机械占位`。

## 测试与守护

- **矩阵表驱动**：Fork 工具调用失败 → 恰好一次 Isolated；Fork 超时 → 直接占位（去掉「不回退」分支，测试红）；Isolated 失败/超时 → 占位；供应商层重试不产生第二次回退。
- **手动 vs 自动**：手动路径任何失败 = 报错且账本零写入（断言）。
- **序列化**：工具报告 > 2000 字符截断且多字节边界不 panic；参数只列键名（对照样例）；`User:` 文本保留 + 模板声明在正文里。
- **树状合并**：2 层与 3 层用例；第 4 层降级保留「用户请求」与「决定」两节。
- **占位**：文案与 §7.5 一致；`compact_finished{path: Placeholder}`；占位路径同样换纪元、`Checkpoint` 正常写。
- **更新模板**：PRESERVE 样例对照（Standing Facts 逐条保留、路径逐字）。
- 先红后绿对照（PR 贴输出）：让 Fork 超时也回退、去掉占位路径各一次。

## 风险与回退

- **「一次回退」的口径**：供应商层单层重试计入同一次（06 §8.2）；测试要防止回退两次。
- **树状合并的保真度**：超 3 层的降级是有损的——如实记录在事件与日志，不假装无损。
- **回退**：`isolated.rs`/`fallback.rs` 新文件；`Summarizer` 接缝回到 P08-03 的 fork-only 版本，提交管线不受影响。
