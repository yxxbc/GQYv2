## 目标

压缩成为一条可回退的提交管线：切点 → 单事务（`Checkpoint` → `Rehydrate` → 新 `StableSection` → `compactions` 行 → 水位行 → 纪元 +1）→ `context_rewrite` 日志；撤销以新纪元恢复旧视图、不删任何条目。做完之后：`TestCompactor` 的替身路径被真实 `CompactEngine` 替换；自动与手动两种形态都在独立任务里跑、不阻塞其他会话；忙时 `BusyError`、取消即等于没发生。

## 范围

- 做：
  - 切点（§5.1）：当前回合整体保护；`tail_budget = min(tail_tokens, window / 2)`（`tail_tokens` 默认 `min(16384, window / 4)`，Chat 档案 8192——档案值来自 12 §6.2 的场所声明，注入与本单读取）；最近 2 个已完成回合无视预算必保留；切点永远落在回合边界；上一纪元 `Checkpoint`/`Rehydrate` 归折叠区并作为「上一份摘要」传给摘要路径。
  - 提交管线（§7.1 六步，一个 store 事务）：乐观并发检查（账本尾 `seq`，冲突 → `compact_failed{reason: "conflict"}`）→ `Checkpoint` 条目（布局照 §7.1；摘要正文由 P08-03/04 注入，足迹三块由 P08-06）→ `Rehydrate`（可为空不写）→ 新纪元 `StableSection`（走 P03-05 的 `open_epoch` 协议）→ `compactions` 行 + `ledger_watermarks` 行 → 纪元 +1 并打 `context_rewrite reason=compaction`（19 §3.4 字段）。
  - 两种形态（§8）：手动 `/compact` 与撤销经 `SessionCmd::Exclusive`（有运行中回合 → `BusyError`，入口提示或排进队列）；预检 / 强制在运行内以 `Compacting` 状态调用同一个 `CompactEngine`，不申请独占操作。两者都以子任务 spawn，actor 只收发消息；全局没有锁与忙标志。
  - 撤销（§11）：只撤最近一次且之后没有更晚压缩；追加新水位记录 + 新纪元（`CompactionUndo`，`checkpoint_entry_seq` 为 NULL）；视图 = 原折叠区 + 原尾巴 + 压缩之后追加的条目（排除该次 `Checkpoint`/`Rehydrate`）；恢复占用 ≥ 强制档 → 拒绝（除显式 `--force`）；原压缩记录写 `undone_by`（受控 UPDATE，先并入 10 §4.4 的白名单）。
  - 事件：`context.compact_started{trigger, stage, before_tokens}`、`context.compact_finished{path, folded_turns, kept_turns, summary_tokens, before_tokens, after_estimate, rehydrated_files, epoch}`、`context.compact_failed{reason, fallback}`（`skipped` 归 P08-05）。
  - 模型绑定：摘要请求只用会话 `ModelBinding`（`ctx.model` 传参），配置层没有「压缩模型」选项。
  - 取消：压缩任务挂在会话（独占）或运行（回合内）的取消令牌下；事务未提交即等于没发生。
- 不做：
  - 摘要请求与提示词（P08-03/04）、四道闸（P08-05）、足迹/回灌/转录（P08-06）、溢出识别（P08-07）。
  - 手动命令的界面与路由改名（P09/P10；`/ops` 路由串已由 13 §5.2 定义）；空闲压缩（Q-05-2 不做）。

## 实施步骤

（L 单：每一步都能单独编译通过。）

1. `cut_point` 纯函数 + 会红用例（最小两回合、切点不劈回合、上一份 `Checkpoint` 在折叠区）。
2. 提交管线（先写「中途失败零写入」的会红断言）与 `compactions`/`ledger_watermarks` 写入。
3. `ExclusiveOp` 两形态接线（`Exclusive` + `Compacting`）；删 `TestCompactor` 的使用路径。
4. 撤销与 `undone_by`；`--force` 边界。
5. 取消与排队联测；`context_rewrite` 行与三条事件。
6. `cargo xtask check --fast`、`cargo test -p gqy-engine -p gqy-store -p gqy-ledger`；提交：`feat(context): 压缩独占操作、水位与撤销`。

## 测试与守护

- **一次改写**：mock 长会话自动压缩前后恰好一个纪元增量、新纪元首条历史条目是 `Checkpoint`、之后 5 回合逐次延伸（04 §12.3 门禁场景接真；去掉这一步，门禁场景红）。
- **切点**：最近 2 回合超预算仍保留；切点不劈回合；当前回合不折叠；上一份 `Checkpoint` 在折叠区（去掉任一规则，对应用例红）。
- **单事务**：注入第 4 步失败 → 零写入（账本、水位、`compactions` 都不变）；把事务拆成两段，测试红。
- **撤销**：撤销后视图与压缩前逐条目相同（+ 压缩之后的条目）；恢复占用 ≥ 强制档被拒；`--force` 通过；原记录 `undone_by` 非空、旧水位行未改写。
- **忙与排队**：有运行中回合时手动压缩 → `BusyError`；压缩期间本会话新提交排队、结束后按序出队。
- **取消**：压缩任务取消 → 无写入；与 02 §5 的取消传播联测。
- **不阻塞**：mock 摘要睡 25 s；压缩开始 3 s 后会话 B 发起回合、B 的往返 < 1 s（把压缩改回 actor 循环内 await，测试红；05 §15 第一条）。
- 先红后绿对照（PR 贴输出）：把 `open_epoch` 调用删掉、把切点挪进当前回合各一次。
