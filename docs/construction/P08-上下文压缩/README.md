# P08 · 上下文压缩

> 状态：【规划】。本阶段把 05 号设计落成 `gqy-engine` 的压缩子系统：占用计量与锚点、压缩独占操作与撤销、fork 摘要与隔离回退、四道闸、足迹与压后回灌、被动溢出恢复。压缩是会话内**唯一**的前缀改写点（铁律 1），也是长会话不撞窗口、撞了能恢复的兜底。
> 创建：AI 助手（Cline 会话），2026-09-28。改动本文件时，按根 `AGENTS.md` 规矩 7 更新这一行：写清谁改的、什么时候改的。

## 阶段目标

（与施工图 `plan-data` 同文）占用计量、水位纪元与撤销、fork 摘要、隔离回退、四道闸、压后回灌、溢出恢复。做完之后：

- 长会话在占用逼近窗口前主动压缩；每次压缩恰好开一个新纪元、新纪元以 `Checkpoint` 开头，之后纯追加直到下一次压缩（04 §12.3 的门禁场景接真）；
- 计量以供应商真实用量为锚（v1 教训 12）：锚点、校准系数与提示 / 触发 / 强制三条线可解释、可测试；
- 压缩不阻塞其他会话，也不阻塞本会话之外的任何东西（v1 事故：`admin_busy`）——两种形态都在独立任务里跑；
- 摘要走 fork（吃缓存）优先、失败回退隔离、再失败写机械占位：自动路径不空转，手动路径如实报错；
- 压后模型仍能工作：逐字尾巴 + `<read-files>`/`<modified-files>` 足迹 + 回灌文件 + `history:fold/<epoch>` 存档；
- 撞窗之后能恢复一次：溢出屏障、强制压缩、再溢出如实失败（`ContextOverflow` 原文落库）。
