## 阶段目标

（与施工图 `plan-data` 同文）v1 导入（预演/核对/应用）、发布构建、桌面宿主、版本一致性、发布流水线。做完之后：

- `gqy import-v1` 成立（D-06 拍板前按 `gqy2` 口径）：discover → snapshot → plan 只读、预演不建目标；`--apply` 走 staging 构建 → 八项核对 → `rename` 提交；v1 目录全程逐字节不变，回退只需删除目标（20 §1、§4）；
- 报告齐全：`report.json`（字段只增不改）＋ `report.md`（结论 → 待处理 → 统计 → 不导入清单 → 核对 → 抽样 diff），终端不打印正文与密钥；应用成功另存目标 `import/v1-<ts>/`（20 §9）；
- 确定性：同一源两次导入的目标（除导入时间戳）完全相同；中断只留 `.importing-*` 待清理、绝不续用半成品（20 §8）；
- 语义保真与一次冷启动：导入回合按 v1 的 Raw / Display / Context 三通道化石，每个导入会话首轮带 `ColdStartReason::V1Import` 计划内冷启动，之后每轮字节前缀稳定（20 §7、04 §9）；
- 发布构建与版本一致性：`version.txt` / manifest / Cargo / changelog 标题 / `--version` 同源，由 `cargo xtask` 守护；`/info` 构建 ID 与 CLI 同值（release-versioning.md、13 §5.1）；
- 发布流水线：Release Please 创建 `v*` tag 后产出制品（macOS aarch64、Linux x86_64 可执行 + `SHA256SUMS`），tag 与版本不符时拒绝上传（19 §8.2、CONTRIBUTING）；
- 桌面宿主：Tauri v2 宿主内嵌模式调用 `gqy_daemon::assemble_daemon`（与 `gqy daemon run` 同一函数），锁被占用则退回客户端模式；WebView 传输按 Q-15-5 先验证后回落；体积与内存实测写回 15 §10.3。

## 遗留与发现

> 施工过程中发现的范围外问题记在这里；写单时发现、需要用户拍板的点也记在这里。

写单时的口径：

1. **结构固定**：每张单按施工总纲 §3.2 写——表头（`| 状态 | 未开始 |`、依赖、`| 设计依据 |`、`| 规模 |`、`涉及 crate / 目录`）＋ 固定九节（`## 目标`、`## 范围`、`## 改动清单`、`## 接口草案`、`## 实施步骤`、`## 测试与守护`、`## 验收流程`、`## 完成判据`、`## 风险与回退`）；表头之后加一行「草案（开工前复核）」；状态以单文件头为唯一真相源，本 README 只写链接与一句话。
2. **v1 只读是硬线**：导入器对 v1 目录只读（SQLite 三件套先复制到 staging 副本再打开）；任何写 v1 的路径都视为越界，由「源不变」守护钉住（20 §1、§11）。
3. **预演与应用的边界**：预演不创建目标、不写目标库；`--apply` 才进入 staging 构建；失败与放弃只删临时目录或目标（v2 未使用前），v1 目录永不受影响（20 §4）。
4. **不静默丢数据**：不导入的内容在 `report.json` / `report.md` 逐项列出（路径、行数、原因）；终端不打印消息正文与密钥（20 §6、§9）。
5. **版本单一来源**：`version.txt` 是发布版本唯一来源（Release Please `simple` 类型）；Cargo 版本与 changelog 标题由检查守护，不在普通提交里手工 bump（release-versioning.md、scripts/CLAUDE.md）。
6. **待定项按推荐先行**：D-06（共存期 `gqy2` 命令名）、Q-20-1（不做增量）、Q-20-2（脚本工具默认禁用）、Q-20-3（MCP 复制并重写路径）、Q-20-4（成员账号全导入、列重设密码）、Q-20-5（伴侣数据暂不导入、报告写明“数据仍在 v1 目录，请勿删除”）；Q-15-5（桌面传输）研究项。拍板前不实现相反行为。
7. **不在本批 7 张单内**：增量导入（Q-20-1）；安装器 / 签名 / 公证与自动更新（15 §10.3）；伴侣数据导入器（等扩展落地，P13-07 已预留扩展目录）；向量 / 语义索引迁移（D-05）；mesh 与桌面宿主的联测（随 P15 另议）。
