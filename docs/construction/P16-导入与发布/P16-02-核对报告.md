## 目标

staging 构建与核对成立：在 `--to` 同级创建 `.<name>.importing-<ts>/`，按 10 的布局初始化全新 v2 数据目录（执行全部迁移），经 `gqy-store` 写接口批量事务（每 1000 行一个事务，不绕过触发器与约束），文件优先 reflink / `clonefile` 否则普通复制并逐文件验 blake3；八项核对全过才通过——行数、会话内容哈希链（Raw / Display / Context 三通道重算）、记忆多重集、文件 blake3、抽样统一 diff（差异必须落在允许类别）、字节回放（两次规划字节相同 + 首轮 `V1Import` 冷启动标记）、库完整性（`integrity_check` + `foreign_key_check` + blob 引用齐全）、源未改；`report.json` 与 `report.md` 字段与顺序完整（20 §9）；任一失败 → 删除 staging、报告失败项并指名会话与检查项、退出 1。

## 接口草案

草案，以实现为准。

```rust
pub enum VerifyCheck { RowCount, TurnContentHash, MemoryMultiset, FileHash,
                       SampleDiff, ByteReplay, Integrity, SourceUnchanged }
pub enum VerifyResult { Pass, Fail { detail: String }, Skipped { reason: String } }
pub struct VerifyItem { pub check: VerifyCheck, pub result: VerifyResult }
/// 在 staging 上执行全部检查；任一 Fail 即不可提交（20 §4.5）。
pub fn verify(staging: &Path, plan: &Plan, baseline: &[FileStamp], opts: &ImportOptions)
    -> Result<Vec<VerifyItem>, ImportError>;
```

## 实施步骤

1. staging 初始化与迁移；写接口批量事务（1000 行 / 事务）；blob 去重与 reflink。
2. 行数 / 内容哈希链 / 记忆 / 文件四项核对（先写「丢弃一条回合 → 红」）。
3. 抽样 diff 与类别白名单；报告 `samples` 与链接。
4. 字节回放门禁：两次规划字节相同 + 首轮 `V1Import` 冷启动。
5. 完整性、源未改；失败路径（删 staging、退出 1）。
6. `cargo xtask check`；提交：`feat(import): 构建、核对与报告`。

## 测试与守护

- **注错必红**：分别注入「丢弃一条回合 / 篡改一个字节 / 漏复制一个附件」，verify 必须失败并指出会话与检查项（20 §11）。
- **回放**：导入会话在 mock 上 3 轮，第 2、3 轮是前一轮字节前缀延伸；首轮带 `V1Import` 冷启动标记（去掉标记，红）。
- **确定性**：同源两次构建的规范化转储逐字节相同（依赖 `--canonical`，复核第 2 条）。
- **密钥**：目标 `gqy.toml` 无夹具明文密钥；`secrets.toml` 0600（`cfg(unix)`）。
- **principal 连续性**：夹具的 principal 可见性记忆在新库同 scope 可召回、换身份不可召回。
- 先红后绿对照（PR 贴输出）：去掉内容哈希核对、去掉首轮冷启动标记各一次。
