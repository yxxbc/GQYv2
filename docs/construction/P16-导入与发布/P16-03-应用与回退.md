## 目标

`gqy import-v1 --apply` 全流程成立：核对通过后 `rename(staging, --to)` + fsync 父目录；`meta` 写入 `imported_from = v1:<源路径>`、`imported_at`、`importer_version`、源清单哈希（`manifest_blake3`）；报告复制到目标 `import/v1-<ts>/`；退出码收敛为 0 = 应用完成；失败或放弃时删除临时目录或整个目标（v2 未使用前），v1 目录逐字节不变；中断（Ctrl-C、断电）只留下 `.<name>.importing-<ts>/`，下次运行检测并提示删除，从不续用半成品；重跑 = 删除目标后重新执行，两次结果逐字节相同（`--canonical` 比对）；对已导入过的目标再次运行比对源清单哈希并提示「源自上次导入后有 N 个会话变化」（Q-20-1 口径）。

## 范围

- 做：
  - commit（rename + fsync + `meta` + 报告复制）；完整退出码表（0/1/2/3/4）。
  - 回退语义：v2 未使用时删目标即回退；已使用后的回退写进手册（P16-07），本单不自动回退已使用的目录。
  - 中断与残留检测（提示删除、不续用）；重跑与确定性。
  - `gqy export --canonical`（复核第 2 条拍板后：并入本单则实现；否则本单只接调用并向下依赖并在 PR 说明）。
- 不做：
  - 增量导入（Q-20-1）；目标合并（Q-10-4 首版不支持）；在运行中的 v2 数据目录上操作。

pub struct MetaStamps { pub imported_from: String, pub imported_at: Timestamp,

## 实施步骤

1. commit：先写「目标已存在 → 退出 4、不动目标」与「核对未过不提交」用例。
2. `meta` 标记与报告复制；`imported_from` 记录源路径（手册提示路径可能移动）。
3. 中断与残留：杀进程后只剩 `.importing-*`；下次运行提示删除、不续用。
4. 重跑与确定性：删目标重跑，`--canonical` 双目标比对逐字节相同。
5. 退出码收敛；回退演练路径交 P16-07 手册。
6. `cargo xtask check`；提交：`feat(import): 应用与回退`。

## 测试与守护

- **提交**：rename 后 `--to` 完整、staging 消失；`meta` 四个字段齐全；报告副本在 `import/v1-<ts>/`。
- **回退**：删除目标后 `gqy doctor` 干净；v1 源哈希与导入前一致（联跑「源不变」）。
- **中断**：过程中杀进程 → 只剩 `.importing-*`；再运行提示删除（去掉检测，红）。
- **重跑 / 确定性**：双跑 `--canonical` 输出逐字节相同（把导入时间戳写进可比较内容，红）。
- **退出码**：0/1/2/3/4 逐条（含预演与 `--apply` 的差异）。
- 先红后绿对照（PR 贴输出）：去掉确定性（写入时间戳）、去掉残留检测各一次。

## 风险与回退

- **中途断电**：staging 残留在目标同级；提示删除，绝不续用（20 §8）。
- **用户已开始用 v2**：回退不再是「删目标」——手册写清「使用后再回退需先备份 v2 数据」（P16-07），本单不提供自动回退。
- **回退**：v1 目录从未被修改，随时可继续使用 v1。
