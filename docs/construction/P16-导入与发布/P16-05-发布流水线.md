## 目标

发布流水线成立：`release-please` 合并发布 PR 后创建 `v*` tag 与 Release；tag 触发的构建工作流在 macOS aarch64 与 Linux x86_64 上从干净检出构建 release 二进制（内嵌前端产物），先跑版本断言（tag == `version.txt` == Cargo 版本），再产出 `gqy-<version>-<target>.tar.gz` 与 `SHA256SUMS` 并上传为 Release 资产；tag 与版本不符时失败且不上传；Windows 只做编译检查（00 §5）；工作流满足 zizmor（固定 SHA、`permissions: {}`、`persist-credentials: false`、不暴露 secrets）；`docs/release-versioning.md` 从「当前不包含制品」更新为含制品的口径并写清校验方法。

## 范围

- 做：
  - `scripts/build-release.sh`（本地与 CI 同一实现：构建 + 版本检查 + 打包 + 校验和；`--no-upload`）。
  - `.github/workflows/release-build.yml`：tag 触发、两平台矩阵、版本断言、打包、上传；`workflow_dispatch` dry-run（产出但不上传）。
  - 失败路径：tag / 版本不符、缺前端产物 → 失败。
  - `docs/release-versioning.md` 更新（制品、校验、失败路径）。
- 不做：
  - 安装器 / 签名 / 公证；自动更新；Windows 制品（只编译）；桌面打包（P16-06 后另议）。

## 接口草案

草案，以实现为准（脚本契约）。

```text
scripts/build-release.sh --version <x.y.z> --target <triple> --out <dir> [--no-upload]
  输出：<out>/gqy-<version>-<target>.tar.gz、<out>/SHA256SUMS
  失败：tag/版本不符、版本一致性检查红、缺前端产物 → 非零退出并说明期望与实际
```

## 实施步骤

1. `scripts/build-release.sh`（先写「版本不符 → 非零退出」用例；`bash -n` 过）。
2. 工作流骨架（固定 SHA、最小权限、缓存按 `Cargo.lock`；本地可跑的检查都调 `scripts/`）。
3. 版本断言与打包；矩阵两平台。
4. 上传与 dry-run 演练（`--no-upload`）。
5. `release-versioning.md` 更新；`workflow-security`（zizmor）与必需检查绿。
6. 提交：`ci(release): 发布流水线`。

## 测试与守护

- **版本断言**：本地伪造 tag 与 `version.txt` 不符 → 脚本非零退出（去掉断言，红）。
- **校验和**：`SHA256SUMS` 校验通过；篡改制品一字节 → 校验失败。
- **可复现路径**：`git clean` 后跑脚本成功；模拟缺前端产物时明确失败（15 §11）。
- **工作流静态检查**：zizmor 通过；actions 全固定 SHA（违规样例：改成浮动 tag → `workflow-security` 红）。
- 先红后绿对照（PR 贴输出）：去掉版本断言一次。

## 验收流程

```sh
bash -n scripts/build-release.sh
scripts/build-release.sh --version "$(cat version.txt)" --target aarch64-apple-darwin --out dist/ --no-upload
ls dist/ && shasum -a 256 -c dist/SHA256SUMS
tar -xzf dist/gqy-*.tar.gz -C /tmp/rel && /tmp/rel/gqy --version
# 流水线演练（需用户环境：GitHub 仓库 + RELEASE_PLEASE_TOKEN 已配置）：
#  1) workflow_dispatch 跑 release-build（dry-run，不建 Release）；
#  2) 合并一个 feat PR → 合并 chore: release PR → 观察 v* tag 与 Release 资产；
#  3) 下载资产复核 --version 与 SHA256SUMS。
```

## 风险与回退

- **`RELEASE_PLEASE_TOKEN` 未配置**：release-please 工作流会明确失败（现状）；本单依赖管理员配置完成，P16-07 手册列出。
- **双平台 runner 时长与成本**：缓存按 `Cargo.lock`；时长如实记录，不掩盖。
- **回退**：删除工作流即回到「无制品」状态；已产出的 Release 资产保留（tag 不可变）。
