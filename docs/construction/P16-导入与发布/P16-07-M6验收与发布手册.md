## 目标

M6 全量验收与两份手册落地：在干净环境演练发布链（合并一个 feat PR → 合并发布 PR → `v*` tag → 流水线 → 下载并按 `SHA256SUMS` 校验 → `--version` 对照），以及导入链（预演 → 核对 → 应用 → 回退；含「源自上次导入后有 N 个会话变化」提示与不导入清单解读）；产出 `docs/release-manual.md`（发布手册：操作清单、必需仓库设置、失败排查）与 `docs/import-v1-guide.md`（数据迁移手册：命令、期望输出、回退、「数据仍在 v1 目录，请勿删除」）；把 release-versioning.md 中过时的「当前不包含的发布能力」更新为现状；M6 记录（日期、版本、tag、制品哈希、导入夹具与真实数据结论、偏差）写进本单与施工图「每一步的图」；`CHANGELOG.md` 的 `[Unreleased]` 补齐用户可见条目。

## 实施步骤

1. 发布链演练（需用户环境：GitHub；无环境时用 `--no-upload` 与 dry-run 记录偏差）。
2. 导入链演练（夹具；真实 v1 数据需用户环境，演练前提醒自行备份 v1 侧）。
3. 两手册撰写（命令逐条跑通再写；照 20 §9 / §10 与 release-versioning.md 现况）。
4. release-versioning.md 与 `[Unreleased]` 更新；M6 记录留档；遗留与发现收口。
5. `cargo xtask check`；提交：`docs: M6 验收与发布手册`（代码修复按实际拆分提交）。

## 测试与守护

- **手册可照做**：手册里的每条命令在干净环境逐条执行并留输出（PR 附）；命令与期望输出同时写入手册。
- **M6 口径逐项**：Release Please 产出制品（下载 + 校验）；导入可预演 / 可核对 / 可回退（三态各自证据）。
- **偏差如实**：无法在 CI / 本机执行的项（真实 v1 数据、GitHub 演练）标注「需用户环境」并记录是否执行。
- **留档**：M6 记录含版本号、tag、制品哈希、导入报告路径或哈希、执行人（或代理）、日期。
- 先红后绿对照不适用（文档单）；以「手册命令在干净环境跑通」替代。

## 验收流程

```sh
cargo xtask check && cargo xtask test
# 发布链（需用户环境）：
#  合并 feat PR → 合并 chore: release PR → gh release view <tag> --json assets
#  下载 tar.gz 与 SHA256SUMS → shasum -a 256 -c → ./gqy --version 对照 tag
# 导入链（夹具）：
gqy import-v1 --from tests/fixtures/v1/v39 --to /tmp/m6-target --report /tmp/m6-report   # 预演
gqy import-v1 --from tests/fixtures/v1/v39 --to /tmp/m6-target --apply                   # 应用
sqlite3 /tmp/m6-target/gqy.db 'select imported_from from meta' && rm -rf /tmp/m6-target    # 回退
# 记录：把版本、tag、哈希、结论与偏差写入本单与施工图「每一步的图」
```
