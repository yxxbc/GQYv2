### 不做什么

- 不改页面自己的样子、交互、版式（那是网页那条线的开发）。
- 不做远程访问、证书（设计 21「后续再定」）。
- 不动 `apps/web-console/`（早期脚手架占位，另案）。
- 不做打包（W-11 暂停着）。

### 验收

1. `cd crates/gqy-web/tests/pages && node --test`：**410 条全过**。
2. `cargo xtask check` 八项全过；三平台 CI 全绿（新增的 `pages` 那一项只在 Linux）。
3. 真机（项目主人）：`gqy web` 打开页面 → 第一次设用户名密码 → 说一句话 → 附件（图片、PDF、文本）→ 链接卡片 → 长回答、Markdown、代码着色 → 侧边栏会话列表 → 断线重连。

### 风险

- **页面的登录流程没有先例**（终端界面、`gqy ask` 都用本机令牌，都没有「用户 + 密码」这一套界面）；照 W-8 的方法写，做出来先让项目主人看一遍。
- `/media` 和桥的 `/file`、`/blob` 参数不一样（一个带票据、一个带口令），拼错了图标、配图、附件缩略图会全裂；测试盯住。
- **本机没有浏览器**（Chrome、Chromium、playwright 的浏览器都没有）：协议层验得到（登录链、会话列表），页面渲染只能项目主人看。
